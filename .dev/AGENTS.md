## Граница материалов разработки и приложения

- По решению пользователя все файлы спецификаций, документации, планирования, тестов, тестовых данных, отчётов и инструментов разработки, не требующиеся самому приложению, размещаются в .dev. Инструкции и память проекта также находятся в .dev; новые материалы создавать там.
- Код приложения, его исполняемые схемы, миграции, ресурсы и конфигурация, необходимые для сборки, установки и работы, размещаются вне .dev. Документальные примеры контрактов в .dev не становятся источником файлов для работающего приложения.
- Разрешено только направление зависимости .dev → приложение: например, тесты обращаются к коду или API приложения. Файлы приложения не импортируют, не читают и не ссылаются на файлы из .dev; его сборка, установка и запуск не требуют наличия .dev.
- Критерий проверки при реализации: приложение собирается, устанавливается и запускается в окружении без .dev. Проверки и другие задачи разработки могут требовать .dev. Сейчас продуктового кода нет, поэтому этот критерий ещё не проверен.
- Указанные в предпроектном контексте ниже пути README.md, docs/, scripts/, data/ и local/ относятся к .dev, если явно не указан абсолютный путь. Материалы разработки сохранять в .dev внутри текущего корня, включая временные файлы.
