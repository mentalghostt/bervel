## Неизменяемые файлы и переход данных — 28 октября 2026

- Отличать идентичность файла от совпадения имени/байтов и повтора команды. Новая загрузка/правка создаёт самостоятельный файл; повтор прежнего ключа сохраняет прежний результат. Редактирование не разрешает удаление исходника.
- Миграция должна изменять только технические ссылки, которыми управляет приложение. Нельзя рекурсивно удалять любое поле revision: у datasets, обращений, схем и внешнего происхождения есть собственный смысл версий. Исторический текст и байты документов сохраняются.
- Сохранность подтверждать восстановлением фактической копии, сравнивая исходные векторы, числовые результаты и связи. Проверка на изолированной БД отдельно от установки в основной runtime; несовместимый со схемой worker требует согласованного обновления с API.
- Перед безвозвратным удалением закреплять точные разрешённые ID, сохранять активные файлы и общие объекты. Уничтожение рабочего экземпляра не означает уничтожение всех независимых резервных копий.

## Чаты, удаление и конкурентные ответы — 28 октября 2026

- Отличать определённый HTTP-отказ от неизвестного исхода. Неизвестное удаление сохраняет ключ;409 не должен оставлять ввод навечно заблокированным,404 чтения после reload должен позволять безопасно начать другой диалог без автоматического повтора.
- Пагинация и изменение состава списка должны быть согласованы. Поздний ответ offset-страницы после удаления может пропустить последний объект; сериализация операций устраняет эту гонку. Свежий список обновляет метаданные, но не перекрывает более новый локальный read/send.
- Обновлять только необходимые службы. Неизменный worker с прежними контрактами можно оставить работать; сохранность при его активной обработке проверять по всем исходным полям и векторам, отдельно фиксируя разрешённый прогресс задания.

## Контекст и интерфейс — 28 октября 2026

- Сначала выбирать операцию, затем получать требуемое содержимое. Фоновый RAG перед каждым запросом перегружал список CSV, подмешивал посторонние документы в тикет и мешал универсальному помощнику. После перехода28.10 показывать ссылки по уникальному ID неизменяемого файла, сохраняя полные фрагменты как доказательства.
- Авторизация должна знать семантику операции: внутренний черновик обращения не отправляет сообщение и не требует существующего адресата. Не заполнять неизвестные шаги выдуманной диагностикой; проверять точную фразу пользователя реальной моделью и отдельно отрицательные сценарии.

## Ассистент и полный радар — 27 октября 2026

- Общая карточка результата не сообщает модели, какая операция уже выполнена. Передавать в следующий контекст серверное подтверждение operation/arguments/state и результат, сохраняя защиту повторных эффектов. Проверять настоящую цепочку read→edit→read: чистая логика и mock могут пройти, пока реальная модель повторяет edit из-за неполной обратной связи.
- Полный результат инструмента и контекст следующего запроса модели имеют разные ограничения. Хранить весь отчёт, а для модели строить ограниченную проекцию с явным покрытием и чтением страниц. Проверять байты после JSON escaping вместе со схемой, включая длинный Unicode и кавычки.
- Браузерный mock должен отвергать лишние поля так же, как настоящий API. Для редактирования обращения отдельно преобразовывать серверный объект в форму и форму в команду; проверять захваченный HTTP body настоящей схемой.
- Поздний ответ изменения файла должен обновлять только тот файл, к которому относится. При переключении выбора сверять ID; после возобновления индексации обновлять состояние строки и включать polling, сохраняя объект открытого просмотра.
- Положительная экономика не отменяет обязательные технические и договорные риски. Моковые цены и мощности не доказывают фактическую прибыль; пропущенные сведения нельзя восстанавливать по похожей исторической заявке.
- Без ключа провайдера можно проверить протокол, интерфейс и корректный отказ, но нельзя подтвердить реальное распознавание или поиск. В отчёте разделять эти доказательства. Число одновременно проверяемых модельных потоков ограничивается реальной ёмкостью runner, включая отдельные тестовые схемы.

Записывать только проверенные устойчивые выводы.

## 2026-10-16 — Docker и восстановление

- Для shell-скриптов первой инициализации PostgreSQL закреплять `eol=lf` в `.gitattributes`: локальный успешный запуск не доказывает работоспособность свежего Windows checkout с CRLF.

## 16 октября 2026 — версии n8n и согласованное чтение процессов

В n8n 2.43.5 native retry с `loadWorkflow=false` сохраняет исходный executable snapshot, но отдаёт `workflowVersionId=null`. Происхождение версии можно восстанавливать по `retryOf` только после точного сравнения сохранённых nodes/connections/settings и привязки входов; текущая опубликованная версия для этого непригодна. Подтверждение — живой N02 и тесты адаптера этапа 3.2.

При PostgreSQL READ COMMITTED два SELECT внутри одной транзакции могут читать разные снимки. Состояние процесса, результат и история попыток должны формироваться одним SQL statement; иначе API может показать RUNNING вместе с попыткой COMPLETED. Гонка воспроизведена барьером между чтениями, исправлена ordered JSONB aggregation. Источники и доказательства — `docs/quality/core-stage-3.2-report.md`.
