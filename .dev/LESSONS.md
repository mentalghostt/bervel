## Локальные показатели радара — 9 ноября 2026

- Кэшировать числовую стадию по всем реально используемым фактам: production products включают EXP и unit/attributes, а не только физический stock SKU. Без этого изменённая маржа может вычислиться, но не сохраниться из-за прежнего fingerprint.
- Выключить календарь в cost-only недостаточно: надо сохранить неоднозначность маршрутов и распределения общего склада. Иначе непроверенная полная себестоимость ошибочно становится подтверждённой. Неизвестное покрытие остаётся null и на изменившихся остатках.
- Чистые unit-гейты и общий controller review не заменяют read-only прогон на сохранённом корпусе: он выявил14дельт. Unchanged reuse допустим отдельно от исправления changed-input engine; скрывать ошибки только cache fastpath нельзя.
- Range не должен наследовать оформление текстового input. Исключение через :where сохраняет специфичность других контролов; проверять реальный порядок загруженного CSS, обе ручки и концы линии.
- Pure benchmark 1,4с и рабочая команда 55с с очередью, БД и опросом — разные измерения. Нулевые расходы подтверждаются boundary-тестами и сохранностью полных hashes priorities/ratings/history/reports и counters на live. One-shot smoke не повторять новым ключом после неизвестного ответа.

## Большой профиль и дублированные вкладки — 5 ноября 2026

Снятие одного размера DTO не устраняет цепочку ограничений: CSV-reader, число строк, HTTP middleware и sessionStorage могут последовательно остановить тот же файл. Проверять полный путь большим реальным payload и последней строкой; не подменять увеличение лимита другим произвольным пределом. IndexedDB подходит для большой идемпотентной команды, а Web Storage — для короткой ссылки. Транзакция должна завершиться до HTTP-запроса. Дублированная вкладка копирует sessionStorage, но разделяет IndexedDB: нельзя удалять общую команду при успехе в первой вкладке. Сохранять маленькую квитанцию, чтобы оставшиеся ссылки разрешались без блокировки и без хранения лишнего полного профиля.

## Снимки, область факта и безопасная установка — 5 ноября 2026

Сохранять raw карточки до первого модельного вызова; производные факты фиксировать отдельно. Аудит обязан повторять извлечение из raw, иначе он воспроизводит исходную ошибку. Общая характеристика «для каждой позиции» должна быть подтверждена у каждой затронутой строки. Название «поставка» рядом с датой не доказывает срок передачи товара: дата заявки/срок действия договора — другие факты. Нулевую мощность отличать от неизвестной, а неудачное жадное распределение склада/маршрута — от доказанной невозможности.

Числа базового и стрессового сценария проверять в своей области: валидная стресс-прибыль35 не равна подмене базовой50. Реальный модельный smoke выявил это после unit-tests. Симуляторный oracle использовать только после фиксации очереди и не выдавать протокольную заглушку за LLM. Перед Docker Compose update сверять разрешённые env/cmd/mounts/ports в памяти и экранировать `$`; проверка только после замены запоздала. Не печатать private compose/inspect. Проверки hash должны различать отсутствующие опциональные поля без падения на undefined; временные e2e-контейнеры не считать постоянными службами.

## Vite в Docker с Windows bind mount — 2 ноября 2026

Изменение исходника на Windows может не инвалидировать кэш Vite в QA-контейнере: чтение файла в контейнере показывает новый код, а HTTP `/src/*.tsx` отдаёт старую трансформацию. Перед проверкой новой правки перезапустить только свой QA-контейнер и при сомнении сравнить HTTP-код с исходником. Production build читает свежие файлы; установка зависимостей и правка продукта этот сбой наблюдения не устраняют. Для параллельных задач в dirty workspace сверять базовую frontend-сборку с установленной и исключать чужие незавершённые изменения через ограниченные исходные файлы в контексте сборки; рабочие файлы другой задачи не откатывать.

## Ограничение доступа и полнота материалов — 30 октября 2026

Маска в JSON реквизитов не доказывает неполноту состава закупки. Признаки для товарного подбора вычислять только из объектов материалов и их характеристик/количеств/единиц. Пустой Value со стандартной инструкцией о выборе участника отличается от скрытого значения; сохранять основание допуска в тексте для модели, включая смешанные массивы значений. Проверять это на реальном сохранённом ответе API и отрицательными тестами, не ослабляя защиту неизвестных требований. Сбой эмбеддингов и результат товарного сопоставления фиксировать раздельно.

Маскированный источник сохраняет свои ограничения даже с полностью покрывающим МОК-складом.

## Неизменяемые файлы и переход данных — 28 октября 2026

- Отличать идентичность файла от совпадения имени/байтов и повтора команды. Новая загрузка/правка создаёт самостоятельный файл; повтор прежнего ключа сохраняет прежний результат. Редактирование не разрешает удаление исходника.
- Миграция должна изменять только технические ссылки, которыми управляет приложение. Нельзя рекурсивно удалять любое поле revision: у datasets, обращений, схем и внешнего происхождения есть собственный смысл версий. Исторический текст и байты документов сохраняются.
- Сохранность подтверждать восстановлением фактической копии, сравнивая исходные векторы, числовые результаты и связи. Проверка на изолированной БД отдельно от установки в основной runtime; несовместимый со схемой worker требует согласованного обновления с API.
- Перед безвозвратным удалением закреплять точные разрешённые ID, сохранять активные файлы и общие объекты. Уничтожение рабочего экземпляра не означает уничтожение всех независимых резервных копий.

## Чаты, удаление и конкурентные ответы — 28 октября 2026

- Отличать определённый HTTP-отказ от неизвестного исхода. Неизвестное удаление сохраняет ключ;409 не должен оставлять ввод навечно заблокированным,404 чтения после reload должен позволять безопасно начать другой диалог без автоматического повтора.
- Пагинация и изменение состава списка должны быть согласованы. Поздний ответ offset-страницы после удаления может пропустить последний объект; сериализация операций устраняет эту гонку. Свежий список обновляет метаданные, но не перекрывает более новый локальный read/send.
- Обновлять только необходимые службы. Неизменный worker с прежними контрактами можно оставить работать; сохранность при его активной обработке проверять по всем исходным полям и векторам, отдельно фиксируя разрешённый прогресс задания.

## Контекст и интерфейс — 28 октября 2026

- Сначала выбирать операцию, затем получать требуемое содержимое. Фоновый RAG перед каждым запросом перегружал список CSV, подмешивал посторонние документы в тикет и мешал универсальному помощнику. После перехода28.10 показывать ссылки по уникальному ID неизменяемого файла, сохраняя полные фрагменты как доказательства.
- Авторизация должна знать семантику операции: внутренний черновик обращения не отправляет сообщение и не требует существующего адресата. Не заполнять неизвестные шаги выдуманной диагностикой; проверять точную фразу пользователя реальной моделью и отдельно отрицательные сценарии.
- Состояние списка не должно зависеть от порядка просмотра: обновление выбранного запуска по ID и сортировка по created_at, а не prepend после любого GET.
- Область идентичности зависит от операции: после перехода28.10 готовность, назначение и удаление адресуют artifact_id; удаление отменяет только запросы этого файла. Поздний ответ удалённого источника не должен возвращать его в просмотр; ручной выбор и другой pending source сохраняются.
- Проверочные запуски с искусственными фильтрами нужно отличать от обычного результата. Нулевой результат с ценой от1трлн не подтверждает неисправность алгоритма, но такая история без видимых параметров может запутать пользователя.

## Ассистент и полный радар — 27 октября 2026

- Общая карточка результата не сообщает модели, какая операция уже выполнена. Передавать в следующий контекст серверное подтверждение operation/arguments/state и результат, сохраняя защиту повторных эффектов. Проверять настоящую цепочку read→edit→read: чистая логика и mock могут пройти, пока реальная модель повторяет edit из-за неполной обратной связи.
- Полный результат инструмента и контекст следующего запроса модели имеют разные ограничения. Хранить весь отчёт, а для модели строить ограниченную проекцию с явным покрытием и чтением страниц. Проверять байты после JSON escaping вместе со схемой, включая длинный Unicode и кавычки.
- Браузерный mock должен отвергать лишние поля так же, как настоящий API. Для редактирования обращения отдельно преобразовывать серверный объект в форму и форму в команду; проверять захваченный HTTP body настоящей схемой.
- Поздний ответ изменения файла должен обновлять только тот файл, к которому относится. При переключении выбора сверять ID; после возобновления индексации обновлять состояние строки и включать polling, сохраняя объект открытого просмотра.
- Положительная экономика не отменяет обязательные технические и договорные риски. Моковые цены и мощности не доказывают фактическую прибыль; пропущенные сведения нельзя восстанавливать по похожей исторической заявке.
- Без ключа провайдера можно проверить протокол, интерфейс и корректный отказ, но нельзя подтвердить реальное распознавание или поиск. В отчёте разделять эти доказательства. Число одновременно проверяемых модельных потоков ограничивается реальной ёмкостью runner, включая отдельные тестовые схемы.

Записывать только проверенные устойчивые выводы.

## 2026-10-16 — Docker и восстановление

- Для shell-скриптов первой инициализации PostgreSQL закреплять `eol=lf` в `.gitattributes`: локальный успешный запуск не доказывает работоспособность свежего Windows checkout с CRLF.
- БД n8n переносится вместе с прежним ключом шифрования. До первой записи при восстановлении проверять ключ, все дампы, пустоту всех целей и контрольные суммы оригиналов. Отдельная проверка восстановления приложения должна читать данные через установленный API в изолированной БД и volume.
- На Windows завершение родительского `docker.exe` само по себе не завершает дочерний `docker-compose.exe`. Проверочный Watch-процесс завершать вместе с принадлежащим ему деревом процессов; не оставлять скрытое наблюдение после теста.
- Linux-браузер с API, использующим `crypto.randomUUID`, требует secure context. Проверенный стенд использует localhost в сетевом пространстве тестового frontend и не отключает browser security.
- Readiness PostgreSQL для зависимых контейнеров проверять по TCP: временный сервер первой инициализации может отвечать через Unix socket раньше готовности основного сервера к сетевым подключениям.
