## Границы

КП описывает два модуля. Более поздний опросник обозначен как «Ядро + Тендерный радар»; его пункт 1.1 выбирает функции радара, но не подтверждает включение пресейла. Архитектура обоих модулей сохраняется; их поставка разделена.

Первоначальная таблица заказчика содержит также обработку заявок, инвестиционные и маркетинговые пожелания. Она не подменяет выбор этапа. Источник списка закупок теперь конкретизирован образцом «Контур Закупок»; автоматическое получение документации и внутренние источники завода требуют проверки. [Покрытие R01–R22 полученными файлами](docs/discovery/customer-package-request-coverage.csv) показывает, что ещё уточнять.

Чертежи, дооснащение, окупаемость, пакет участия и запись во внешние системы уточняются по выбранному объёму. Автоматическая подача тендерной заявки, электронная подпись, управление оборудованием и резервирование товара не включаются по умолчанию.

## Проверка материалов

`python .dev/scripts/check_project_materials.py`

Проверяет ссылки в проектных Markdown, целостность исходных снимков, структуру реестров и связь декомпозиции с запросами. Это проверка документации, не тест работающего приложения. Python 3.9+; сторонние зависимости не нужны.

Из рабочего корня `.dev/scripts/core_stage_3_1_local.ps1 -Action verify` выполняет живой учебный сценарий и проверку сохранности после перезапуска; `-Action serve` запускает API. Проверки кода: `.dev/local/core-stage-3.1/venv/Scripts/python.exe -m pytest -c .dev/pytest.ini --rootdir=. -q` с отдельной тестовой PostgreSQL-БД. Полная настройка — в инструкции выше; промышленный деплой пока не определён.
