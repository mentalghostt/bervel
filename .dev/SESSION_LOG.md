## Решения и причины

Пользователь выбрал отдельный графический клиент PostgreSQL; таблица просмотра строк внутри новой страницы не добавлялась. Обработка начинается по кнопке «Загрузить в БД», а не автоматически после выбора. Использованы существующие API и Vite proxy. Ключ не встроен в сборку и не сохраняется в browser storage. Повтор текущей попытки сохраняет ключи команд и подтверждённые ссылки, чтобы пережить потерю ответа без дублирования; перезагрузка страницы, смена ключа или файла начинают новую попытку.

Фиксация времени загрузки не определяет свежесть содержимого. observed_at предусмотрен контрактом, но учебный обработчик оставляет null. Каждая новая загрузка через текущий UI создаёт отдельный материал и набор; current_revision — версия внутри одного объекта, а не глобальный признак актуальности. Для частых выборок по источнику и датам рекомендованы обычные колонки; это рекомендация к будущему согласованию, а не внесённое изменение схемы.

Full выполняется в существующей папке без переноса, worktree, коммитов и push. Штатный helper MOX сохраняет память, атрибуцию, защиту от дублей и GitHub work-log; локальный одноразовый запуск меняет только пути журналов и проверки контекста на .dev, поскольку личное правило размещения имеет приоритет над корневыми путями helper. Внешний установленный скилл не редактируется. Анализ worktree допускается только без --apply и с --no-fetch.

## Проблемы и уроки

PowerShell пользователя запретил запуск ps1 политикой выполнения. Подтверждённый рабочий способ — Bypass для отдельного процесса; системная политика не менялась. Ключ и API должны запускаться в одном окружении, поскольку helper может генерировать новые процессные ключи. В браузере Windows CSV может определяться как файл Excel; multipart Blob отправляется с text/csv при сохранении серверной проверки содержимого.

Пустой результат SQL без ошибки оказался неверным идентификатором, а не потерей данных: record_id строки ошибочно использовали в фильтре dataset_id. Сначала проверять идентификатор и ревизию read-only запросом, затем объяснять различие ID файла, результата и строки.

Для проверки идемпотентности нужно оборвать ответ после реальной публикации результата и повторить команду, затем проверить ID и число наборов/строк в PostgreSQL. Один mock успешного ответа этого не доказывает. В проверенном Windows/Edge окружении параллельные наборы нестабильно открывали системный filechooser; последовательный запуск браузерных наборов устранил взаимное влияние без изменения продукта. Дата повторной загрузки не делает старый остаток свежим; для актуальности требуется смысловая дата источника и явная принадлежность к заменяемому набору.

## Незавершённое

Код ядра, frontend и материалы разработки остаются локально незакоммиченными; доставка в GitHub git-репозиторий и промышленный деплой не выполнены. Full/work-log не означают commit, push, merge или приёмку всей клиентской поставки. Существующие изменения в рабочем дереве не откатывались и не включались в индекс.

Не реализованы выбор предметного источника в UI, связывание загрузок как следующих редакций, заполнение observed_at, публикация действующего предметного состояния, политика устаревания и автоматический выбор актуальных данных. Восстановление браузерной попытки после reload не обещано. Текущий CSV — учебный ограниченный формат, не универсальный импорт любых таблиц. Следующие этапы ядра 3.2/3.3 не начинались; решение о промышленной авторизации, эксплуатации и отдельной площадке также остаётся вне выполненной работы.

## Следующие шаги и блокеры

До следующего кода согласовать небольшой этап: какие данные заменяют друг друга (например, источник плюс склад или поставщик), откуда брать дату применимости и когда новая загрузка становится действующей. Пользователь работает в обычном поэтапном режиме; обсуждение актуальности не является разрешением на реализацию. После решения выбрать минимальные необходимые изменения контракта/БД/UI с понятной ручной проверкой и только затем реализовать согласованный этап.

Для текущей ручной проверки использовать .dev/docs/operations/frontend-csv-upload.md; DBeaver подключать к рабочей, а не тестовой БД, фильтр строк строить по «ID результата». Уже включённый PostgreSQL разрешено использовать после проверки доступности; включать и переключать модули Open Server может только пользователь. VPN не менять. Git в основной ветке выполняет человек; при завершении передать ему локальные изменения для отдельного review и фиксации.
