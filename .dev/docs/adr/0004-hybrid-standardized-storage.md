# Гибридное хранение

Принят принцип совместного хранения исходных байтов, общих метаданных/происхождения и структурированных результатов. Предметные таблицы принадлежат своим модулям и обеспечивают реальные бизнес-ограничения; JSONB хранит связанные версионные payload. Это сохраняет проверяемость, не превращая данные в универсальную модель «поле — значение».

Поздние решения заменили конкретный учебный механизм регистрации схем/datasets. Он не является текущим контрактом. Файловые редакции заменены [ADR-0006](0006-independent-files.md): новая загрузка/правка создаёт отдельный неизменяемый файл. Редакции пресейла/снимки предприятия сохраняют свой предметный смысл.

Исходные байты не переписываются, производитель данных отвечает за их смысл. Извлечённый документ не становится автоматически достоверным складом/каталогом. Новая бизнес-модель оформляется миграцией владельца; исторические миграции сохраняются.

[Текущие границы ядра](../architecture/12-core-v0.1-spec.md), [владение данными](../architecture/05-data-model.md). Это архитектурное решение разработчика, а не политика доступа/хранения заказчика.
