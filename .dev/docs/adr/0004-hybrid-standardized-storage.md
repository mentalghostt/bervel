# Гибридное стандартизированное хранилище ядра

Владелец разработки 14 октября 2026 выбрал гибридную структуру: общие метаданные, происхождение и редакции для всех материалов; результаты по зарегистрированным версионным схемам; предметные таблицы для каталога, остатков и данных с бизнес-ограничениями. Новый формат результата добавляется схемой; изменение бизнес-модели — миграцией её владельца. Так сохраняется расширяемость без универсальной модели «поле — значение» и без потери строгих предметных правил.

Рассмотренная альтернатива — только предметные таблицы — требует проектирования и миграции даже для нового формата промежуточного извлечения. В выбранном варианте исходные байты остаются неизменяемыми, а ядро обеспечивает общее хранение и доступ. Производитель данных владеет смыслом схемы; извлечённый файл не становится автоматически действующим справочником или складским остатком.

Принят принцип хранения для разработки. [Спецификация v0.1](../architecture/12-core-v0.1-spec.md) и её конкретные контракты приняты владельцем разработки 14 октября 2026 в рамках этапа 1, включая независимость от Open Server Panel. Это решение не выбирает конкретную БД, провайдера хранения, сроки хранения или клиентскую политику доступа.
