# ADR-0005: фоновые процессы на Python/PostgreSQL

Принято владельцем 22.10.2026. Текущее приложение использует PostgreSQL-очереди и Python workers вместо n8n/Redis. Выбор сохраняет фоновую обработку, не требует отдельного оркестратора и не вводит новую универсальную workflow-систему.

API принимает команду/оригинал, предметный worker исполняет сценарий и сохраняет результат/контрольные точки с проверкой владения. Повтор использует ключ команды и уже подтверждённые этапы; неизвестный внешний исход не исполняется вслепую.

Учебный CSV-сценарий впоследствии выведен, но принцип отдельных Python-ролей действует для knowledge/chat/inspection/ai_tender_radar/presales. Старые n8n-адаптеры/callbacks/секреты и команды восстановления не являются текущим API.

Исторические БД, volumes, резервные копии и миграции сохраняют данные и не удаляются вместе с исполняемым движком. Это решение разработки не утверждает промышленный SLA или клиентскую политику восстановления.
