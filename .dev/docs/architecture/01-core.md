# Общее ядро

Ядро предоставляет общие операции над файлами, права/область, чтение документов, знания, модельный транспорт и соединения. Оно не определяет возможности завода, категории пресейла или тендерный отбор.

HTTP проверяет вход → прикладная операция проверяет правила → переданные адаптеры выполняют SQL/файловые/сетевые действия. `ArtifactService` регистрирует самостоятельный оригинал, перечисляет файлы, читает метаданные/байты и управляет удалением. Чужая область не раскрывает существование файла.

`KnowledgeService`, `DocumentMemory` и `DocumentReader` готовят оригиналы к поиску/чтению. Индекс хранит происхождение и пространство embeddings; несовместимость/неполнота показываются явно. Индекс не заменяет оригинал и не доказывает бизнес-соответствие.

PostgreSQL хранит структурные данные, очереди, квитанции и поиск; байты файлов находятся отдельно. Неизвестный внешний исход не объявляется успехом. Очереди принадлежат своим сценариям; универсального ProcessService нет.

Модули подключаются явно в `app_setup.py`, `ai_tender_radar_setup.py` и `presales_setup.py`. Статического `/modules`, манифестного discovery и учебного реестра datasets нет. Дополнительный слой нужен только для реальной задачи.
