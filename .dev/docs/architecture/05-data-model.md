# Данные и владение

| Данные | Владелец |
|---|---|
| Метаданные/байты оригиналов, доступ и квитанции | `core` |
| Извлечённые документы и embeddings | Общая база знаний |
| Сессии/сообщения/действия | `chat`; inspection использует отдельный режим/native thread |
| Каталог, склад, мощности, ресурсы и снимки | `company_settings` |
| Профили/анализы/вопросы/очереди радара | `ai_tender_radar` |
| Настройки/обращения/редакции/строки/очередь пресейла | `presales` |
| Внутренние обращения | `tickets` |

PostgreSQL хранит структурные поля, JSONB предметных снимков, очереди и pgvector. Байты файлов находятся отдельно. JSONB не заменяет типизированную проверку. Модуль не читает внутренние таблицы соседа.

Файл — самостоятельный неизменяемый ID. `artifact_revisions` и `current_revision` отсутствуют. Правка сохраняется новым ID; редакции пресейла и версии алгоритма имеют другой смысл. Историческая ссылка указывает точный оригинал либо сообщает об удалении.

Сырые ответы источника/frozen-входы не переписываются задним числом. Анализ хранит версии этапов, время и происхождение. Неизвестное/устаревшее/противоречивое различаются; денежные расчёты проверяются отдельно от текста модели.

Миграции — `core/migrations/versions`. История 0001 и далее нужна новым/существующим установкам, включая изменения выведенных функций. Установленная схема — `0029_presales_pipeline`; отложенная inspection-ветвь 0028 не применялась. Нельзя запускать все heads из dirty-исходников по одному номеру файла.
