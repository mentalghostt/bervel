# Контракты компонентов

Статус: эскиз контрактов. Не опубликованный API и не готовая OpenAPI-схема. Версии и обязательность полей уточняются при реализации.

При подготовке реализации ядра использовать [спецификацию v0.1 от 14 октября 2026](12-core-v0.1-spec.md): контракт модуля, точные ссылки на редакции, общий конверт результатов и правила совместимости. Она принята владельцем разработки в рамках этапа 1 с дополнением о независимости от Open Server Panel; таблицы ниже сохраняют предметные границы исходного эскиза.

## Публичные границы

| Интерфейс | Вход | Выход | Основное ограничение |
|---|---|---|---|
| DocumentService.ingest | файл/ссылка, источник, scope, ключ запроса | документ и редакция | Авторизация и проверка файла до обработки |
| ExtractionService.extract | редакция, схема требований, версия извлечения | поля + evidence + issues | Отсутствующее остаётся неизвестным |
| MatchingService.assess | требования, снимок справочников | проверки + кандидаты | Сходство не равнозначно допуску |
| EconomicsService.calculate | проверенные входы, методика | результат + ограничения | Нет неутверждённых коэффициентов |
| ReviewService.request | результат, редакция, действие | задача проверки | Только известная неизменяемая редакция |
| ReviewService.decide | review_id, expected_revision, решение | одобрение/отказ | Проверка роли и конфликтов редактирования |
| ExternalActionService.request | действие, одобрение, payload_hash, ключ | intent_id | Точный payload соответствует одобрению |
| KnowledgeService.retrieve | запрос, scope, версия индекса | разрешённые доказательства | Фильтрация доступа до передачи модели |

## Конверт результата

По полученному пакету предлагается дополнить входные контракты происхождением записи (файл/лист/строка, роль источника), типизированными ссылками и manifest комплекта. Извлечение возвращает также общие примечания и область их действия, исходную единицу и состав комплекта. Результат сопоставления раздельно возвращает техническую проверку, производимость, наличие/срок и подтверждение альтернативы. Итоги строятся из проверенных строк. Детали схем остаются предложением; см. [карту источников](11-data-sources-and-intake.md).

schema_version; result_id; subject_id; subject_revision; input_snapshot_id; process_version; rule_set_version; extraction_version; model_invocation_ids; status; findings; issues; evidence; generated_at; valid_until при наличии.

Не все поля обязаны быть публичны сотруднику; технические метаданные доступны по роли. Большие файлы передаются ссылками с контролем доступа, не через историю каждой задачи.

## Конверт события

event_id; event_type; event_version; aggregate_id; aggregate_revision; occurred_at; correlation_id; causation_id; producer; data_scope; payload.

Возможные события: DocumentAccepted, ExtractionCompleted, AssessmentReady, ReviewRequested, RevisionApproved, ApprovalInvalidated, ExternalActionRequested, ExternalActionConfirmed, ExternalActionUnknown. Событие описывает факт, команда запрашивает действие; их нельзя смешивать.

## Совместимость и доставка

- Потребитель обрабатывает повтор по event_id/ключу операции.
- Порядок разных потоков не предполагается; aggregate_revision защищает от устаревшего события.
- Неизвестная версия помещается в очередь разбора, не трактуется как текущая.
- Изменение смысла поля требует новой версии; добавление необязательного поля допустимо по правилам совместимости.
- Outbox фиксируется вместе с бизнес-изменением. Для межсистемных шагов используется явное состояние частичного успеха.
- Контрактные тесты проверяют согласованность producer/consumer, включая неизвестное и ошибки.

## Ошибки

VALIDATION_ERROR - неверный вход; не повторять автоматически без изменения.
MISSING_DATA / NEEDS_REVIEW - бизнес-состояние, не технический сбой.
TRANSIENT_DEPENDENCY_ERROR - ограниченный повтор с задержкой.
STALE_REVISION - пересчитать/переоткрыть, не перезаписывать.
FORBIDDEN - действие запрещено.
EXTERNAL_RESULT_UNKNOWN - сверка результата, не слепой повтор.
QUOTA_EXCEEDED - очередь/оператор по согласованной политике.

LLM-текст и загруженные документы являются данными. Они не могут расширять права инструмента, менять конфигурацию или одобрять собственный вывод.
