# Отказоустойчивость и безопасность

Статус: предлагаемые требования к реализации. Численные RPO/RTO/SLO пока не согласованы (R09, R16).

## Отказовые сценарии

| Сбой | Поведение | Доказательство проверки |
|---|---|---|
| Обработчик остановлен во время OCR | Сохранён оригинал, доступен повтор/продолжение | Принудительное завершение процесса на тестовом документе |
| Модель недоступна/429 | Ограниченная очередь/повторы, видимое ожидание | Заглушка отказа, проверка лимита повторов и уведомления |
| Невалидный или ложный ответ модели | Схемная и предметная проверка, ручной разбор | Примеры корректного JSON с неверными значениями |
| 1С недоступна | Возраст снимка виден, запрещённые на старых данных действия блокируются | Проверка согласованной политики актуальности |
| Поисковый индекс недоступен | Работа с доступными данными; неполнота явна | Нельзя тихо заменить отсутствие поиска на «не производим» |
| Ошибка БД | Не выполнять новое согласование/внешний эффект | Внешнее действие отсутствует без сохранённого намерения |
| Ответ отправки потерян | UNKNOWN, сверка/ручная проверка | Прервать связь после приёма запроса внешней системой |
| Повтор команды | Один бизнес-эффект при поддерживаемой идемпотентности | Два одинаковых запроса и восстановление после crash |
| Новая документация после одобрения | Проверка влияния и инвалидирование | Старое одобрение не разрешает новый результат |
| Накопление очереди | Лимиты, приоритет дедлайнов, тревога | Нагрузочный тест типичного и пикового потока |

Ни один оркестратор не отменяет необходимость idempotency и сверки внешнего результата. Резервная копия не отменяет уже отправленное письмо.

## Изоляция и доступ

Отдельные пулы тяжёлых задач, лимиты CPU/памяти/страниц, ограничение сети и временных файлов. Основной API не исполняет макросы/скрипты из документов. Права сотрудников и сервисных учётных записей минимальны; на старте интеграция с учётной системой по чтению, пока запись не согласована.

Фильтры доступа действуют в БД, объектном хранилище и поиске. Текст закупки не может инструктировать агента отправить данные стороннему адресу или поменять цены. Это проверяется тестами вредоносных инструкций в документах.

Секреты не хранятся в репозитории и не записываются в логи. Наличие PDF с клиентскими данными в private repo тоже требует решения владельца данных; по умолчанию здесь только уже подготовленные источники/артефакты без новых производственных выгрузок.

## Актуальность и аудит

Сохранять источник, редакцию, методику, промпт/модель и использованный ответ в рамках разрешённой политики хранения. Воспроизведение обоснования означает восстановить сохранённые факты и решения; не обещать битовую повторяемость генерации LLM.

## Восстановление

Согласовать потерю данных/длительность простоя. Проектировать копирование БД, оригиналов, истории оркестратора, правил и конфигурации как целое. Отдельная площадка копий и проверка восстановления; период и срок хранения определяются R06/R09.

Одна VM с Docker остаётся единой точкой отказа. Высокая доступность потребует схемы нескольких узлов/управляемых сервисов, выбранной под бюджет и эксплуатационные компетенции. Репликация не заменяет резервную копию.

## Выпуск

Изменение модели, правил, схемы и процесса версионируется. Незавершённые задания совместимы со старой версией либо мигрируются проверенным способом. Откат схемы нельзя считать безопасным автоматически; при несовместимом изменении нужен план восстановления/forward-fix.
