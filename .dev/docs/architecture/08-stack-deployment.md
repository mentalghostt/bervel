## Оркестрация

n8n подходит для обозримых интеграционных цепочек. В режиме очередей нужны соответствующие компоненты и эксплуатация; multi-main и связанные условия лицензии проверяются по выбранной редакции. Критические правила должны находиться в коде/версионированных данных, а не быть рассыпаны по неподконтрольным узлам.

Temporal интересен при долговременных процессах, ожидании сотрудников, восстановлении и версиях исполнения. Требует поддержки собственной инфраструктуры/сервиса и дисциплины детерминированного workflow-кода. Сетевые операции и LLM-вызовы выполняются как Activities; их эффекты могут потребовать повтора и дедупликации.

По результатам перезапуска обработчика, многократной доставки, ожидания человека, смены версии и ручного восстановления владелец разработки принял n8n для ядра v0.1 ([ADR-0002](../adr/0002-durable-orchestration.md)). Испытан выпуск 2.43.5; он не фиксирует автоматически версию промышленной поставки. Автоматическое продолжение после аварии worker не подтверждено; защита команд и эффектов относится к ядру и ещё не реализована. Temporal не испытывался и не входит в выбранный профиль.

## Размещение

Опросник ссылается на облачную площадку, которую настраивает подрядчик. Не выбирать on-prem без изменения согласованных рамок. Выяснить провайдера, условия безопасности, регулярный бюджет, RPO/RTO и эксплуатацию. Пилот и промышленный контур могут иметь разную степень резервирования.

Уточнение владельца разработки от 14 октября 2026: Open Server Panel можно использовать локально, но установка системы заказчиком должна обходиться без него. Требование переносимости закреплено в [спецификации ядра v0.1](12-core-v0.1-spec.md). Оно не выбирает промышленную площадку вместо облачной рамки опросника.

Панель может предоставлять PostgreSQL и один веб-сервер; состав установленной у пользователя версии проверяется перед настройкой. Python API, фоновые обработчики, выбранный движок процессов и хранение объектов остаются самостоятельными ролями. Для Python-профиля PHP не требуется. Apache/Nginx/Caddy могут обслуживать внешний HTTP-вход при соответствующей конфигурации; выбранный proxy не становится зависимостью бизнес-кода.

Поставка описывает стандартные зависимости и запуск без Open Server; адреса сервисов и пути задаются конфигурацией окружения. Пригодность хостинга подтверждается возможностью запускать выбранный runtime и длительные обработчики, подключать БД и необходимые сервисы. Обычный тариф только с PHP не объявляется подходящим без этой проверки.

## Модели

Проверка: извлечение чисел и единиц, сложные таблицы, корректная неопределённость, стоимость, задержка, квоты, политика данных, возможность смены модели. Пользовательская подписка и API не считаются взаимозаменяемыми. Сетевая достижимость не подтверждает разрешённый промышленный способ доступа. Пользовательский VPN не изменяется.
