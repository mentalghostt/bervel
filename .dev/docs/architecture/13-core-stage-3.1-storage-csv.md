# Этап 3.1: хранилище и учебная обработка CSV

Дата: 14 октября 2026. Статус: технический профиль принят владельцем разработки в текущем диалоге. Основание — явный ответ «Принять предложенный профиль 3.1». Владелец разрешил этап 3.1 и выбрал Python/FastAPI. Основа — [контракт ядра 0.1.0](12-core-v0.1-spec.md).

## Результат этапа

Запускаемое приложение принимает искусственный CSV, сохраняет оригинал и его редакции, обрабатывает строки модулем `demo.document-review`, проверяет результат по зарегистрированной схеме и сохраняет неизменяемую редакцию набора. Пользователь повторяет сценарий через интерактивную документацию API и видит источник каждого значения.

Полный CORE-V01 ещё не выполняется: подключение n8n относится к 3.2; согласования и второй модуль — к 3.3. Данные заказчика, OCR, модели, действующие складские остатки и внешние действия в 3.1 не участвуют.

## Принятый технический профиль

| Решение | Рекомендация | Альтернатива и последствия |
|---|---|---|
| Оригинальные байты | Локальная папка файлов; путь задаётся окружением, в БД хранится логическая ссылка. Доступ только через ядро. Компонент хранения отделён от правил и API | S3-совместимый сервис сразу: нужен дополнительный сервис или доступ к нему, настройка и проверки; выбор продукта ещё не сделан |
| Доступ к PostgreSQL | SQLAlchemy и psycopg, явные транзакции; Alembic для последовательных миграций структуры | Прямой SQL через psycopg: меньше библиотек, больше собственной логики структурных изменений и преобразования записей |
| Доступ к учебному API | Секретные Bearer-ключи из окружения, сопоставленные на сервере с субъектом, областью данных и разрешёнными операциями. Отдельные ключи для проверки разделения областей | Полноценный вход пользователей сразу: нужно выбрать хранение учётных записей, выпуск сессий и правила входа; увеличивает объём этого этапа |

Ключ — предъявляемый клиентом секрет доступа, а не идентификатор пользователя из тела запроса. Такой профиль предназначен для локального учебного контура; он не принимает клиентскую матрицу прав или промышленную систему входа. Секреты не попадают в ответы, Git, документацию или журнал. Сервер по умолчанию слушает только loopback.

Python/FastAPI уже выбраны. Для проверки формата предлагается `jsonschema` с Draft 2020-12, проверкой дат и локальным разрешением зарегистрированных `$ref`. Для запуска — Uvicorn, для тестов — pytest и HTTPX. Версии зависимостей закрепляются после принятия профиля и сверки документации; произвольное скачивание схем по ссылке запрещено.

## Границы реализации

- Правила и прикладные сценарии не зависят от FastAPI, SQLAlchemy или путей Open Server. HTTP принимает команды и отображает ошибки; адаптеры реализуют хранение и доступ к PostgreSQL.
- Реестр содержит проверенный пакет учебного модуля, его манифест, версии и схемы. Регистрация неизменяема для одной пары ID/версия; произвольная загрузка исполняемого плагина через API не добавляется.
- Оригинал сохраняется до доступной ссылки в БД. Незавершённая загрузка не создаёт доступную редакцию. Файловая система и PostgreSQL не объявляются одной транзакцией; объекты без зарегистрированной ссылки не видны пользователю, автоматическое удаление не вводится.
- Новая редакция требует ожидаемого номера прежней редакции. Конкурентное изменение возвращает конфликт; опубликованные редакции не перезаписываются.
- Набор результата, его строки, точный снимок входа и аудит публикуются одной транзакцией. Ошибка посередине не оставляет видимой половины набора.
- Повторы загрузки и обработки защищаются ключом команды в пределах области, субъекта и операции. Тот же ключ и те же данные возвращают прежнюю ссылку; изменённые данные под прежним ключом отклоняются. Защита действует и при одновременных запросах через ограничения и транзакции БД.
- Обработка синхронная и ограниченная учебным объёмом. Сохраняется запись факта обработки для происхождения результата; API управления долговременными процессами и собственный оркестратор не создаются.
- Все чтения и изменения проверяют разрешения и область. Совпадающие байты из разных областей не раскрывают чужие материалы. Файлы не доступны через прямой публичный каталог.

## Предлагаемые операции API

Префикс `/api/v0.1`. Это детализация транспорта прикладных контрактов, а не новая редакция базового контракта.

| Операция | Назначение |
|---|---|
| `GET /modules` | Посмотреть зарегистрированные модули и поддерживаемые схемы |
| `POST /artifacts` | Загрузить оригинал с источником, ролью и ключом команды; получить ID и редакцию |
| `POST /artifacts/{id}/revisions` | Добавить редакцию с ожидаемой прежней редакцией и отдельным ключом |
| `GET /artifacts/{id}/revisions/{revision}` | Прочитать разрешённые метаданные точной редакции |
| `GET /artifacts/{id}/revisions/{revision}/content` | Получить исходные байты после проверки доступа |
| `POST /demo/document-review/extractions` | Обработать точную редакцию CSV и создать либо дополнить набор с проверкой ожидаемой редакции |
| `GET /datasets/{id}/revisions/{revision}` | Прочитать конверт результата |
| `GET /datasets/{id}/revisions/{revision}/records` | Прочитать страницу строк именно этой редакции |
| `GET /artifacts/{id}/history` | Посмотреть доступную историю редакций и связанных результатов |

Область и субъект определяются сервером после проверки ключа. Метаданные источника входят в отпечаток команды. ID имеют серверный формат UUID; исходное имя файла не становится путём хранения. Ошибки доступа не раскрывают существование чужого материала. `/docs` предоставляет интерфейс для ручной проверки; здоровье процесса и доступность БД проверяются отдельно.

## Учебный CSV

Колонки: `line,name,quantity,unit`. Кодировка UTF-8, допускается BOM; разделитель — запятая, строки LF или CRLF. Пустое количество превращается в `UNKNOWN`/`null` с замечанием `MISSING_QUANTITY`; ноль остаётся известным значением. `pcs` и `piece` нормализуются в `piece`, исходная единица сохраняется. Источник каждого поля — точная редакция файла, строка и колонка.

Учебные ограничения: файл не более 5 MiB, не более 1000 строк данных, ячейка не более 2000 символов. `line` — уникальное положительное целое; имя не пустое; известное количество — конечное неотрицательное десятичное число по согласованному формату. Некорректные заголовки, повтор номера, посторонние колонки, лишние ячейки, повреждённая кодировка, неправильное число или неизвестная единица дают понятную ошибку обработки. Оригинал при этом остаётся сохранённым; невалидный набор не публикуется.

Эти ограничения относятся к учебному модулю, не к будущей платформе всех документов. Разделитель, кодировка и поддерживаемые единицы не угадываются автоматически.

## Наблюдаемые проверки

1. CSV из примера v1 даёт две строки: количество `10` и неизвестное количество; набор `PARTIAL`, сохранены ссылки на ячейки.
2. Пример v2 того же материала создаёт вторую редакцию; обе доступны, первая не изменена.
3. Повтор одной загрузки или обработки, включая одновременные запросы, возвращает прежнюю ссылку. Другие данные под тем же ключом дают конфликт.
4. Неправильный CSV сохраняет оригинал, но не создаёт опубликованный набор. Ошибка в середине транзакции не публикует часть результата.
5. Субъект другой области не читает метаданные, оригинал, строки или историю первого субъекта.
6. Реестр отклоняет несовместимую версию и изменённую схему под прежним ID/версией; результат проверяется реальным валидатором.
7. Миграции поднимают пустую отдельную БД; повтор применения ничего не разрушает. Приложение после перезапуска читает прежние результаты.
8. Собранный пакет запускается и проходит загрузку/обработку без `.dev`. Структура БД и HTTP проверяются на PostgreSQL; SQLite не подменяет его в этих проверках.

Проверки связываются с частями CV01–CV20 только в пределах действительно реализованного поведения. Полный сценарий не отмечается выполненным по одному этапу 3.1.

## Размещение и выполнение

Основная папка: `C:/OSPanel/home/bervel.local`, существующая ветка `core`. Создание копии и worktree для этого этапа не требуется; изменения индекса и истории Git не выполняются.

Приложение, исполняемые схемы, миграции и настройки сборки находятся вне `.dev`. Тесты, фикстуры, план, инструкция проверки и отчёт — внутри `.dev`. Runtime-файлы оригиналов не имеют встроенной привязки к `.dev` или Open Server; каталог задаётся конфигурацией. Учебные инструменты могут передавать приложению окружение и входные данные, но приложение не читает их файлы и не требует их для установки.

Используется уже включённый пользователем PostgreSQL 17, отдельные база и роль BERVEL; БД эксперимента n8n и другие базы не меняются. При недоступности модуля его включает пользователь. Redis и n8n на этапе 3.1 не запускаются и не перенастраиваются.
