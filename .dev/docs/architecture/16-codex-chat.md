# Codex, чат и память CSV

Дата: 22 октября 2026. Реализация по автономному запросу владельца. Вкладки: `#/chat` и `#/settings`.

Обновление того же дня: память расширена на весь каталог любых оригиналов, PDF/OCR и изображения. Текущий контракт — [17-file-memory.md](17-file-memory.md); раздел «Память CSV» ниже описывает первоначальную версию и больше не ограничивает поиск последним файлом.

## Устройство

Браузер → FastAPI → PostgreSQL (история и очередь) → Python worker → приватный codex-runner → выбранный провайдер. Runner использует официальный Codex SDK и CLI 0.163.0; SDK управляет процессом CLI без интерпретации пользовательского текста оболочкой. Shell, web search и приложения отключены. Ответ модели не выполняется как код.

API принимает сообщение с ключом команды и отвечает 202. Worker выполняет очередь последовательно внутри диалога с PostgreSQL advisory lock. Повтор команды возвращает прежний результат. Аварийное running завершается явной ошибкой неизвестного исхода; внешняя генерация автоматически не повторяется. История хранится в PostgreSQL, браузер хранит только ID диалога и незавершённой команды.

## Память CSV

Источник — последний загруженный доступный оригинал CSV в области данных, а не последний успешно обработанный dataset. Источник фиксируется при отправке вопроса; следующий вопрос заново выбирает последний оригинал. Чтение проверяет целостность файла. Поддерживаются UTF-8/BOM, разделители comma/semicolon/tab/pipe, кавычки и переносы внутри полей. Все исходные колонки сохраняются в текстовом индексе PostgreSQL.

Индекс делится на фрагменты по 3500 символов. Поиск по словам выбирает до восьми фрагментов в пределах 16000 символов. История ограничена 12000 символами, вопрос — 4000. При неполном контексте источник имеет truncated=true и интерфейс показывает предупреждение. Источник содержит artifact_id, редакцию, имя, время загрузки, номера записей, общее число записей и реальный отрывок. Номера записей не равны физическим строкам CSV с многострочными ячейками.

Это поиск по последнему CSV, а не по всему архиву и не промышленная система семантического поиска. Векторная БД, эмбеддинги, OCR, вложения и каталог диалогов не добавлены. Содержимое CSV передаётся как недоверенные данные; модель не получает SQL, доступ к хранилищу и инструменты изменения приложения.

## Провайдеры и секреты

Вкладка «Настройки» предлагает ровно MOX Access и API-ключ. По умолчанию выбран MOX. Профили и выбранный режим сохраняются в provider-settings.json внутри именованного Docker volume bervel_codex_state с правами 0600. API-ключ — только на запись; GET возвращает лишь признак наличия. После сохранения поле очищается; localStorage/sessionStorage не содержат ключ. Изменение применяется к следующим запросам, уже начатый использует прежнюю конфигурацию.

MOX — необязательное подключение через compose.mox.yaml. Внешние auth.json/config.toml монтируются только для чтения. Runner читает существующие access token/account ID, модель и chatgpt_base_url; токены не копируются в volume и не обновляются приложением. Исходное имя localhost сохраняется для TLS hostname validation. Только optional MOX deployment запускает loopback TCP bridge к host.docker.internal; он пересылает зашифрованные байты, не завершает TLS. Публичный CA монтируется read-only и передаётся Node через NODE_EXTRA_CA_CERTS, дочернему CLI через CODEX_CA_CERTIFICATE. Конечная точка Codex дополняется /codex. Вход/выход, изменение сертификата самого MOX и обновление токенов не выполняются. Доверие внутри контейнера добавлено по явному разрешению владельца. После атомарной замены внешних файлов может потребоваться пересоздать контейнер с тем же read-only подключением.

API-профиль использует HTTPS Responses API, модель и отдельный API-ключ. Основной Compose запускается без MOX. Также сохранён необязательный внешний read-only API secret через compose.codex-credentials.yaml. Ошибка неактивного профиля отображается безопасным статусом и не блокирует рабочий профиль.

Кнопка «Проверить подключение» использует сохранённые настройки и один запрос «Ответь одним словом: OK». Перед передачей токена MOX проверяется HTTPS без credentials. При TLS/auth ошибке запрос останавливается, повторов нет. Таймаут генерации 180 секунд, внутреннего HTTP 190, браузера 200, Nginx 210. Ошибки провайдера не возвращают исходный stderr или секреты.

## Доступ и ограничения стенда

Сохраняется ранее выбранный общий серверный web-ключ без личного входа сотрудников. Чат проверяет владельца диалога, область и chat/artifact/dataset permissions. Настройки общие для установки и требуют settings:read/write; helper добавляет их только выбранному полному web binding без смены секретов. У свежей установки второй тестовый binding этих прав не получает. Все посетители текущего сайта действуют с общим серверным доступом; персональное разграничение посетителей не реализовано.

История/очередь требуют additive migration 0005_chat. Прежние таблицы и Docker volumes не удаляются. Модельный контейнер не имеет доступа к Docker socket, оригиналам, SQL или всему проекту. Файлы разработки .dev не требуются runtime.
