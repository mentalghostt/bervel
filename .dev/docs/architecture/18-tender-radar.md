# Рабочий тендерный радар

Историческое описание. Действующий поток с тремя файлами, фильтрами до LLM и экономикой описан в [архитектуре27.10.2026](24-workspace-assistant-radar.md).

Действующая обработка обновлена26.10.2026: прямая оценка всех тендеров, без embeddings. Пользователь выбрал один длинный запуск без сохранения порций; общий worker не обрабатывает чат до завершения радара. Проверки и ограничения: [отчёт этапа](../quality/radar-direct-evaluation-report.md).

Выбранный профиль читается полностью через DocumentMemory.context(complete=True), без лексического поиска фрагментов. Допускается до96КиБ суммарного извлечённого UTF-8 текста; частично извлечённый/нечитаемый/слишком большой профиль вызывает понятную ошибку до обращения к модели. В чате сохранён прежний поиск фрагментов. Текущий bervel-product-profile.csv утверждён только как список интересующих групп: capability_confirmed=false остаётся ограничением.

Запрос АВТОНОМНО22.10.2026. Корень C:/OSPanel/home/bervel.local, core, Personal; код в существующем дереве, Git только чтение. Реализация текущего сценария по решению владельца разработки; это не промышленная приёмка заказчиком.

## Источники и выбор решения

Рассмотрены оплачиваемое API, импорт официального Excel и неофициальный scraping. Выбирается реальный доступный канал — XLSX/CSV импорт с сохранением оригинала; запрос бесплатного API не подтверждён, приватную авторизацию/схему не выдумывать, signup/заявки не отправлять. Официальное API требует отдельного предоставленного доступа. Текущие публичные карточки можно сохранить в нормализованный CSV со ссылками/датой наблюдения и явно отличить от API/официальной Excel-выгрузки. Исследование ../research/2026-10-22-kontur-tenders.md, разбор пакета ../research/2026-10-22-radar-customer-package.md.

## Границы

Модуль modules/tender_radar владеет отбором и анализом. Общие ArtifactService/DocumentMemory/модельный runner переиспользуются. Транспорт api.py, XLSX/CSV-адаптер infrastructure/importer.py и PostgresRadarRepository в infrastructure/repository.py находятся внутри modules/tender_radar, снаружи его бизнес-логики. Действующая карта — 19-python-layout.md. Две additive таблицы radar_batches/radar_runs, immutable импорт/входной snapshot и версия отчёта. Новый обработчик в прежнем Python worker, никакого дополнительного контейнера/оркестратора. Зависимость openpyxl нужна для реального Excel с датами/leading zeros/hyperlinks; defusedxml и лимиты архива защищают чтение. DOCX/XLSX текст становится доступен общему DocumentReader без изменения старого CSV-процесса.

Пользователь на #/radar импортирует XLSX Контур (реальный F02 header row4, grouped duplicate headings, footer) либо нормализованный UTF-8 CSV. Отдельно выбирает конкретные уже загруженные файлы для RAG; до10 файлов, точные ID/revision закрепляются при отправке, чужие/несуществующие не принимаются. Ни один невыбранный файл не попадает в модель. Тендерная документация/чужие отчёты не объявляются утверждённым каталогом. Не реализуются автоматическая подача, подпись, банковские/складские действия, инвестиционная оценка и неполученная экономика.

## Обработка

Импорт: до5МиБ, ZIP inflated≤50МиБ и≤1000 частей, до10000 строк/200 колонок, отказы с номером строки вместо молчаливой потери. Сохраняются номер/namespace/URL, цена как Decimal string, валюта, aware даты, исходная строка/лист, provenance и предупреждения. Итоги пропускаются явно. Однозначные дубли объединяются; конфликтующие сохраняются/отмечаются. Номер не превращать в число или глобальную идентичность. У normalCSV обязательны number/title/deadline_at/source_url; отсутствующие стадия/свежесть остаются unknown.

Запуск: read/import требуют artifact/dataset permissions, start/read используют прежние process permissions, scope и actor сохраняются. Durable run имеет queued/running/completed/failed; advisory lock не допускает двойной модели, повтор команды возвращает тот же запуск. После аварии running становится failed/unknown, автоматического повторения API модели нет. Новый запуск с обновлёнными данными — явное действие.

Каждая импортированная запись проходит прямую оценку моделью: без поиска по словам, ранжирования кандидатов и общего лимита12. Порции идут последовательно в одном запуске: до20тендеров и240КиБ UTF-8 текста запроса. Даже закрытые/просроченные закупки получают товарный fit. Код отдельно проверяет закрытие, дедлайн, свежесть стадии и конфликты: нерелевантное исключается; релевантное/неопределённое дополнительно ограничивается этими проверками. Поэтому неизвестный срок не превращает непрофильный товар в задачу менеджеру.

Модель возвращает строго проверенный JSON по каждому ID: fit/reason/risks/next_steps/evidence_indexes/product_group/tender_quote/profile_quote. Для relevant нужны дословные цитаты из названия/описания тендера и из указанного читаемого источника; product_group дословно входит в цитату профиля. Пропуски/дубли/чужие ID, неверный формат и неподтверждённые цитаты прерывают весь запуск без публикации частичного отчёта и без автоматического повтора. Fit хранится независимо от итоговой категории. Совпадение группы не подтверждает производство, склад, точные параметры или экономику; participation_ready=false. Новый отчёт1.1.0, старый1.0.0 читается с fit=null.

## UI и проверка

Одна вкладка: источник/импорт, явный выбор файлов RAG, фокус отбора, запуск/прогресс, сохранённые отчёты. Разделы отчёта: в работу/уточнить/исключено/не проанализировано с причинами, исходными URL, дедлайном и свежестью, доказательствами и следующими действиями. Экспорт PDF по фиксированному серверному шаблону BERVEL1.0 со встроенными шрифтами; содержание модели не управляет оформлением. См. ../operations/files-and-pdf.md. Старый чат/CSV/настройки сохраняются.

Критерии: оригинальный F02 импортирован2290 карточек с hyperlink/dates без footer; настоящий текущий CSV даёт релевантных кандидатов, просроченные/отменённые не рекомендуются; изменение выбранных RAG меняет контекст и результат; чужие файлы запрещены; scope/idempotency/crash проверены. Живой UI→worker→MOX→SQL отчёт, reload, скачать отчёт, desktop/mobile QA. Старые данные/auth/config неизменны. Runtime не читает .dev. Основания ADR0001/0004/0005 и03-tender-radar/11-data-sources-and-intake.
