## Как проходит запрос

HTTP проверяет форму входа и получает пользователя с областью данных. Операция модуля проверяет права и правила, вызывает явно переданные платформенные операции/порты. PostgreSQL-адаптер сохраняет задание. Worker вызывает ту же операцию модуля; она читает документы через общую память и обращается к общему модельному клиенту. Адаптер сохраняет результат, HTTP выдаёт его по прежнему URL.

Платформа не импортирует конкретные модули. Их знает `app_setup.py`: явно создаёт зависимости и подключает роутеры. API и worker используют одну сборку; `worker.py` вызывает три обработчика. Манифестов и реестра совместимости модулей нет. `default_schemas` явно регистрирует только реальные схемы сохранённых данных; их версии и закреплённый CSV workflow сохраняются. `/modules` выдаёт прежний статический HTTP-каталог из `core/api/module_catalog.json` для совместимости, не участвуя в сборке или авторизации. Права проверяет сама операция.

CSV preview и индекс используют `core/csv_memory.read_csv`: UTF-8/BOM, Windows-1251 и прежний UTF-16 с BOM; разделители запятая, точка с запятой, TAB и вертикальная черта. Пределы: 5 МиБ, 200 колонок, первые 10000 строк с явной частичностью. Значения остаются строками. Предметный учебный CSV и импорт тендеров сохраняют собственные правила. Индекс документов имеет версию 4: старый производный кэш перестраивается при обращении к проверенному оригиналу, история/оригиналы не меняются. Старые `CsvMemory/retrieve` и методы legacy chunks больше не исполняются; исторические таблицы и миграции сохранены.

Фразу «последний CSV» разбирает `chat.service.select_sources` внутри закреплённого снимка. Общая память получает готовый набор редакций, радар — явный выбор пользователя, без флага отключения поведения чата.

Общий индекс документов и каталог принадлежат `core/infrastructure/documents.py`, а не чату. Репозиторий чата получает каталог явно и фиксирует его в транзакции отправки. Радар использует общую память напрямую. `CommandReceipts` из `core/infrastructure/commands.py` сохраняет прежние блокировку, проверку повторной команды и аудит в переданной транзакции вместе с бизнес-записью. Радар и чат не вызывают private-методы общего репозитория.

## Таблицы и миграции

Общие таблицы описаны в `core/infrastructure/database.py`, `chat_sessions/chat_turns` — в `chat/infrastructure/tables.py`, `radar_batches/radar_runs` — в `tender_radar/infrastructure/tables.py`. Все используют одну metadata; это общий каталог SQL-описаний, а не новая база. Имена таблиц, столбцы и данные не переименовывались.

Миграции исторически централизованы: revision IDs и порядок не меняются. В `0007` сохранено прежнее описание SQL на момент создания таблиц, без импорта текущих моделей. Так будущая правка модели не изменит задним числом установку старой версии. Сам перенос Python-файлов не требует преобразования данных. Новое изменение БД оформляется следующей линейной миграцией.

## Новый модуль

Начать с [минимальной заготовки](../../templates/module/README.md). Скопировать только пакет, добавить нужные публичные операции с типами, порты потребителя и реальные адаптеры. Настройки установки берутся из `core/config.py`/окружения; настройки сценария передаются явно. Подключение — явные строки сборки и только нужные ресурсы в `pyproject.toml`. Не добавлять пустые API/БД/слои ради единообразия. Между модулями разрешены обычные Python-вызовы через публичный пакет `__init__.py`; чужие private-методы, внутренние файлы/таблицы и циклы запрещены. Архитектурная проверка допускает публичный импорт, но проверяет внутренний доступ и циклы.

## Проверка и запуск

Из корня в PowerShell: `.dev/scripts/docker.ps1 -Action tests` проверяет установленный пакет. Полный запуск прежний: `.dev/scripts/docker.ps1 -Action start -Mox` с уже настроенным MOX. Для одинаковой версии API и worker после изменения Python нужна сборка образа и пересоздание обоих контейнеров; один одинаковый tag не доказывает одинаковый image ID. Watch сейчас не используется.

Результаты этой перестройки: [отчёт проверки](../quality/python-layout-report.md). Исторические отчёты соседних этапов не считаются новой проверкой.
