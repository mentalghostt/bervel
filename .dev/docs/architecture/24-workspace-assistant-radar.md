# Рабочее пространство: файлы, радар и ассистент

Файловая модель28.10.2026: [каждый файл имеет один неизменяемый ID](25-independent-files.md). Переход реализован и проверен на восстановленной БД в изоляции; установка в основной runtime и общая итоговая проверка ещё не подтверждены. Остальные описанные здесь UI/chat-возможности установлены предыдущими задачами.

Действующая реализация обновлена28.10.2026. Этот документ заменяет описания прежнего выбора профилей и прямой оценки всех закупок в документах18/23. Исторические отчёты сохраняют свои правила. Проверки нового интерфейса и планирования: [отчёт28.10](../quality/workspace-polish-2026-10-28.md).

## Границы и хранение

Приложение остаётся модульным монолитом Python/PostgreSQL. Общие оригиналы, индексы, права и область данных принадлежат `core`; чат, радар и обращения — своим модулям. `app_setup` передаёт публичные сервисы через конструкторы. HTTP/SQL/SDK не входят в правила отбора. Отдельные исполнители knowledge/chat/radar используют прежнюю очередь PostgreSQL и один пакет приложения.

Миграция0011 добавляет назначение файла: general/procurement/stock/economics. Миграция0012 добавляет обращения и журнал действий ассистента. Миграция0013 заменяет файловые редакции самостоятельными ID и преобразует технические ссылки; исходные тексты чатов и байты сохранённых документов не переписываются. Назначение файла не подтверждает его достоверность. Готовность означает завершённое извлечение и индексирование: `state=ready` и равные счётчики фрагментов. Частичный индекс не считается готовым.

Полное удаление сохраняет прежний контракт: удаляются оригинал и принадлежащие только ему поисковые/производные данные. Общие байты, используемые другим файлом, сохраняются. Старые чаты и отчёты остаются; открытие удалённого источника возвращает410 и текст «Файл удалён». Очистка объектов после транзакции выполняется устойчивым заданием knowledge-worker.

## Отбор закупок

Пользователь выбирает три разных готовых файла по назначению: выгрузка, склад, экономика. Ссылки на точные ID неизменяемых файлов и фильтры сохраняются в запуске. Импорт XLSX/CSV выполняется сервисом радара, загрузки внутри его страницы нет.

Порядок: импорт всех строк → проверка стоимости/срока подачи/публикации кодом → смысловая оценка оставшихся кандидатов моделью → проверка позиций и количества по складу → расчёт экономики и сроков. Все выбранные файлы должны иметь полный индекс. Для полного прохода используются все структурные фрагменты выбранного склада, без ограничения top-k; векторы обеспечивают общую готовность поиска, но числовой расчёт не заменяют. Смысловая модель не определяет остаток или прибыль.

Каждая строка учитывается с происхождением. Полностью одинаковые версии могут объединяться с сохранением всех origins; конфликтующие версии остаются отдельно. `coverage.unique_tenders` — число уникальных пар (номер, ссылка источника), а не число различных номеров. `input_rows/accounted_rows` показывают охват строк. Порции ограничивают размер одного запроса, но не число кандидатов. Ошибка порции сохраняет неполный отчёт и не объявляется успешным анализом; автоматического повтора платного запроса нет.

Фильтры: цена от/до в RUB, запас дней до закрытия подачи, текстовый фокус, допустимая нехватка и минимальная маржа. Неизвестные существенные условия требуют проверки. Срок подачи не считается сроком поставки. Любая нехватка в пределах допуска требует проверки человека, превышение допуска исключает закупку. Каждый тендер оценивается независимо, склад и мощности между ними не резервируются.

Выручка — количество × цена продажи из экономики. НМЦ — верхняя граница бюджета. Расходы — себестоимость и упаковка на единицу плюс выделенные постоянные/логистические расходы один раз на SKU в тендере. Расчёт использует Decimal, единую валюту и полные цены; скрытых конвертаций валют/НДС нет. Мощности CSV — выделенная независимая мощность каждого SKU, общий график оборудования не моделируется.

Отчёт1.3: «Можно участвовать», «Требует внимания», «Вне анализа» (объединяет excluded/not_analysed). Положительная экономика не снимает риски сертификатов и иных обязательных условий. Моковые входы и результаты помечены демонстрационными и не подтверждают фактическую прибыль. Старые кандидаты1.0–1.2 отображаются как «Первичный кандидат». Сохранённый неполный отчёт можно скачать с явным предупреждением.

## Универсальный ассистент

Модель предлагает типизированные операции из закрытого списка. Сервер повторно проверяет аргументы, права/область пользователя и явное намерение из текущего запроса. Документы, результаты инструментов и история не разрешают действия. Явно запрошенное действие выполняется без второго подтверждения. Доступа к shell, произвольному коду и секретам у модели нет.

С28.10 планирование начинается с запроса и каталога метаданных, без фонового извлечения всех документов. Чтение/изображения подключаются через существующий file.read для конкретного ID файла; только эти источники входят в ответ и следующие раунды. Метаданные списка, обращения и прочие команды не требуют embedding-запроса. Legacy ChatService без actions сохраняет прежнее поведение. Авторизация различает создание нового внутреннего черновика обращения и изменение существующего объекта; подтверждённый адресат/полная диагностика для черновика не требуются, факты и шаги нельзя выдумывать.

Действия вызывают те же публичные сервисы, что интерфейс: файлы/назначения/индексирование, радар, доступные настройки, документы, схемы, обращения, веб-поиск. Для «последних данных» выбирается последний готовый файл каждого из трёх назначений. Радар возвращает сохранённую карточку запуска; UI следит за состоянием, показывает ссылку и скачивает PDF через защищённый API.

Изменение документа создаёт новый отдельный файл через file.create после чтения исходного ID. Исходник остаётся до явного удаления; file.revise/file.history удалены. Каждая загрузка создаёт самостоятельный файл, кроме повтора той же команды с прежним ключом.

Результат сохраняется в журнале действия до ответа пользователю. Повтор той же команды не повторяет эффект; неизвестный исход после аварии автоматически не воспроизводится. Документы PDF/DOCX/TXT/CSV и схемы SVG строятся безопасными шаблонами. SVG показывается изображением, не внедряется в DOM. Обращения создаются/редактируются внутри приложения со статусом «Создано»; отправка не реализована.

Следующему шагу модели передаётся отдельное серверное `_receipt` с выполненной операцией, её параметрами и ссылкой на сохранённый результат. Общая карточка сама по себе не подтверждает модели, что редактирование уже выполнено. Квитанция сохраняется при сокращении контекста; длинные параметры отмечаются как частичные. Это только контекст модели, полный результат и карточка интерфейса не меняются. `completed` у квитанции запуска означает принятую команду, состояние самого асинхронного анализа остаётся queued/running/completed. Повторное чтение разрешено для проверки результата; повтор эффекта и неизвестный исход по-прежнему защищены.

Полные результаты и журнал остаются в БД. Только следующий контекст модели ограничен192 КиБ UTF-8 и240 КиБ вместе с JSON/schema framing. Усечения явно отмечены, статистика полного отчёта не пересчитывается по видимой порции. `radar.read_page` читает до100 строк по смещению/ID/решению, включая последнюю строку. Ограничение шести раундов планирования сохраняется; при большем объёме ассистент должен указать непрочитанное и дать полный файл.

## Голос и поиск

Ключ Groq вводится человеком в настройках, хранится только сервером в codex_state и никогда не возвращается API. Голос использует `whisper-large-v3-turbo`: запись до60 с/5 МиБ → распознавание → редактируемый черновик → обычная отправка. Отмена/переход освобождают микрофон и прерывают запрос. Для микрофона нужен защищённый контекст браузера; локально используется127.0.0.1.

Веб-поиск выполняется штатным Codex по запросу пользователя, с подтверждёнными native источниками. Поддержка standalone web и маршрут /alpha/search описаны в26-assistant-data-and-native-web.md. Groq используется только для голоса; его ключ не участвует в поиске. Ссылки из обычного текста модели не выдаются за результаты поиска.

Работа и ограничения: [инструкция](../operations/workspace-assistant-radar.md). Проверки установки и живых сценариев: [отчёт](../quality/workspace-upgrade-2026-10-27.md).

Интерфейс28.10: верхнее меню; список файлов ограничен по высоте, документ справа имеет такую же минимальную высоту и растёт по странице. Загрузка — modal dialog; удаление — действие карточки. Результат/история радара растут вниз, история сортируется по created_at DESC и не поднимает просмотренный запуск. Источники чата — уникальные ссылки artifact_id в «Файлы», без повторных excerpts. Canonical radar URL используетrun, старыйrun_id — поддерживаемый alias. Полные результаты БД и PDF-происхождение сохраняются;0013 меняет только структурированные файловые ссылки. Исторические тексты и байты документов сохраняются.

Чаты28.10: слева серверный список собственных диалогов по created_at DESC/session_id DESC, сводки с пагинацией; полный контекст читается только для выбранного чата. DELETE с ключом команды удаляет только session/turns/actions этого диалога, сохраняя независимые результаты и минимальные служебные квитанции. Enqueue и delete сериализованы; worker lock и queued/running запрещают удаление активной работы. Переписка прокручивается внутри высоты окна; ввод со стрелкой и микрофоном остаётся внизу. Неизвестный DELETE сохраняет ключ и блокирует ввод выбранного чата до разрешения; определённый409 освобождает попытку,404 сбрасывает недоступный выбор без повторной отправки. Проверки: [отчёт о чатах](../quality/chat-workspace-2026-10-28.md).
