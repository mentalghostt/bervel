## Идентичность и ответственность

Один `artifact_id` определяет один неизменяемый файл с именем, байтами, происхождением, временем регистрации, назначением и состоянием подготовки. Каждая новая загрузка создаёт новый ID, даже при совпадении имени и байтов. Только повтор той же команды с прежним `command_key` возвращает её исходный результат. Общий физический объект допустим; удаление защищает все оставшиеся ссылки на его байты.

`core.models.ArtifactRef(artifact_id)` адресует файл; `Artifact(ref, metadata, content)` содержит прочитанный оригинал. `RegisterArtifact` регистрирует самостоятельный файл без параметров выбора/замены прежнего. Метаданные принадлежат `artifacts.metadata`; индексы документов, CSV и знаний ссылаются на ID файла, фрагменты дополнительно имеют порядковый номер. Чат и радар хранят ссылки на конкретные ID. Назначение можно менять у того же файла; содержимое через эту операцию не меняется.

Редактирование документа ассистентом: `file.read` исходного файла → `file.create` изменённого содержимого → новый ID. Исходный файл остаётся. Право сохранить правку само по себе не разрешает удалять источник. Операции `file.revise`/`file.history`, методы истории, таблица `artifact_revisions` и указатель `current_revision` отсутствуют в новой модели. Фиктивный номер редакции и постоянный механизм совместимости не вводятся.

Собственные редакции `dataset_revisions`, обращений и версионные схемы/алгоритмы сохраняют прежний смысл. Поля происхождения внешней системы также не становятся историей файла внутри BERVEL.

## Файловый HTTP-контракт

Все пути ниже имеют префикс `/api/v0.1`. Права и проверка области данных выполняются сервером, как раньше.

| Операция | Путь и результат |
|---|---|
| Создать файл | `POST /artifacts` → `{artifact_id}` |
| Список | `GET /artifacts?cursor&limit` |
| Метаданные | `GET /artifacts/{id}` |
| Оригинал | `GET /artifacts/{id}/content` |
| Просмотр | `GET /artifacts/{id}/preview?cursor&limit` |
| Готовность | `GET /artifacts/{id}/knowledge` |
| Продолжить подготовку | `POST /artifacts/{id}/knowledge/resume`, тело `{}` |
| Назначение | `PUT /artifacts/{id}/usage-role` |
| Полное удаление | `DELETE /artifacts/{id}` → 204 |

Файловые `revision`/`expected_revision` отвергаются с422, устаревшие файловые маршруты `/revisions` и `/history` удалены. Закладка `#/files?artifact_id=UUID` открывает ровно этот файл. Старый параметр `revision` даёт явное сообщение «Ссылка устарела» без чтения другого содержимого. Старую неизвестную команду радара в браузере с неподдерживаемыми ссылками нельзя автоматически отправить в новом формате: её JSON и ключ сохраняются, запуск блокируется до сверки результата человеком.

Полное удаление очищает оригинал и принадлежащие ему поисковые/производные данные. Сохранённые чаты, результаты радара, обращения и защита повторов остаются. Минимальная запись удалённого файла имеет SQL `NULL` вместо метаданных: свой источник возвращает410, чужая область404. Устойчивая очистка объектов и блокировка с активной подготовкой сохраняются.

## Однократный переход данных

Миграция `0013` переносит метаданные в `artifacts`, удаляет файловые номера из индексов и ссылок. Текущее содержимое сохраняет прежний UUID; прочие сохраняемые варианты при наличии получают `uuid5(original_uuid, 'bervel:file-revision:<number>')` как самостоятельные ID. Ссылки на уже удалённое содержимое получают только минимальную запись в прежней области доступа, без восстановления байтов. Исторические миграции остаются необходимой историей установки.

Преобразуются только именованные технические ссылки приложения: источники/снимки/карточки чата, аргументы и результаты действий, выбор/снимки/отчёты радара, индексы и служебные квитанции. Пользовательские таблицы, свободный текст, числовые результаты и произвольное поле `revision` в предметных данных не переписываются. Готовые эмбеддинги и их исходный текст сохраняются без платной переиндексации. Completed/failed/unknown квитанции остаются защитой от повторного эффекта; удалённая старая операция не может воскресить файл.

По отдельному разрешению до миграции из рабочего хранилища уничтожены ровно28 скрытых файлов/32 сохранённых содержимых;17 неиспользуемых физических объектов удалены,6 активных оригиналов сохранены. После удаления сделана проверенная резервная копия БД/объектов. Старые независимые резервные копии и исходные папки пользователя в эту операцию не входят.

Изолированное восстановление фактической копии с последующей миграцией подтвердило сохранность6 активных файлов,7678 прежних векторов,13 запусков радара (12 с отчётом),44 реплик,14 чатов,4 обращений и29 действий. Старой файловой схемы в проверенной БД нет;4 дополнительные минимальные записи обеспечивают честный ответ об удалённом источнике. Это проверка сохранности, отдельно от установки в основной runtime.
