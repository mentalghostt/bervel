## Работа с данными

Планировщик получает каталог и формирует типизированные команды. knowledge.search ищет в текущем доступном каталоге PostgreSQL через существующую базу знаний, с необязательным назначением файла. Пользователь не обязан помнить имя загрузки. Найденные фрагменты являются кандидатами, не полным содержимым или итогами. Старые ответы/документы не разрешают дополнительные действия.

file.read_page читает упорядоченные фрагменты с offset/limit/next_offset и исходными строками/страницами. Счётчики страницы относятся к фрагментам, а не к строкам таблицы. В модель передаются целые фрагменты; усечение не перескакивает через недочитанный фрагмент.

file.query читает полный CSV либо выбранный лист XLSX: количество строк, суммы названных столбцов через Decimal, необязательная группировка. Это серверный расчёт без произвольного SQL модели. Ограничения:10000строк данных,200столбцов XLSX; неверный dimension hint не доказывает полноту. Неизвестные/нечисловые/формульные значения суммируемого столбца требуют уточнения, не заменяются нулём. Несколько листов требуют явного выбора. Число строк не автоматически равно числу уникальных SKU.

Признаки mock из data_kind, имени и происхождения созданного файла сохраняются в поиске/чтении/расчёте. Сервер маркирует создаваемые PDF/DOCX/SVG/TXT; CSV сохраняет табличные байты, происхождение и предупреждение карточки. Производные индексы старых таблиц могут обновиться для сохранения признака mock; векторы не переиндексируются.

## Codex и веб

Используется прежний Codex SDK0.163 и выбранный шлюз/модель. Для web-turn объявляется model_providers.bervel.supports_standalone_web_search=true. SDK вызывает штатный POST /alpha/search. Локальный прокси пропускает неизменённые байты /responses и /alpha/search; tools/tool_choice не подменяет.

Источники берутся из native text_result и Responses annotations/action.sources. Обычные URL в тексте модели не являются доказательством поиска. Ключ Groq нужен исключительно для голосового распознавания и не участвует в веб-поиске.

Только явный HTTP429 до успешного ответа /responses допускает не более трёх попыток. Retry-After seconds/date учитывается; ожидание более10с возвращает MODEL_RATE_LIMITED без раннего повтора. При отсутствии заголовка ожидание500/1000мс. Общие deadline/cancel сохраняются. /alpha/search, неизвестный транспортный исход и успешный поток повторно не исполняются. Бизнес-команды и квитанции не переигрываются.

Общий бюджет одного нативного web/model запроса —180секунд внутри190секунд Python/HTTP-транспорта. Прежние60секунд относились к удалённому fallback старого провайдера и оказались недостаточными для составного нативного поиска конкурентов. Новое ожидание не означает повтор старой команды.

## Границы и проверки

Устойчивость чата дополнена 28.10.2026, см. [команды и квитанции ядра](12-core-v0.1-spec.md). Известный отказ query embeddings не запрещает чтение базы: `KnowledgeService.retrieve_result` возвращает `RetrievalResult(sources, mode, notice, reason)`, а scoped PostgreSQL `lexical_search` ищет по сохранённым текстам. Лексический режим не смешивает векторы, не переиндексирует файлы и не означает полноту поиска. При нулевой выдаче режим и ограничение сохраняются отдельно от источников. Чужие, удалённые файлы и другая модель индекса не становятся доступными через резервный поиск.

`file.read` выбранного оригинала при пустом поиске или недоступном индексе использует упорядоченную первую страницу `DocumentMemory.read_page`. В результате явно указаны `read_mode=page`, исходные локаторы и неполное покрытие. Это чтение оригинала без повторного embedding-запроса; поиск кандидатов и чтение известного файла имеют разные обязанности.

Ожидаемые отказы операций передаются планировщику как model-only `_receipt.state=failed` с безопасным кодом и сообщением. Они не становятся успешными карточками или источниками. Исправление заведомо отклонённых параметров допускается; повтор той же failed-команды, completed-мутации и новый web-поиск после failed web в том же запросе останавливаются. Изменение формулировки запроса не обходит этот запрет.

Неопределённый исход сохраняется как `unknown`: в частности, потеря подтверждения после регистрации файла или записи настроек. Он и отказ в правах останавливают следующие эффекты. Ошибки модели, её транспорта, лимит шагов и контекста дают честный доставленный ответ с фактически сохранёнными карточками. `completed` у сообщения означает доставленный ответ, а не успешность каждой операции. Окончательный текст после эффектов/отказов строится сервером по квитанциям; модель не может объявить несозданный файл готовым. Неизвестные программные ошибки остаются ошибками и не маскируются успешным результатом.

Политика повторов относится к текущему клиенту/runner: временная ошибка, неизвестный оплаченный исход и подтверждённая завершённая операция различаются. Повтор не должен переигрывать бизнес-квитанцию.

Модули вызывают существующие scoped сервисы. Доступ/идентичность пользователя принадлежат серверу. PDF/DOCX рендерится сервером из текста. Новых зависимостей и служб продукта нет. Защита неизвестного исхода сохранена; исследование ограничено отдельно от подготовки, создания и проверки документа.

Длинные задачи используют серверную машину состояний research → synthesizing → generating → verifying → completed/partial/blocked. Состояние, версии checkpoint и стабильные доказательства сохраняются в JSONBworkflow; UI получает безопасную сводку. Миграция0014 аддитивна, старые строки остаются workflow=NULL. Исследование:4раунда/2web/240секунд; подготовка текста180секунд, сохранение120секунд, затем локальная проверка. При нехватке данных или провайдере429готовый результат не объявляется. Сохранённые состояния/квитанции определяют дальнейшее продолжение; завершённый документ подтверждается регистрацией и проверкой, а не обещанием модели.

Переход0013 из прежней задачи обязателен для совместимости текущих исходников. Проверяется восстановлением фактической БД и сохранностью данных, затем единым обновлением API/трёх Python workers/frontend/Codex. Служебные tombstones старых удалённых редакций не содержат оригиналов и нужны для корректных410/404.
