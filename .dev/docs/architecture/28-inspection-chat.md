# Проверка BERVEL — 29 октября 2026

## Утверждённая задача

Раздел «Проверка» предоставляет такие же сохраняемые чаты, как универсальный ассистент. Руководитель исследует всю BERVEL: исходники, `.dev`, оригиналы, БД, конфигурацию, логи, контейнеры и тома проекта. Ограничение относится к ИИ этого раздела; остальные страницы и общий вход сохраняются. Единственный предметный эффект — создание нового внутреннего обращения по прямой просьбе пользователя. Значения паролей, токенов и ключей скрываются. Пользователь разрешил автономную реализацию всех этапов.

## Границы и компоненты

- Существующий модуль chat владеет диалогами, очередью, квитанциями и HTTP-контрактом. Новое неизменяемое поле session.mode (`assistant` / `inspection`) разделяет списки, адресацию, команды и выбор worker. Старые строки получают `assistant`; прежние тексты и результаты не переписываются.
- Общие ChatService, роутер и компонент интерфейса получают явно выбранный режим/исполнитель. Проверка имеет собственный закрытый контракт инструментов в modules/inspection. Универсальный исполнитель не вызывается для inspection даже при подмене URL/аргументов/содержимого модели.
- Изолированный inspection-reader читает источники. Файловые bind/volumes доступны ro. Подключение БД — отдельный LOGIN без членства, владения, DML и DDL, только CONNECT/USAGE/SELECT; каждое чтение идёт в READ ONLY транзакции. Произвольный SQL не принимается: разрешены только выбор таблицы, столбцов, страницы и точного фильтра.
- Только reader получает Docker socket. Его внутренний HTTP-контракт принимает именованные диагностические операции; наружу нет маршрута Docker, произвольного URL, HTTP-метода, exec, start, stop, create или write archive. Контейнер выбирается по точному ID/имени и метке compose project=bervel. Тома и mount-пути исследуются через разрешённое чтение файлов контейнера; никакой запускаемой контейнерной команды.
- Worker получает только URL reader; модель получает только типизированные результаты, не транспорт, доступ к сокету или служебные credentials. Новых сторонних зависимостей не требуется.

## Чтение и секреты

Операции: system.list, system.read, database.tables, database.schema, database.rows, container.list, container.inspect, container.logs, container.files и ticket.create. Каталог system имеет именованные корни project и objects; файлы томов дополнительно доступны через container.files. Пути нормализуются, выход за корень и ссылки наружу запрещены; socket/device/FIFO не читаются. Чтение текстов и структур данных постраничное, с next_offset и точными локаторами. Поддерживаемые документы извлекаются штатным декодером, неизвестный бинарный формат возвращает свойства и явное ограничение. Непрочитанный остаток никогда не выдаётся за проверенный.

Все результаты проходят маскирование до модели, квитанций, истории и тикетов. Маскируются чувствительные поля вложенных JSON/ENV/конфигурации, auth-заголовки, private keys, URL credentials и известные значения секретов из окружения/конфигурации установки. Маскирование файла выполняется до разбиения на страницы. Сырые скачивания, кодировки в обход маскирования и произвольное выполнение отсутствуют. Служебные credentials и внешние mounts MOX не изменяются. Нераспознанный секрет в произвольном свободном тексте остаётся ограничением эвристического распознавания; известные значения маскируются независимо от имени поля.

## Разрешённая запись

Создание/отправка/удаление собственных диалогов человеком и сохранение истории/очереди/квитанций являются служебной работой чата. Эти операции не входят в инструменты ИИ. ticket.create вызывает публичный TicketService, сохраняет внутренний черновик со ссылкой на результат, защищается прежней квитанцией/idempotency и независимой проверкой прямого намерения. ticket.edit, изменение файлов/ролей/индекса, настройки, радар и внешняя отправка отсутствуют. Повтор неизвестного эффекта запрещён.

## Интерфейс и ошибки

Пункт «Проверка» рядом с ассистентом; одинаковые список диалогов, ввод и история. Отдельные browser storage keys и API namespace исключают смешение выбора и незавершённых команд. Краткое пояснение режима только при пустом чате. В ответах и раскрываемых результатах — реальные пути, строки, таблицы, контейнеры и время логов. Недоступный reader/источник, неподдерживаемый формат и лимит явно обозначаются; исправление и создание фиктивных источников не выполняются. Ошибки транспорта не сохраняют сырые exceptions.

## Проверка и установка

1. Сначала RED-тесты: неизменяемый режим, изоляция очереди/команд, запрет всех чужих операций, обход пути/симлинка, секреты до paging, чужой контейнер, запрет SQL, создание тикета без дублей.
2. GREEN: реальные PostgreSQL проверки в отдельной test DB, тесты reader с управляемым Docker transport, общий backend/Node/browser набор, build/lint.
3. Живая проверка нового UI desktop/mobile и настоящего model turn: чтение кода/БД/контейнера, отказ записи, создание собственного контрольного тикета. Контрольные изменения только в собственном чате/тикете.
4. Перед установкой — снимок прежних данных и оригиналов, backup/restore check, отсутствие активных заданий; согласованный пакет API/workers/frontend/reader, additive migration. После — сравнение прежних записей/оригиналов, доступность всех служб и повторная живая проверка. VPN, OSP, Git index/history и внешняя конфигурация не меняются.

## Источники технических контрактов

Context7 недоступен в текущей сессии. Проверены официальные Docker Engine security/API v1.53, PostgreSQL GRANT/READ ONLY, SQLAlchemy PostgreSQL READ ONLY, FastAPI request body, React useState. Диагностическое чтение `.dev` — явно запрошенный источник проверки; обычная сборка/работа BERVEL по-прежнему не зависит от наличия `.dev`.
