# Радар1.4: извлечение и сопоставление через эмбеддинги

Реализация29.10.2026. Пользователь выбрал два прохода ИИ и сохранение действующих фильтров, остатков и экономических формул. Индекс и embedding-модель остаются общими с памятью документов. Новых зависимостей, таблиц и миграций нет.

## Поток

`filter_rows / preselect → extraction_prompt → parse_extractions → DocumentMemory.matching_context → matching_prompt → parse_matches → full_report → stock_check / economics_check`.

Первый проход получает только исходные тендеры. Возвращает обязательные позиции с дословными цитатами и исходными quantity/unit; общий бюджет ответа30000символов, максимум50позиций тендера. Он не получает каталог/экономику. Сервер проверяет все ID, цитаты и тип количества. Количественные строки сопоставляются отдельным вхождениям исходника: одна строка болтов не может покрыть строку кабеля с тем же количеством. Неполнота остаётся явной.

Каждая цитата становится поисковым запросом в выбранном файле склада. Тот же OpenAI text-embedding-3-small:1536 и существующий pgvector/полнотекстовый поиск возвращают до48 исходных фрагментов. Память проверяет доступ/целостность оригинала и режим hybrid; lexical fallback не считается успехом радара. Структурные строки CSV связывают фрагменты с каноническими SKU. Явное упоминание SKU сохраняется среди кандидатов, но не отменяет проверки характеристик. Повторные одинаковые запросы используют кеш только внутри текущего запуска.

Второй проход видит исходные тендеры, полный выбранный профиль для определения товарной группы, проверенные позиции и кандидатов отдельно для каждой позиции. Кандидаты содержат полные характеристики из строгого импортера. Векторы не передаются модели. Для relevant запрещены потеря/перестановка позиций, изменение цитат/количеств/единиц, повышение false полноты и SKU другой позиции. Чисто смысловая близость не доказывает точного соответствия. Смешанные лоты сохраняют непрофильные товары с null SKU. Нет кандидатов — неизвестная идентичность, а не доказанное отсутствие товара.

Бюджет второго ответа учитывает уже известные цитаты и длины допустимых SKU; oversized тендер отмечается отдельно, соседние продолжают анализироваться. Повторы ИИ при неизвестном исходе не добавлялись. MODEL_RATE_LIMITED на любом проходе останавливает последующие порции; сбой семантического поиска также останавливает запуск с частичным отчётом.

## Расчёты и совместимость

`full.py`, `preselection.py`, `stock.py`, `economics.py` не изменены. Количества/остатки и маржа рассчитываются прежним кодом. Экономика присоединяется по точному SKU после сопоставления; числовые поля не выбираются по близости эмбеддингов. Требования к полноте и mock остаются.

Новые команды фиксируют selection.pipeline_version1.4, отчёт schema_version1.4.0. Ранее созданные1.3 исполняются прежним путём; исторические результаты не пересчитываются. API, UI и PDF понимают обе версии.

Отчёт сохраняет semantic_analysis по tender_id: extraction, retrieval (номер позиции, кандидаты, ID/строки источников), matched. funnel различает extraction_requests, matching_requests, embedding_queries; model_requests — сумма двух модельных этапов. embedding_queries — число поисковых запросов до внутреннего разбиения, не счётчик HTTP-вызовов провайдера. portion_errors.stage показывает extraction/retrieval/matching.

Теперь каждый из четырёх workers knowledge/chat/radar/inspection получает8000 embedding-токенов/минуту: суммарно32000. Индексация раньше имела24000, когда радар не выполнял embedding-запросы. Её скорость может снизиться. По-прежнему одна реплика каждой роли; произвольное масштабирование требует общего лимитера.

## Ограничения

ИИ работает только с имеющимися title/description. Карточки Контур/ЕИС и ТЗ автоматически не загружаются. Результат uncertain при отсутствии состава остаётся корректным. Эмбеддинги повышают полноту поиска синонимов, но измеримое улучшение точности на реальных тендерах требует независимой разметки. Небольшой каталог из10товаров часто целиком попадает в48кандидатов; этот контроль проверяет путь обработки, не статистический прирост точности. Полный профиль сохраняет прежний предел96КиБ.
