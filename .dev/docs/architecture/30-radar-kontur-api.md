# Источник Контур.Закупки API

Реализовано 29 октября 2026. Основание: [официальная документация](https://developer.kontur.ru/doc/zakupki.external_api?about=0), сохранённая OpenAPI-схема и реальные ответы API в `local/kontur-api-2026-10-29`.

`KonturClient` — внешний адаптер модуля радара. Ключ `KONTUR_API_KEY` передаётся только API и radar worker; заголовок `X-Kontur-Apikey` отправляется только документированному HTTPS origin. Ключ отсутствует в интерфейсе, командах радара и снимках. Redirect запрещён, запросы последовательные, ответ/снимок ограничены; HTTP429 и неизвестные исходы автоматически не повторяются.

1. Пользователь выбирает выгрузку или API. Для API задаёт 1–20 поисковых выражений, период публикации до 366 дней по Москве, стадию и лимит 1–100 закупок. Поиск включает документы. Склад и экономика выбираются из прежних полностью подготовленных файлов.
2. `POST /api/v0.1/radar/analyse-kontur` проверяет права, роли и параметры, закрепляет команду и ставит её в прежнюю очередь. Сетевых запросов к Контуру внутри HTTP нет. Пока данные не получены, `batch_id=null`.
3. Worker последовательно читает `/external/v1/search` (страницы по 50, с нулевой страницы) и полные `/external/v1/purchases/{id}` выбранных записей. Неполная/изменившаяся пагинация, дубли и ошибка любой полной карточки останавливают получение. Незаметной подстановки выгрузки или публикации части источника нет.
4. Исходные ответы сохраняются неизменяемым JSON-артефактом, нормализованные TenderRecord — прежней партией. В транзакции запуска закрепляются партия, снимок и статистика источника. Это аудит ответа API, без промежуточного XLSX/CSV. Фактическая точность чисел сохраняется через Decimal.
5. Далее работает pipeline1.4: прежние фильтры → извлечение позиций ИИ → гибридный поиск выбранного склада → сопоставление ИИ → прежние расчёты остатков и экономики. Сводный состав и распределение по заказчикам не суммируются повторно. Неоднозначные количества дают явную ошибку источника.

Нормализация передаёт названия, бюджет, валюту, сроки, наблюдаемую стадию и строки позиций с количеством, единицей и характеристиками. Полные дополнительные поля/условия/цены позиций/ссылки документов остаются в исходном JSON. Файлы по ссылкам автоматически не скачиваются. Поэтому наличие ссылки на ТЗ не означает, что его текст прочитан ИИ.

Маски `#####` и `░░░` означают ограниченный доступ, не демонстрационные данные. Для товарного подбора `source_restricted` учитывает только поля материалов: Name, Quantity, Okei и названия/значения/единицы Characteristics. Маски реквизитов, контактов, классификаторов, ссылок и прочих полей не устанавливают неполноту состава. Скрытая цена остаётся неизвестной для отдельной экономической проверки.

`source_incomplete` устанавливается при отсутствии состава отдельного лота/заказчика, обязательных полей материала или значений заявленных характеристик. ИИ не может снять этот запрет. Стандартная инструкция «Участник закупки указывает в заявке конкретное значение характеристики» разрешает пустое значение для выбора участником; инструкция сохраняется в описании, фактическое значение не выдумывается. Маски значения эта инструкция не разрешает. Отсутствие отдельного массива Characteristics само по себе не доказывает неполноту: параметры могут быть в Name, точность сопоставления проверяется вторым проходом. Причины входят в риски и статистику. `demo` реального API не устанавливается; прежняя отметка МОК по тестовым складу/экономике сохраняется. Исторические снимки и отчёты автоматически не переписываются.

Отчёт показывает количество найденных и загруженных закупок, выбранный предел, число позиций/документов, время снимка и ограничения. Исходный JSON можно скачать. `GET /radar/kontur/status` проверяет только наличие настройки ключа, не доступность сети/тарифа и не расходует поисковую квоту.

Миграция0016 меняет только nullable у `radar_runs.batch_id`. Исторические файловые команды, pipeline1.3/1.4 и расчётные функции сохранены. Неопределённая отправка в UI восстанавливается с прежними параметрами и ключом идемпотентности. Прерванное исполнение worker не запускается автоматически заново.

Действующие ограничения ИИ по объёму и эмбеддингам остаются в силе. Большой состав может дать `RADAR_CONTEXT_LIMIT`; данные не обрезаются. Ошибка эмбеддингов останавливает анализ с частичным отчётом. Успех загрузки API не означает успех последующих этапов.
