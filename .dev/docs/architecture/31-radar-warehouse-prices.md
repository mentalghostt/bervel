# Радар: экономика из складского CSV

Версия алгоритма 1.5, схема отчёта 1.5.0. Установлена 30 октября 2026.

Радар принимает склад с ценами и источник тендеров: выгрузку либо Контур API.
Отдельный файл экономики необязателен. В интерфейсе по умолчанию выбраны
«Цены из склада»; существующий файл экономики автоматически не подставляется.
Явный выбор отдельной экономики сохраняет прежний алгоритм 1.4 и его расчёты.
Прежние сохранённые отчёты и команды продолжают использовать свою версию.

Без economics_source цены читаются из оригинала выбранного склада:
sku, unit, currency, sale_price, unit_cost, data_kind. Валидность колонок и цен
проверяется до постановки задачи и расходования квоты Контур API.
Цены считаются окончательными: доставку и другие расходы повторно не начисляем.
Для требуемого закупкой количества q по каждой сопоставленной позиции:

- Выручка = Σ(q × sale_price).
- Себестоимость = Σ(q × unit_cost).
- Валовая прибыль = выручка − себестоимость.
- Маржа = валовая прибыль / выручка × 100%.

Используется требуемый объём закупки, а не весь складской остаток. Единицы,
валюта и бюджет проверяются прежними правилами; деления на ноль нет.
При нехватке в пределах допуска восполнение остаётся неподтверждённым;
нехватка сверх допуска исключается прежним правилом.

Последовательность сохранена: детерминированные фильтры → первый LLM извлекает
состав закупки → эмбеддинги и поиск только в выбранном складе → второй LLM
сопоставляет позиции с SKU → код проверяет остаток и экономику.
Недоступность эмбеддингов останавливает сопоставление с частичным отчётом.
Маскированные данные API не заменяются вымышленными значениями.

В версии 1.5 «Можно участвовать» означает товарно-экономический отбор.
Сроки исполнения и мощности отдельно не проверяются: production_readiness=unknown,
participation_ready=false. Интерфейс и PDF явно показывают эту границу;
непроверенные дни не отображаются как рассчитанные сроки.

При обрыве отправки сохранённое тело команды повторяется без изменения состава
источников. Недоступный ранее выбранный файл экономики сохраняется в селекторе
с пояснением и блокирует новую отправку до явного выбора пользователя.

Миграции БД и новые зависимости для режима не требуются. За проверку складских
цен отвечает EconomicsImporter.parse_stock, расчёт остаётся в economics_check.
