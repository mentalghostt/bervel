# Проверка: настоящий встроенный Codex CLI — 30 октября 2026

## Файлы и визуализации — обновление 2 ноября 2026

Фиксированный предел 5 МиБ для оригиналов удалён из браузерного загрузчика, экспортера, регистрации, HTTP upload/download и общего preview. Оригинал может передаваться как bytes или seekable stream: SHA256 и прежний fingerprint вычисляются порциями по 1 МиБ, store публикует immutable hash-key атомарно и проверяет содержимое перед выдачей. API использует UploadFile spool на существующем дисковом volume через `TMPDIR=/data/objects`, а не RAM `/tmp`; download отдаётся StreamingResponse с закрытием дескриптора при завершении/отмене. Node exporter хеширует и отправляет один file-backed Blob, поэтому замена исходного файла не регистрирует новые байты под старым ключом. MIME не ограничен списком расширений. Ограничения конкретных декодеров, голоса и контекста моделей остаются отдельными контрактами.

Mermaid-блоки визуализируются через лениво загружаемый Mermaid 12.2.0 в strict mode и SVG image. Ошибка синтаксиса сохраняет исходник и показывает понятное сообщение. HTML-блоки и экспортированные text/html отображаются прямо в inspection-ответе в opaque iframe `sandbox=allow-scripts`, без same-origin. Внутренний CSP блокирует загрузку внешних ресурсов и HTTP-запросы, а доверенная страница приложения задаёт `frame-src 'none'`, блокируя также сетевую self-navigation iframe. Ползунки и JavaScript автономных графиков работают; исходный файл остаётся доступен для скачивания. Доступа к DOM, storage и авторизации приложения у графика нет. Это изоляция от приложения, а не обещание air-gap всех побочных сетевых протоколов браузера (WebRTC/DNS); отдельный JS runtime в эту задачу не входит. CLI по-прежнему имеет собственный доступ в интернет.

Ошибки отсутствующего файла, чтения диска, неподтверждённой передачи и несовпадения контрольной суммы различаются; отказ передачи больше не описывается как невозможность читать большой файл. Текущий интерфейс передачи описан ниже.

Последнее прямое решение пользователя заменяет read-only выпуск от29.10.2026 и промежуточное расширение с подтверждаемыми патчами. Раздел «Проверка» — транспорт и отображение настоящего Codex CLI с полными правами, native контекстом и обычными инструментами. Прежние planner/actions/context/engineering классы могут оставаться для исторических тестов, но не собираются в действующий inspection workflow и не являются fallback при ошибке CLI.

## Состав и владение

`chat` по-прежнему владеет BERVEL сессиями, HTTP, очередью, историей отображения и Stop. Неизменяемый `mode=inspection`, отдельный API/browser storage/worker отделяют их от обычного ассистента. `app_setup` создаёт `ChatService` инспектора с `NativeInspectionWorkflow`, `NativeCliClient`, `memory=None`, `model=None`, `actions=None`; content filter предназначен только для post-CLI отображения. В сборке нет `EngineeringService` и confirmation routes. Обычные chat/radar/voice продолжают использовать прежние `/v1/generate` и свои контракты.

Node `NativeInspectionJobs` в codex service запускает настоящий CLI через уже установленный официальный `@openai/codex-sdk` 0.163.0. Не добавляется самописный MCP/JSON planner или AppServer orchestration. SDK передаёт исходную строку вопроса в `thread.runStreamed(question, {signal})`, без префикса, history envelope, outputSchema, классификатора действий и ручного подбора контекста. Inspection не имеет искусственного 4000-character input ceiling; слишком большой HTTP payload отклоняется явно.

Private job API: POST `/v1/inspection/jobs`, GET `/v1/inspection/jobs/{id}`, POST `/{id}/cancel`. Идентичность actor/scope/session/request ID и server-side токен защищают transport и чужую историю, а не выдают разрешения на отдельную команду модели. API key приложения передаётся как credential окружения для API/export helper; он не вставляется в пользовательский вопрос. Native session→thread mapping и job state хранятся атомарно в существующем codex_state; сам вопрос/API key не дублируются в job receipt.

## Native контекст и продолжение

Первое сообщение использует `startThread`; последующие — `resumeThread` того же native ID. CLI хранит rollouts в отдельном `CODEX_HOME=/data/codex/native-inspection`, mapping/jobs/exports — в соседних inspection-каталогах состояния. Перезагрузка UI или штатный restart не требует вручную собирать историю. Контекстное окно, выбор инструментального контекста и compaction принадлежат CLI. Нет вызовов прежнего `ConversationContext.select`, автоматического clipping истории/выдержек или предварительного маскирования модельного ввода.

Pre-native BERVEL сообщения сохраняются как архив. Они не превращаются автоматически в prompt нового native thread; при необходимости агент читает доступную историю через обычный API. Один BERVEL диалог остаётся одним расследованием; новый диалог получает независимый native thread.

У приложения нет общего лимита раундов, секунд или токенов native задачи. Старые восемь раундов/240 секунд и 180 секунд на вызов старого planner не применяются. Технические timeouts HTTP/провайдера/SDK сохраняются и не означают общий бюджет задачи. POST acknowledgement при потере связи не повторяется как новый запуск: Python продолжает GET observation и доставку Stop. Недоступный job после прерывания даёт явный `unknown`; после Node restart queued/running jobs помечаются `unknown`, без автоматического replay. Ошибка нового пути не переключает его на старый planner.

Stop посылает abort signal native CLI. Уже выполненные записи и запущенные внешние эффекты не откатываются. Отмена/перезапуск с неопределённым исходом сохраняет это состояние; пользователь/агент должен проверить фактические файлы и сервисы, а не доверять автоматическому повтору.

## Полномочия и реальная среда

Профиль: `sandboxMode=danger-full-access`, `approvalPolicy=never`, network access enabled, стандартные CLI shell/file tools и live web search. Пользователь прямо отказался от `code.propose`→human confirm, закрытого списка диагностик и custom tool permission gates. Старые квоты патча 20 файлов/2 МиБ/UTF-8/существующие parent directories и фиксированный test broker не ограничивают native действия. Это не обещание наличия любой сторонней программы: агент пользуется реальным runtime и может сообщить об отсутствующем инструменте.

Codex видит настоящий RW bind project `/workspace/project`, Docker socket и сети codex/default/inspection-tests. Главный Dockerfile target `codex-agent` содержит Python 3.12/runtime/pytest, Node 24/npm, pinned SDK/CLI, Git, ripgrep, curl и Docker CLI 29. Python source проекта доступен через PYTHONPATH. Есть отдельная test БД `inspection-test-postgres` / `bervel_core_stage31_test` с `public.vector`; `docker/inspection/test-init.sql` создаёт extension при первом старте tmpfs контейнера. Ранее запущенный test контейнер уже инициализирован отдельно и проверен.

Общие пользовательские правила про VPN, OSP, Git основной ветки и пути материалов передаются как инструкции агенту. Они остаются обязательными, но native окружение не подменяется технической read-only песочницей. Через настоящий project/Docker CLI может управлять файлами, контейнерами и данными в рамках прямой задачи. Изменение source само по себе не вызывает post-patch deploy hook; при задаче установки сам CLI может использовать доступные команды. Автоматической публикации на каждый file_change нет.

Compose binds используют абсолютный host root из `BERVEL_ENGINEERING_HOST_PROJECT_ROOT`; Windows init helper передаёт `C:/...`, а native Linux Docker CLI получает `BERVEL_HOST_PROJECT_ROOT`. Это предотвращает ошибочную попытку daemon bind несуществующего `/workspace/project`. Provider/model берутся из существующего SettingsStore; внешние MOX auth/config/CA остаются readonly mounts, состояние codex_state сохраняется. Новая migration не требуется: схема остаётся 0018.

## Секреты, события и экспорт

Модельный ввод и tool context не проходят прикладной фильтр. Secret masking применяется только после CLI к отображаемым событиям/ответам и истории; короткие preview команд/прогресса не сокращают native контекст/final answer. Известные credential values скрываются в Node job output, далее используется существующий reader.redact. Одиночное большое поле не нарезается до маскирования. Это не гарантия распознавания неизвестных секретов и не фильтрация байтов экспортированного attachment. Агент обязан не печатать и не экспортировать credentials.

Frontend показывает `engine=codex-cli`, thread ID, native progress и реальные `command_execution`/`file_change`/web/tool события. Прежняя phase-planning модель скрыта, активных proposal grants нет. Legacy proposal cards остаются архивом. Markdown/GFM/сноски, таблицы, безопасные ссылки и авторизованные изображения используют существующий renderer; сырой HTML не исполняется в DOM приложения. Явные HTML-блоки и HTML-вложения используют отдельный изолированный просмотр, описанный выше.

CLI создаёт реальные документы/изображения обычными программами. Старый шаблон «SVG только из plain labels» и whitelist document.create не относятся к native созданию файлов. Helper `bervel-export <path>` загружает файл в ArtifactService и только после API success пишет canonical artifact ID/export record. Workflow удаляет повторы, проверяет UUID и actor/scope через metadata сервиса и строит file cards из фактических метаданных. Имя, URL и утверждение модели не являются доказательством attachment. Missing/foreign/invalid artifact не добавляется, пользователю видна честная ошибка. Даже failed/cancelled native job может вернуть ранее успешно экспортированное вложение.

## Установка и проверка

Новый выпуск требует coherent API/workers/reader/frontend и codex-agent image; Codex recreation теперь прямо разрешён пользователем. Основной PostgreSQL не пересоздаётся. Старый inspection-executor удаляется адресно после native health, без orphan cleanup/prune. Перед заменой — свежий backup всех текущих пользовательских строк/оригиналов, `.env` и codex_state, hashes внешних MOX файлов/настроек, restore check и нулевая очередь; старый backup до новых диалогов не заменяет свежий.

Native выпуск установлен. Freshest dump 8911 строк/24 объекта восстановлен в собственный disposable PostgreSQL; post-install сравнение сохранило все исходные строки/объекты и 6254 прежних файла codex_state. Внешние MOX bindings/contents, provider env и IDs обоих PostgreSQL сохранены. В шести API/worker/reader контейнерах совпали по 125 source/font hashes, в codex — 134 включая runner.mjs; actual CLI0.163.0 healthy. Старый executor удалён адресно. Точечный r2 заменил только codex/frontend: штатные CLI retry defaults и trusted artifact preview resolver. При zero-active настоящем restart сохранены все 11765 текущих state files (jobs/thread mapping/rollouts включены), а также свежие 8937 строк/26 объектов; все прочие container IDs неизменны. Это deployment evidence, а не утверждение, что все native live сценарии завершены. Фактические native executable/resume/restart/direct edit/Kontur/export/Stop/UI проверки и финальный installed state фиксируются root в quality report. Исходники/образы/защищённое состояние проверяются отдельно по SHA256 и container identity.
