# Временная ссылка BERVEL через Cloudflare

Корень: `C:\OSPanel\home\bervel.local`. Команды выполняются из него в PowerShell.

```powershell
# При первом запуске cloudflared скачивается автоматически.
.\.dev\scripts\cloudflare.ps1 -Action start

# Посмотреть текущую ссылку и процесс.
.\.dev\scripts\cloudflare.ps1 -Action status

# Закрыть доступ по ссылке, сохранив локально работающий BERVEL.
.\.dev\scripts\cloudflare.ps1 -Action stop
```

Сначала должны работать Docker Desktop и существующий сайт `http://127.0.0.1:5173`.
Помощник не собирает приложение, не применяет миграции и не пересоздаёт контейнеры.
Если Docker Desktop закрыт, открыть его и дождаться запуска прежних контейнеров.
Для нестандартного порта frontend передать `-Port <порт>`; обычный порт — `5173`.
Отдельная установка без публикации: `-Action install`.

`start` проверяет не только регистрацию соединения Cloudflare: публичная HTML-страница
должна совпасть с локальной, JavaScript приложения — полностью передаться с тем же SHA-256,
а чтение списка файлов через API — вернуть корректный JSON. Проверка только читает данные.
При провале помощник закрывает созданный туннель и не выдаёт ссылку как готовую.

Проверка 10 ноября 2026: в текущем сетевом окружении полная загрузка приложения через
Cloudflare не прошла. Подробности: [отчёт](../quality/cloudflare-sharing-2026-11-10.md).
До устранения сетевого блокера работоспособность интернет-ссылки не подтверждена.

Путь запроса: браузер → HTTPS Cloudflare → исходящее соединение cloudflared → локальный Nginx → API BERVEL.
Серверный ключ остаётся в существующем Nginx; в ссылку и браузер он не передаётся.
API, PostgreSQL и внутренние callbacks отдельно не публикуются. Существующие loopback-привязки портов сохраняются.
Помощник принимает только Nginx frontend, чтобы случайно не опубликовать исходники Vite.

Все обладатели ссылки получают доступ к общей рабочей области с существующими правами сайта:
это не отдельная учётная запись, не гостевой режим и не доступ только для чтения.
Приложение сейчас не требует персонального входа. Передавать ссылку только тем, кому разрешена работа с этими данными.

Используется [Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/),
без аккаунта и домена. Ссылка вида `https://….trycloudflare.com` действует, пока запущены cloudflared,
компьютер и приложение. После остановки и нового старта адрес меняется. Повторный `start` возвращает
существующую ссылку, если процесс ещё работает. Автозапуска туннеля после перезагрузки нет.
`status` сообщает состояние процесса, а доступность сайта проверяется открытием ссылки.

Cloudflare не гарантирует непрерывную доступность Quick Tunnel, ограничивает число одновременно
выполняемых запросов до 200 и не поддерживает Server-Sent Events (SSE). BERVEL получает статусы
через обычные HTTP-запросы, SSE в текущем приложении не используется. Ограничения Cloudflare
на HTTP-запросы, загрузки и время ответа сохраняются; передача больших файлов через туннель отдельно не проверена.

`cloudflared 2026.10.7` для Windows amd64 закреплён SHA-256 официального релиза:
`2493dbc168923bb3e59e5e7716f71deced92992eea9acd6e9d74f84ac7751343`.
Бинарный файл проверяется перед запуском. Он, состояние, пустой конфиг и журналы находятся
в исключённой из Git папке `.dev/local/cloudflare/`. Системная установка и служба Windows не создаются.
Глобальный конфиг Cloudflare не читается; используется отдельный пустой файл проекта.
Транспорт HTTP/2 использует TCP; настройки VPN, адаптеров, системного DNS, firewall и Open Server Panel не меняются.
Если системный DNS не возвращает служебные SRV-записи туннеля, помощник получает их через
официальный `https://cloudflare-dns.com/dns-query` и передаёт имена серверов самому cloudflared.
IP-адреса не закрепляются; актуальные данные запрашиваются при старте. Эта ветка использует
скрытый параметр `--edge` закреплённой версии cloudflared: его совместимость нужно повторно
проверить при обновлении бинарного файла. В журнале может остаться ошибка дополнительного
SRV/feature-запроса cloudflared; готовность определяется фактической регистрацией соединения.
`stop` проверяет путь и время старта процесса, чтобы не завершить чужой процесс при повторном использовании PID.

При ошибке смотреть `.dev/local/cloudflare/tunnel.stderr.log`. Если соединение не установлено
за 60 секунд или публичная проверка сайта не проходит, помощник завершает только созданный им процесс и сообщает об ошибке.
Если URL получен, но ещё не открывается, дождаться распространения DNS и повторить открытие;
при сетевом сбое VPN самостоятельно не отключать и не перенастраивать.
