# BERVEL в Docker: запуск и данные

Актуально на 22 октября 2026. Корень `C:/OSPanel/home/bervel.local`; команды выполняются из него. Для обычного запуска нужны Docker Desktop и PowerShell. Python, Node и PostgreSQL из Open Server Panel не используются.

```text
Браузер → frontend :5173 → api :8011 → PostgreSQL
                              ↓             ↑
                         оригиналы       worker Python
```

| Сервис | Обязанность | Доступ с Windows |
| --- | --- | --- |
| frontend | Сайт и Nginx; добавляет серверный ключ к публичному API | http://127.0.0.1:5173 |
| api | Загрузка, просмотр, прямой разбор и постановка фоновых заданий | http://127.0.0.1:8011/health/ready |
| postgres | Структурированные данные и очередь заданий | 127.0.0.1:5433 |
| migrate | Применяет структуру БД перед стартом; завершение с кодом 0 штатно | Нет |
| worker | Берёт сохранённые задания и вызывает Python-обработчик CSV | Нет |

n8n и Redis удалены из рабочего запуска по решению владельца. [Фоновый запуск и восстановление](python-background.md), [архитектурное решение](../adr/0005-python-background-processes.md).

## Ежедневная работа

```powershell
.\.dev\scripts\docker.ps1 -Action start
.\.dev\scripts\docker.ps1 -Action status
.\.dev\scripts\docker.ps1 -Action stop
.\.dev\scripts\docker.ps1 -Action dev
```

`start` собирает API и сайт, применяет миграции и запускает Python-исполнителя. `dev` включает наблюдение за исходниками API, исполнителя и сайта. Обычная остановка сохраняет постоянные данные. На новой машине сначала выполнить `-Action init`: создаётся исключённый из Git `.env`. При повторном `init` прежние секреты и права сохраняются; отсутствующий серверный веб-ключ выбирается из подходящей существующей привязки.

Сайт: http://127.0.0.1:5173; загруженные файлы: http://127.0.0.1:5173/#/files. Ключ не вводится в браузере и не хранится в нём. Все посетители работают с общей настроенной областью, без входа сотрудников. [Устройство доступа](frontend-server-access.md).

Внутри Docker `postgres` и `api` — имена сервисов. Браузер обращается к localhost, Nginx — к `api:8011`, API и worker — к `postgres:5432`. Порты опубликованы только на loopback; публикация в интернете требует отдельной настройки доступа, адреса и HTTPS.

## Данные и резервирование

| Volume | Содержимое |
| --- | --- |
| bervel_postgres_data | База приложения, тестов и сохранённая историческая БД прежнего движка |
| bervel_objects | Оригиналы загруженных файлов |
| bervel_test_objects | Отдельные тестовые оригиналы |

Данные не входят в Git и не заменяются копированием исходников. Именованные volumes сохраняются при пересоздании контейнеров.

```powershell
.\.dev\scripts\docker_backup.ps1
.\.dev\scripts\docker_backup_verify.ps1 -BackupPath 'абсолютный путь к копии внутри .dev/local/docker/backups'
```

Текущий backup сохраняет БД приложения, оригиналы и `.env`, на время останавливая сайт/API/worker. Проверка восстанавливает копию в отдельную временную БД и volume, читает оригиналы и результаты, затем убирает только созданные тестовые цели. Возврат сервисов через `compose up` пересоздаёт устаревший контейнер миграций после пересборки.

Перед удалением прежних сервисов создана полная копия `docker-20261022T091022Z`: обе БД, оригиналы, исторические volumes и ключи. Старый эксперимент целиком сохранён в `retired-experiment` внутри этой копии. Историческая БД и volumes не используются новым worker и оставлены для сохранности данных; текущий backup приложения не объявляется резервной копией этих архивных сервисов.

## Проверки и журналы

```powershell
.\.dev\scripts\docker.ps1 -Action tests
.\.dev\scripts\docker.ps1 -Action e2e
docker compose logs --tail 100 api worker postgres
```

Тесты используют отдельную БД и тестовые оригиналы. Сборка API, сайта и Linux-зависимостей выполняется в контейнерах. `.dev` содержит инструменты и тесты, но не требуется установленному приложению. Приложение не зависит от структуры каталогов Open Server. Перенос на отдельный промышленный сервер этой локальной проверкой не подтверждается.
