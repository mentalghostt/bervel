## Запуск и ручная проверка

Git Bash в Windows:

```bash
cd /c/OSPanel/home/bervel.local/frontend
npm run dev -- --host 127.0.0.1
```

Открыть адрес из терминала, обычно `http://127.0.0.1:5173`. Для самого выбора файла Python, PostgreSQL и Open Server не требуются. Остановка сервера — Ctrl+C в запустившем его терминале.

1. Перетащить один CSV в пунктирную область. Должны появиться его имя, размер и надпись «Файл выбран». Пример: `C:/OSPanel/home/bervel.local/.dev/fixtures/core-stage-3.1/requirements-v1.csv`.
2. Заменить файл кнопкой «Заменить файл» или перетаскиванием другого CSV. Отображается только новый файл.
3. Нажать крестик «Убрать выбранный файл». Карточка исчезает; тот же файл можно выбрать снова.
4. Перетащить файл с другим расширением, пустой CSV, CSV больше 5 МиБ или несколько файлов. Появляется понятная ошибка, прежний выбор сбрасывается.
5. При закрытии диалога выбора без выбора файла прежний файл сохраняется.
6. Проверить клавиатуру: Tab переводит фокус на «Выбрать CSV», Enter или пробел открывает диалог. После сброса файла фокус возвращается на кнопку выбора.
7. Проверить узкое окно браузера: блок требований располагается ниже выбора, длинные имена переносятся, горизонтальной прокрутки страницы нет.
8. Без ключа API кнопка «Загрузить в БД» остаётся отключённой и после выбора файла. Выбор, замена и перетаскивание сами по себе не вызывают запросов API. Отправка выполняется только по кнопке в рамках второго этапа.

## Что происходит при выборе

Браузер предоставляет объект `File`. React хранит ссылку на него в памяти открытой страницы и отображает имя и размер. Перезагрузка страницы сбрасывает выбор. При самом выборе содержимое не читается и не отправляется на сервер.

Встроенные проверки: ровно один файл, расширение `.csv` без учёта регистра, размер больше нуля и не больше `5 * 1024 * 1024` байт. Ровно 5 МиБ допустимы. Расширение и размер не доказывают корректность содержимого CSV.

UTF-8, порядок колонок `line,name,quantity,unit` и ограничение количества строк показаны как требования существующего серверного обработчика. Проверку содержимого и значений полей браузер не дублирует: серверная обработка вызывается по кнопке во втором этапе.

## Проверки разработчика

Из каталога `C:/OSPanel/home/bervel.local/frontend`:

```bash
npm run build
npm run lint
```

Браузерные проверки: `C:/OSPanel/home/bervel.local/.dev/tests/frontend-csv-selection.cjs`. Скрипт использует встроенный тестовый модуль Node.js, Playwright из окружения проверки и установленный Microsoft Edge в отдельном временном профиле. Для другого доступного канала Chromium можно задать `BERVEL_BROWSER_CHANNEL`. Новые пакеты в `frontend/package.json` не добавлены.

При запущенном Vite на порту 5173, из корня проекта в Git Bash, для текущего окружения Codex:

```bash
mkdir -p .dev/local/frontend/tmp
export TEMP="$(cygpath -m "$PWD/.dev/local/frontend/tmp")"
export TMP="$TEMP"
export NODE_PATH='C:/Users/Evan/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules'
node --test .dev/tests/frontend-csv-selection.cjs
```

`BERVEL_FRONTEND_URL` позволяет указать другой адрес запущенного Vite. Путь `NODE_PATH` относится только к локальному инструменту проверки, а не к конфигурации приложения или его сборки. На другой машине нужен доступный Playwright и соответствующий путь к нему.

Скриншоты сохраняются в `C:/OSPanel/home/bervel.local/.dev/local/frontend/screenshots/`. ## Граница поставки

Код страницы, стили и настройки сборки находятся вне `.dev`. Приложение не читает тесты, примеры и эту инструкцию. Наличие `.dev` не требуется для сборки и запуска интерфейса. Результат `npm run build` создаётся в `frontend/dist`; локальные инструменты проверки и скриншоты в поставку не входят.
