# Раздел «Проверка»

Адрес локальной установки: http://127.0.0.1:5173/#/inspection. Доступ общий, как в остальных разделах; отдельной учётной записи руководителя нет. Ограничены только инструменты ИИ «Проверки».

Примеры вопросов: «Прочитай src/bervel/app_setup.py и объясни подключение модулей», «Покажи таблицы и структуру artifacts», «Исследуй контейнер API и его логи», «Прочитай .dev/docs/architecture/28-inspection-chat.md». Для создания тикета прямо попросить создать обращение; результат появится в «Обращениях» и карточке чата. ИИ не редактирует существующие тикеты и не отправляет их наружу.

## Устройство

- Общие chat_sessions/chat_turns/chat_actions, неизменяемый mode=inspection, отдельные API /api/v0.1/inspection/sessions и browser storage. Старые диалоги имеют mode=assistant.
- Отдельный Python worker-inspection использует прежний механизм очереди. Он не задерживает worker-chat долгими исследованиями. API/workers/frontend — один согласованный выпуск.
- Private inspection-reader не публикует порт на хост. API и worker-inspection соединяются с ним с отдельным server-side токеном. Процесс модели не получает Docker socket или транспорт reader.
- Корни project/objects/codex/embeddings/postgres подключены ro. Возможность DAC_READ_SEARCH нужна только для чтения файлов тома PostgreSQL; все подключённые источники остаются ro. Docker socket :ro сам по себе не ограничивает API; запрет обеспечен закрытыми GET-операциями адаптера и отсутствием passthrough/exec.
- bervel_inspector имеет только CONNECT/USAGE/SELECT в БД BERVEL и READ ONLY по умолчанию; адаптер также устанавливает READ ONLY и принимает структурированные параметры, а не SQL. При ошибочной выдаче роли write/admin прав reader не запускается.
- ticket.create проходит публичный TicketService и прежние durable receipts. История, очередь, квитанции и временное декодирование документов — служебные данные; файлы и рабочие данные системы инструментами ИИ не меняются.

## Настройка и запуск

`docker.ps1 -Action init` создаёт BERVEL_INSPECTION_DB_PASSWORD и BERVEL_INSPECTION_TOKEN один раз, сохраняя прежние секреты. PostgreSQL init создаёт read-only роль для новой установки. В этой существующей установке роль/grants настроены отдельно после проверенного backup/restore; не запускать task-local install.ps1 повторно вслепую.

Штатный запуск остаётся `.dev/scripts/docker.ps1 -Action start -Mox` для существующего MOX или без `-Mox` для независимого API-провайдера. worker-inspection подключён к обычным start/worker; его dependency запускает inspection-reader. Изменения исходников reader/worker требуют совместимой пересборки API-образа. VPN, OSP и внешние auth/config MOX не меняются.

## Секреты и ограничения

Значения известных credentials, чувствительные JSON/ENV/YAML/XML поля, URL passwords, auth/cookie headers и private keys скрываются до страниц, модели и долговременных результатов. История и replay очищаются повторно текущим фильтром. Opaque credential-файлы скрываются консервативно. В source symlinks используются фактический путь и закреплённые directory handles.

Полнота чтения явно ограничивается конкретным источником: одна порция текста до32000символов, файл/ответ Docker до32МиБ, список/таблица постранично, логи по tail/диапазону времени. Неизвестные бинарные форматы дают metadata_only; PDF/OCR/Office сохраняют ограничения штатного декодера. Секрет, нигде не обозначенный и ещё не известный установке, невозможно гарантированно распознать в произвольном свободном тексте; это ограничение эвристического маскирования. Ответ обязан обозначать непрочитанный остаток.

Сервис недоступен → явная ошибка чтения. Нельзя автоматически исправлять окружение, открывать дополнительные источники или повторять неизвестное создание тикета. Спецификация: ../architecture/28-inspection-chat.md. Доказательства текущей установки: ../quality/inspection-chat-2026-10-29.md.
