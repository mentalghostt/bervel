Корень: `C:/OSPanel/home/bervel.local`. Раздел реализован отдельным модулем `presales` и установлен 10.11.2026 после явного разрешения пользователя. Доказательства — в `.dev/docs/quality/2026-11-10-presales-pipeline.md` и `.dev/local/presales-pipeline-2026-11-10/install/REPORT.md`.

## Путь менеджера

1. В общих настройках предприятия проверить официальный каталог, склад с `unit_cost`, единицы измерения и производственные ресурсы. Эти сведения общие для радара и пресейла.
2. Открыть настройки пресейла (`#/presales-settings`), сохранить видимые **50%** целевой маржи и **70%** маржи спецзаказа. При первом запуске сохранение обязательно: скрытой подстановки при анализе нет. Здесь же задаются контакты продавца и текст условий КП.
3. Открыть «Пресейл-конвейер» (`#/presales`), выбрать один или несколько уже загруженных файлов и подтвердить. Весь комплект создаёт одну заявку и первую редакцию истории.
4. После анализа проверить источники, таблицу сопоставления, полноту данных, метрики и внутреннее заключение ИИ. Для расходящихся списков открыть позиции каждого исходного списка и при необходимости выбрать основной.
5. Подтвердить предлагаемый аналог либо адаптацию/базу себестоимости спецзаказа. Можно уточнить клиента, срок, количество, единицы и характеристики. Сохранение правок создаёт новую редакцию; старая сохраняется.
6. Проверить автоматически созданный черновик КП и скачать PDF/DOCX. Неподтверждённые позиции перечисляются отдельно. Отправка клиенту, резерв склада и запуск производства выполняются вне этого сценария.

## Как данные проходят через систему

```text
Общие оригиналы → полный разбор страниц/таблиц → единый состав заявки
                                                    ↓
Общий снимок предприятия/склада → сопоставление → остатки/изготовление/цены
                                                    ↓
                               ИИ-заключение → черновик КП → PDF/DOCX
```

Каждая редакция фиксирует оригиналы, настройки пресейла и снимок предприятия. Worker читает только эти входы. Последующее изменение склада или настроек не переписывает готовую историю. «Повторный анализ» получает новый снимок и создаёт новую редакцию; «Продолжить» использует прежний снимок.

Собственные таблицы: `presales_settings_snapshots`, `presales_requests`, `presales_revisions`, `presales_lines`, `presales_jobs`. Файлы экспорта регистрируются через общее хранилище артефактов с владельцем `presales`; отдельного файлового сервиса нет. HTTP: `/api/v0.1/presales`; история, строки анализа и исходные списки выдаются страницами.

## Правила результата

| Статус | Смысл |
|---|---|
| Есть полностью | Подтверждённое исполнение полностью закрывается доступным складом |
| Частично + допроизводим | Требуется любое собственное изготовление, включая выпуск с нулевого остатка; неизвестные нормы требуют уточнения |
| Не производим | Для определённой позиции доказано отсутствие подходящего исполнения во всём подтверждённом каталоге |
| Спецзаказ | Есть близкое собственное исполнение для адаптации и рекомендация ИИ; для предложения нужны подтверждения менеджера |

Отсутствие сведений не доказывает «Не производим»: статус может быть не определён, а строка отмечается для проверки. Неполное распознавание и неизвестные единицы не становятся нулём или подтверждёнными 100%. Общий склад распределяется между строками без повторного расходования. Закупка у сторонних поставщиков не предлагается.

Совпадающие списки не суммируются. Выбирается наиболее подробный: сначала число уникальных строк, затем заполненность параметров. Равные по подробности конфликтующие списки требуют выбора менеджера. Предупреждение о различиях сохраняется для передачи менеджеру.

Цена = складская себестоимость / (1 − маржа). Это маржа от цены продажи. При себестоимости 100 ₽ обычная цена — 200 ₽; спецзаказ при 70% — 333,34 ₽. Производственные, транспортные и прочие затраты не добавляются. Конвертация валют и автоматическое начисление НДС отсутствуют. Разные SKU предлагаются отдельными строками, без усреднения себестоимости.

LLM оценивает выгодность условий спецзаказа и пишет заключение. Программный расчёт проверяет 70% по явно указанным клиентским ценам. Неизвестная клиентская цена остаётся предварительной оценкой. Менеджер отдельно подтверждает адаптацию и использование себестоимости близкого SKU.

Процент соответствия — подтверждённые подходящие позиции / все уникальные позиции. Покрытие склада — подтверждённо покрытые штуки / все требуемые штуки. При неполном знаменателе соответствующая общая метрика не вычисляется. Оценка ИИ — самостоятельное число 0–100; она не заменяет эти проценты.

## Остановка и восстановление

- «Остановить» запрещает новые действия после текущего безопасного шага. Уже выполненный внешний вызов сохраняется; мгновенная отмена выполняющегося запроса к провайдеру не обещается.
- «Продолжить» возобновляет ту же редакцию и использует сохранённые стадии/ответы. Неопределённый исход внешнего вызова требует явного действия пользователя; worker не повторяет такой вызов автоматически.
- Потерянный HTTP-ответ повторяется с прежним ключом команды. Перезагрузка и дублированная вкладка не должны создавать новую заявку.
- После некорректного ответа модели явное продолжение повторяет только неподтверждённый ответ. Успешно проверенные стадии сохраняются.
- Если регистрация файла успела завершиться до сбоя, восстановление находит сохранённую квитанцию и возвращает тот же артефакт, не создавая второй экспорт.

## Установка подготовленного выпуска

Точный состав образов, SHA и инструкции находятся в `.dev/local/presales-pipeline-2026-11-10/release/manifest.json` и `release/INSTALL.md`. Пакет накладывает только изменения пресейла на фактически установленный выпуск радара. Отложенная inspection-ветвь и незавершённые изменения чата исключены.

Перед применением повторно сверить текущие образы/конфигурацию/состояние заданий с manifest. Изменившийся параллельно выпуск требует обновления пакета. Резервная копия рабочей БД и репетиция восстановления выполняются helper `.dev/local/presales-pipeline-2026-11-10/backup_rehearsal.py`; он мигрирует только уникальную собственную тестовую БД и не изменяет рабочую схему.

Рабочая миграция адресная: **`0027b_radar_profiles` → `0029_presales_pipeline`**. Общий `upgrade heads` и сервис общей миграции не применяются: в исходниках присутствует независимая отложенная `0028_inspection_followups`.

После отдельного разрешения установки: сохранить актуальную резервную копию, выполнить адресную миграцию, заменить API/frontend подготовленными образами и добавить `worker-presales`. Действующий worker радара не требуется заменять. Сохраняются реальные env/порты/тома/runner, секреты остаются в приватной конфигурации внутри игнорируемого каталога задачи.

Откат приложения возвращает прежние API/frontend и останавливает только новый worker пресейла. Добавленные таблицы и новые записи сохраняются. Полный старый dump поверх более новых данных автоматически не восстанавливается.

После установки проверить доступность двух маршрутов, явное сохранение 50/70 и чтение общих настроек. Контрольную заявку запускать на известных тестовых файлах с пониманием, что это реальный вызов настроенной модели. Готовое КП — черновик для проверки менеджером.
