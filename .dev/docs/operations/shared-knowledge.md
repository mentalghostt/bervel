# Подготовка файлов для ИИ

Обновление28.10.2026: готовность и продолжение подготовки адресуют один ID файла: `GET /api/v0.1/artifacts/{id}/knowledge`, `POST /api/v0.1/artifacts/{id}/knowledge/resume` с `{}`. Состояние и счётчики относятся к этому файлу. [Модель, миграция и статус основной установки](../architecture/25-independent-files.md). Раздел о перезагрузке27.10 и прежнем логическом удалении ниже исторический; последующее полное удаление и0013 заменяют этот порядок для файлов.

Три отдельных workers установлены; [устройство и проверка](../architecture/22-independent-workers.md). Все поддерживаемые текущие файлы полностью проиндексированы.

Текущее окружение использует OpenAI `text-embedding-3-small` и существующие PostgreSQL/API и три workers. Полная архитектура: [общая база знаний](../architecture/21-shared-knowledge.md).

## Обычная работа

Загрузить файл на странице «Файлы» и открыть его. После сохранения оригинал сразу доступен для скачивания. Блок «Подготовка файла для ИИ» показывает отдельное состояние извлечения/индексации и число обработанных фрагментов. Готовность загрузки не означает готовность поиска.

`Готов для ИИ` означает полное покрытие извлечённого содержимого. `Частично` означает достигнутый предел извлечения; для полного профиля радара такой файл не подходит. `Формат не поддерживается` означает, что байты сохранены, но декодера нет. Изменение расширения не создаёт декодер.

При ошибке прочитать сообщение, устранить причину и нажать «Продолжить подготовку». Это разрешает обработать отсутствующие векторы; готовые порции не отправляются заново. Прерывание worker также требует явного продолжения. Автоматических повторов после таймаута или HTTP 429 нет.

## Серверные настройки

В `.env`:

```dotenv
BERVEL_EMBEDDING_PROVIDER=openai
BERVEL_EMBEDDING_API_KEY=<секретный API-ключ>
```

После изменения ключа пересоздать **API и все три workers**, чтобы процессы получили новое окружение:

```powershell
docker compose up -d --no-deps --wait api worker-knowledge worker-chat worker-radar
```

Не печатать `.env`, полный `docker inspect` или развёрнутый `docker compose config`: они содержат секреты. Провайдер генерации Codex/MOX настраивается отдельно и не требует изменения ради embedding-ключа.

Текущий бюджет индексации — 24000 токенов/минуту, чата — 8000. Порция содержит до 8000 токенов; интервал между запросами не менее 5 секунд. Ограничение основано на реально полученном заголовке 40000 TPM. Время большой загрузки зависит от **числа токенов**, а не только количества файлов/тендеров. На один миллион токенов нужно не менее ~42 минут при таком бюджете, плюс извлечение/сеть. Успешная проверка ключа не гарантирует наличие средств в будущем.

Локальная альтернатива `BERVEL_EMBEDDING_PROVIDER=local` использует закреплённую E5-small ONNX CPU и volume `bervel_embedding_models`. Первое скачивание требует сети; последующие загрузки используют сохранённые веса. Не удалять этот volume ради обычного перезапуска.

Смена модели меняет пространство векторов. Приложение останавливает несовместимый поиск с `KNOWLEDGE_REINDEX_REQUIRED`. Перед переключением нужно отдельно запланировать переиндексацию производного индекса с резервной копией, сохранив оригиналы и историю. Публичный интерфейс «сменить модель и перестроить всё» в эту задачу не добавлялся.

## История установки и резервной копии27.10.2026

Сведения ниже относятся к исходной установке знаний. Прежнее логическое удаление заменено полным удалением, а файловые редакции — моделью одного ID. Точная операция28.10, разрешённая очистка28 файлов и статус0013 описаны в [новом контракте](../architecture/25-independent-files.md).

PostgreSQL 17.9/pgvector 0.8.7 собирается из `docker/postgres/Dockerfile`. Расширение `vector` должно быть установлено администратором БД до миграции 0008. Существующие volumes не пересоздавать; `docker compose down -v` удаляет данные и не является способом обновления приложения.

Резервная копия перед перезагрузкой:
`C:/OSPanel/home/bervel.local/.dev/local/knowledge-2026-10-27/backup/`.

В ней полный custom-format dump, объектные данные,29 оригинальных редакций, манифест SHA256 и таблицы до изменений. `reload-map.json` рядом с папкой связывает 25 старых текущих файлов с новыми ID. `reload-verified.json` подтверждает точное совпадение байтов. Дополнительный тестовый browser-файл сохранён отдельно и не включён в 25 пользовательских файлов.

Удаление из активного каталога логическое. Исторические ссылки продолжают указывать на прежние редакции; физические байты, включая совпадающие с перезагруженными файлами, сохраняются. Это не процедура безвозвратного удаления конфиденциальных данных.

После перезагрузки по отдельному указанию пользователя удалён активный дубликат `2.xlsx`; оставлен файл «Тендеры период 4 кв. 2025_1 кв. 2026.xlsx». Совпадение байтов проверено, запись — `duplicate-removed.json`. Итоговый каталог содержит 24 файла; резервная копия и исторический журнал первоначальной перезагрузки сохраняют все 25.

Проверки задачи находятся в `.dev/local/knowledge-2026-10-27/`: `index_status.py` читает прогресс, `verify_preservation.py` сравнивает исходные бизнес-данные/историю с копией, `evaluate.py` сравнивает поиск после полного окончания индексации. Последний вызывает платный embedding API для вопросов. `deploy.py` и `reload_originals.py` — журнал конкретной миграции, повторять их для обычного запуска не нужно.
