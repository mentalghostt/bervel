# Тендерный радар: работа и источники

Файловый контракт28.10.2026 заменяет прежнюю адресацию редакций: [отдельные неизменяемые файлы и статус установки](../architecture/25-independent-files.md). Используются точные ID; загрузка/сохранение правки создают самостоятельный файл. Прежние примеры и результаты ниже сохраняют исторический контекст.

Инструкция ниже сохраняет прежний интерфейс. Для установленной версии с тремя файлами используйте [актуальную инструкцию](workspace-assistant-radar.md).

Состояние на 27.10.2026. [Актуальная архитектура](../architecture/23-radar-free-stock.md), [проверки отбора по остатку](../quality/radar-free-stock-2026-10-27.md). Ранние результаты ниже сохраняют свои исторические правила.

## Открыть результат

[Контрольный отчёт по 8 МОКОВЫМ закупкам](http://127.0.0.1:5173/#/radar?run=34321338-d05e-4bd5-bedf-eef6045fc715): 1 кандидат, 2 уточнения, 5 исключённых. Ведомость `bervel-free-stock-mock.csv` создана из выбранного пользователем профиля исключительно для тестирования; фактический склад не подтверждает. Допуск 10% по каждому SKU. Все 8 решений совпали с ожидаемыми; это не статистическая оценка точности на реальных закупках.

[Сохранённый отчёт по шести реальным закупкам](http://127.0.0.1:5173/#/radar?run=78ca94fa-6be4-445b-86e2-b06cf5c99804): четыре кандидата для первичного разбора, один на уточнение, один исключён. Источник проверен 22.10.2026 в 14:48:49 МСК. Это снимок, не постоянная лента. Обновление страницы читает отчёт из PostgreSQL без повторного вызова модели.

Обычный вход — вкладка «Тендерный радар» или `http://127.0.0.1:5173/#/radar`. Запуск уже настроенного локального Docker из корня проекта прежний:

```powershell
.dev/scripts/docker.ps1 -Action start -Mox
```

MOX этой установки использует существующие внешние файлы доступа только для чтения. Для заказчика предусмотрен API-провайдер на вкладке настроек; MOX не обязателен. [Доступ и запуск](codex-chat.md).

## Выполнить подбор

1. В «Загрузить список тендеров» выбрать XLSX/CSV и нажать «Импортировать закупки». Выбрать полученную партию в «Источник закупок».
2. В «Какие файлы учитывать» отметить от одного до десяти файлов. Можно загрузить профиль здесь или выбрать ранее загруженные материалы. Профиль продукции, ограничения и подтверждённый каталог полезнее случайного архива тендеров. Невыбранные файлы в модель не передаются.
3. Отдельно выбрать «Ведомость свободных остатков» и задать «Допустимая нехватка, %»: 0..100, до двух десятичных знаков; по умолчанию 0. Сейчас поддержан CSV с `sku,product,free_quantity,unit`; формат раскрывается под полями. Для моковой проверки выбрать `bervel-free-stock-mock.csv`, для профиля — исходный `bervel-product-profile.csv`. Это разные роли файлов. Без ведомости количество потребует уточнения.
4. При необходимости задать фокус: например, «болты М16–М24, отдельно отметить смешанные лоты». Нажать «Подобрать тендеры».
5. Просмотреть группы «В работу», «Уточнить», «Исключено», «Вне анализа»: этап решения, ссылки, цитаты, «нужно / свободно / нехватка», процент, строку ведомости и риски. «Скачать PDF» выдаёт сохранённый результат с тем же расчётом и пометкой мока.

Оригиналы неизменяемы. Запуск закрепляет точные ID/редакции RAG-файлов. Новый профиль не меняет старый отчёт: требуется новый запуск. «Сохранённые запуски» возвращает предыдущие результаты; прямая ссылка `/#/radar?run=<run_id>` сохраняет проверку доступа.

При неизвестном исходе отправки «Повторить запуск» использует ту же команду и входы, защищая от дубля. Явный HTTP-отказ снимает этот режим и позволяет исправить выбор. Прерванная после начала модельной обработки задача становится ошибкой без автоматического платного повтора; новый анализ запускает пользователь.

## Подготовленные данные

- `.dev/outputs/tender-radar/bervel-product-profile.csv` — 11 реальных групп крепежа по пакету заказчика: стандарты, размеры, прочность, покрытия, количества, места в оригиналах. `capability_confirmed=false`: заявка или сторонний отчёт не подтверждает возможности завода.
- `.dev/outputs/tender-radar/kontur-public-tenders-2026-10-22.csv` — шесть реальных карточек, включая непрофильный контроль. Ручной снимок с provenance, не ответ API и не официальный Excel-экспорт. Стадия/срок/цена проверены в браузере; состав из индексируемого официального текста требует проверки актуальной документации.
- Оригинал `.dev/data/private/customer-package-2026-10-06/2.xlsx` загружен отдельной исторической партией: 2290 карточек, итоговая строка пропущена. Даты не переносились на сегодня.

Партии и профиль уже загружены. В каталоге оставлены явно названный контроль `radar-control-other-profile.txt` и оригинал первого неудачного CSV-импорта с датами без пояса. Последний не стал партией и не использовался в итоговом отчёте; выбирайте партию с шестью закупками. Работающее приложение читает собственное хранилище, не зависит от `.dev`.

## Получить новые тендеры

По [официальным материалам](../research/2026-10-22-kontur-tenders.md) анонимный API и самостоятельная бесплатная выдача тестового ключа без заявки не подтверждены. «Попробовать бесплатно» на API-лендинге ведёт к заявке; обычная API-лицензия платная. API-клиент и автосинхронизация не включены.

Штатный путь: поиск/Избранное/шаблоны Контур → Excel → импорт здесь. [Описание экспорта](https://zakupki.kontur.ru/site/features/lk). По [прайсу с 15.09.2026](https://zakupki.kontur.ru/site/Files/userfiles/file/price-zakupki-skb.pdf), Excel есть в Стандарте и выше; трёхдневное Промо Эксперт после регистрации допускает экспорт с ограничением контактов/ИНН. Анонимная бесплатная выгрузка не подтверждена. Регистрации, заявки и покупки не выполнялись.

Поддерживается проверенный формат XLSX заказчика с «Номер», «Название», «Окончание приема заявок». Заголовок ищется в первых 50 строках, настоящая гиперссылка читается с номера. Ведущие нули текстовых ID и простой числовой zero-padding Excel сохраняются; потенциально потерявшие точность длинные числовые ID отклоняются. Даты Excel без пояса — МСК. При наличии «Все шаблоны» берётся только общий лист, без двойного импорта. Изменённая схема выгрузки требует проверки.

## Нормализованный CSV

Обязательные заголовки: `number,title,deadline_at,source_url`. Нужны непустые номер/название и полная HTTP(S)-ссылка. Пустой срок допускается как неизвестный, с переводом на проверку. Заполненные даты содержат время и пояс: `2026-10-26T10:00:00+03:00`.

Дополнительные поля: `buyer,price,currency,published_at,source_observed_at,stage,region,description,provenance,demo`. Для «В работу» нужны открытый приём (`stage=open` либо «Этап подачи заявок»), будущий срок и `source_observed_at` не старше 24 часов и не из будущего. Время импорта не заменяет наблюдение. Неизвестное оставляется пустым; выдуманные тестовые карточки помечаются `demo=true`.

UTF-8 с BOM/без, разделитель запятая/точка с запятой/табуляция; номер — текст. Цена — конечное неотрицательное число без валютного символа, до 30 значащих цифр, exponent от −12 до 18, порядок не больше 18. Файл до 5 МиБ, партия до 10000 записей; XLSX до 200 колонок, распакованный архив до 50 МиБ/1000 частей. Формулы не исполняются; формулы в ключевом блоке XLSX отклоняются. Одинаковые строки объединяются, конфликтующие сохраняются и требуют проверки.

## Смысл и границы результата

С26.10.2026 выбран один длительный запуск без сохранения промежуточных порций. Чат ждёт завершения радара. При сбое частичный отчёт не публикуется; повтор запуска — явное действие с повторной оценкой всех строк. Не меняйте модель во время выполнения. Обновление страницы не повторяет модельный запрос.

Для прямого сопоставления выбранные профили должны быть полностью читаемыми и вместе давать не более96КиБ извлечённого UTF-8 текста. Если это невозможно, запуск прекращается до модели. Радар не заменяет полный профиль найденными фрагментами. Обоснования совпадений содержат проверенные дословные цитаты; их наличие ещё не доказывает семантическую правильность решения модели — она проверяется отдельно на реальных закупках.

Новый отчёт 1.2: код проверяет сроки, затем осторожно название вместе с описанием; LLM оценивает смысл оставшихся и извлекает обязательные позиции с количеством/единицей и цитатой; код суммирует повторные SKU и сравнивает потребность с выбранным свободным остатком. Модель не получает складские количества как основание расчёта. Неизвестные характеристики/количества/единицы и неподтверждённые позиции смешанного лота дают «Уточнить». Превышение допуска хотя бы по одному SKU исключает закупку. Остатки между тендерами не резервируются.

Порции до 20 строк дополнительно ограничиваются входом 240 КиБ и оценкой ответа с позициями под предел шлюза 32 000 символов. Модель получает инструкцию уложиться в 30 000; соблюдение не гарантируется. Слишком большой тендер не обрезается: запуск завершится явной ошибкой. Все импортированные строки остаются в итоговом отчёте, включая исключённые до LLM; `model_analysed` может быть меньше `total`. Старые отчёты сохраняют прежние решения. Чат, индексация и радар обслуживаются независимыми worker.

«В работу» означает начать разбор менеджером. Совпадение группы не подтверждает размеры, эквивалентность стандартов, производство, склад или рентабельность. В отчёте `participation_ready=false`, техническая/производственная готовность и экономика неизвестны. Перед участием нужны актуальные документы, проверка технолога и коммерческий расчёт. Полный комплект приложений автоматически не скачивается.
