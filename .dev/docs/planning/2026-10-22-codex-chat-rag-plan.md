# Codex chat and CSV RAG implementation plan

**Цель:** отдельный контейнер Codex CLI, вкладка «Тест чата», долговременная история и ответы по реальному последнему загруженному CSV с указанием источника.

**Архитектура:** API проверяет область данных, сохраняет команды и историю в PostgreSQL; Python-worker получает реальный CSV, обновляет индекс его фрагментов и вызывает внутренний codex-runner. Node-сервис использует официальный Codex SDK и закреплённый CLI. Провайдер, модель и доступ задаются окружением развёртывания.

**Стек:** существующие Python/FastAPI/SQLAlchemy/PostgreSQL, React/TypeScript/Tailwind, Node 24, Codex SDK/CLI.

**Спецификация:** [Codex chat](../architecture/16-codex-chat.md).

## Контракты

### Runner

`POST /v1/generate`: JSON `{request_id: string, prompt: string}`; результат `{answer: string, model: string}`. Внешний текст не запускается оболочкой. Ограничение тела 256 КиБ; timeout модельного запроса 180 секунд. `GET /health/live` подтверждает процесс, `GET /health/ready` сообщает о наличии модельной конфигурации без секрета. Для тестового чата отключены shell, web search, MCP, apps и установка плагинов. API и worker обращаются к сервису по внутреннему адресу, без Docker socket.

### Browser/API

`POST /api/v0.1/chat/sessions` с `{command_key}` возвращает сессию `{session_id, created_at, turns: []}`.

`GET /api/v0.1/chat/sessions/{session_id}` возвращает ту же форму с `turns`.

`POST /api/v0.1/chat/sessions/{session_id}/messages` с `{command_key, content}` возвращает HTTP 202 и turn `{turn_id, question, answer, state, created_at, sources, error}`.

Состояния turn: `queued`, `running`, `completed`, `failed`. Источник: `{artifact_id, revision, filename, created_at, row_start, row_end, total_rows, excerpt, truncated}`. `error` — безопасное сообщение или null. Чтение требует chat:read и прав чтения документов; отправка — chat:write. Полный web-ключ текущего сайта получает новые права без смены самого ключа или чужих ограниченных ключей.

## Проверки повышенного внимания

- Новый CSV выбирается вместо старого; чужая область и не-CSV не влияют на результат.
- Новая редакция одного оригинала меняет источник; непрошедшее извлечение не приводит к подстановке старого dataset.
- Большой CSV не объявляется прочитанным целиком при ограниченном контексте.
- Повтор команды не вызывает вторую генерацию; конкурентные сообщения в одном диалоге не перемешиваются; неизвестный исход после аварии не повторяется автоматически.
- Секреты, инструкции внутри CSV и текст модели не получают серверных полномочий; отсутствие модели не ломает прежний CSV-интерфейс.
