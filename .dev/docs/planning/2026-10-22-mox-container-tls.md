# Исправление TLS MOX в контейнере

Пользователь явно разрешил исправить контейнер и проверить настоящий чат на разных CSV. auth.json и настройки MOX менять запрещено; при выявленной проблеме в них остановиться с доказательствами. Это продолжение незавершённой автономной задачи чата.

Диагностика: peer сертификат SHA256 5635D0726498F455CF55EF0B8E411457CFEFD7092218C0335CF83356D5339110 совпал с сертификатом MOX в доверенных Windows Root. Срок до 2036-09-15. SAN localhost/127.0.0.1/::1, не host.docker.internal. Причины: CA отсутствует в контейнере, прежняя замена hostname ломает проверку имени, CLI child environment не получает отдельный CA bundle.

1. Подключить только публичный сертификат из существующего доверенного Windows Root в optional compose.mox.yaml, передать NODE_EXTRA_CA_CERTS Node и CODEX_CA_CERTIFICATE CLI. Никаких глобальных изменений Windows/настроек MOX, private key и отключения проверки TLS. Публичный локальный PEM — docker/mox/ca.pem (ignored); helper -Mox экспортирует только сертификат.
2. Сохранить исходный localhost URL. Только в optional MOX развёртывании открыть прозрачный TCP bridge внутри codex: loopback:8000 → host.docker.internal:8000. TLS проходит сквозь bridge до MOX, имя и цепочка проверяются клиентом. Без нового сервиса/пакета, без публичного порта, plaintext proxy и подмены сертификата.
3. RED/GREEN: сохранение hostname и TCP forwarding/error cleanup. Затем TLS-проверка из контейнера с полной валидацией и реальный /settings/model/test. При auth/config ошибке остановиться; секреты не печатать.
4. Если реальная модель отвечает, браузером/через штатный API загрузить несколько уникальных CSV, спросить о последнем в одном диалоге, проверить фактический текст ответа и source artifact/revision. Проверить после reload, смену источника, сохранность прежних данных и внешних auth/config hashes. Результаты/скриншоты в .dev/local/codex-chat/tls-live.
