# Настройки провайдера Codex

Продолжение незавершённого автономного чата/RAG. Пользователь выбрал два режима: API-ключ и MOX Access; MOX по умолчанию, реальная проверка MOX обязательна. Существующие запреты login/logout, изменения auth.json и исправления TLS сохраняются.

1. Настройки runner: отдельный файл с правами 0600 в существующем именованном codex_state volume; ключ только на запись, без возвращения в GET и логирования. Два профиля сохраняются при переключении. MOX читает смонтированные внешние auth/config только для чтения; не копирует и не обновляет токены. Тесты: сохранение, перезапуск, смена профиля, отсутствие утечек, валидация.
2. Защищённые API GET/PUT /api/v0.1/settings/model и POST /test. Права settings:read/write только у выбранного полного web binding; прежние секреты не меняются. API обращается к runner через закрытую Docker-сеть.
3. Вкладка Настройки: два варианта шлюза, модель, API URL и поле API-ключа только для API, сохранить и проверить. Ключ не сохраняется в browser storage. Проверка использует сохранённый профиль, при ошибке нет автоматического повтора.
4. Сборка, серверные и браузерные проверки, развёртывание на текущем локальном адресе. Перед запросом модели MOX — HTTPS-проверка без секрета. При TLS/auth ошибке прекратить живые попытки и явно показать ошибку. Тестовый API не выдавать за настоящую модель. Существующие файлы и volumes сохранить; Git только чтение.

Новые файлы: codex-runner/settings.mjs, src/bervel/provider_api.py, frontend/src/ProviderSettings.tsx, .dev/tests/provider-settings.test.mjs и проверки API/UI. Интеграция: runner/server.mjs, compose, api/config, helper разрешений, навигация. Изменений БД для настроек не требуется.
