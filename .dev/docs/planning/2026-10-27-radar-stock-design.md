Пользователь подтвердил сценарий, указал учитывать описание и выбрал только свободный остаток. Отдельный запрос реализации введён словом «АВТОНОМНО» после уточнения; выполняются все этапы до установки и проверки. Корень C:/OSPanel/home/bervel.local, Personal, ветка core. Исходники редактировать на месте, Git только читать. VPN/OSP/внешние MOX-файлы не менять.

## Входы и данные

- Полная импортированная партия тендеров из общих оригиналов; никакого сокращения партии через RAG top-k.
- Полный выбранный профиль из общего DocumentMemory (прежние гарантии точной редакции/целостности/полноты).
- Отдельный явно выбранный CSV свободных остатков, закреплённый редакцией. Канонический формат: sku,product,free_quantity,unit; необязательные standard,thread,length_mm,strength,coating,as_of,data_kind,notes. Уникальный SKU, неотрицательное точное число, пустое количество означает неизвестность. CSV-декодер общий; обрезанный/дублирующийся/повреждённый ввод отвергать.
- Пользователь выбрал bervel-product-profile.csv как мок. Исходное source_request_quantity сохраняет смысл. Создать отдельный bervel-free-stock-mock.csv, перенести эти значения в free_quantity только как явно помеченные моковые данные (data_kind=mock, пояснение каждой строки). Это обычный формат остатков, без исключения в коде по имени файла. Загрузить штатным API; исходный профиль не менять.
- max_shortage_percent: 0..100 с точностью до сотых; по умолчанию0. Отсутствующий источник остатков допускает первичный смысловой разбор, но не положительный вывод по количеству.

## Последовательность

1. Код исключает закрытые/отменённые закупки и истёкшие дедлайны до LLM. Неизвестные сроки/свежесть остаются основаниями проверки, а не доказанным отсутствием товара. Перед публикацией перепроверить срок.
2. Осторожный лексический фильтр учитывает название И полное описание. Профильные слова/общие обозначения метизов/неопределённость пропускаются. Жёстко отсеивать только явно непрофильные категории для распознанного крепёжного профиля; при неизвестном профиле не гадать. Смешанные лоты с явным профильным изделием пропускать. Хоккейная шайба доходит до LLM.
3. Модель получает только кандидатов, полный профиль и каталог идентификации складских SKU БЕЗ доступных количеств. Результат каждой закупки: прежняя смысловая оценка/цитаты + позиции (sku,exact_match,quantity,unit,quote) и positions_complete. Количество только из самого тендера с буквальным подтверждением числа/единицы; source_request_quantity из профиля не переносить. Неизвестный SKU/количество — null; никакого вывода по производственным мощностям.
4. Код проверяет известный SKU, цитаты, количество/единицу и подтверждённые в цитате характеристики. Все требования одного SKU в одной закупке суммируются. Неиспользованные компоненты комплекта/кг/шт не конвертируются без явного правила. Процент нехватки=max(0,required-free)/required*100; сравнение Decimal без округления перед решением. Достаточно известного превышения допуска для исключения; неполный состав/неизвестная позиция/несопоставимые данные требуют проверки. Избыток другого SKU не компенсирует нехватку.

Для смешанных лотов неподтверждённые обязательные позиции удерживают общий результат в проверке. Отбор каждой закупки независим: это не резервирование остатков под одновременное выполнение всех выбранных тендеров.

## Ответственность и хранение

Сценарий/арифметика/фильтры — modules/tender_radar; CSV-адаптер снаружи правил, StockImporter-порт определяет потребитель. Общую базу и другие модули не обогащать тендерными правилами. Брокер/новые контейнеры/векторные модели не нужны.

Миграция0009 добавляет nullableJSONB selection в radar_runs: max_shortage_percent и stock_source snapshot. У старых запусков при чтении безопасные defaults; старые отчёты1.0/1.1 читаются. Новые отчёты1.2 включают этап решения, проверку количества по SKU, допуск, источник/тип остатков, воронку. Результат всегда содержит каждый импортированный тендер и причину решения.

Фильтр и редакции входят в fingerprint команды; нормализовать проценты. Прежний fingerprint сохраняется для пустых новых опций, чтобы не повторить старую команду с неизвестным исходом. Задания по-прежнему один длинный запуск без промежуточного результата/автоповторов; workers независимы.
