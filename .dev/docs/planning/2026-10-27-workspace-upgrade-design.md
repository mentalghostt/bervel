## Решения пользователя

1. Три одиночных выбора уже загруженных готовых оригиналов: закупки, данные по складу, экономика/производительность. Склад является номенклатурой интересов и остатками. Допуск нехватки находится рядом со складом; загрузки файлов в радаре нет.
2. Фильтры: цена от/до (RUB), минимальный запас дней до закрытия подачи заявок, текстовый фокус, допустимая нехватка0..100%, минимальная маржа0..100%. Цена/сроки отсеиваются кодом до LLM и экономики. Порог маржи редактируется, начальное значение15%; ограничения цены по умолчанию не заданы, запас дней0.
3. Цепочка: готовность/точные редакции выбранных файлов → все строки закупок → сроки/цена/осторожный отсев названий → LLM смысл/точные позиции/цитаты → Decimal количество по SKU → Decimal экономика/мощности.
4. Выручка = цены продажи из файла экономики × потребность. Сравниваем полный итог с бюджетом закупки, НМЦ не выдаём за нашу выручку. Учитываем себестоимость, фиксированные расходы, упаковку/логистику и сроки/мощности по явно заданным данным. Валюты без курса не смешиваем.
5. Нехватка сверх допуска — вне анализа; любая положительная нехватка внутри допуска — требует внимания, даже при возможном производстве. Каждый тендер оценивается независимо, общий резерв между заказами не создаётся.
6. «Можно участвовать» только при подтверждённых по входам обязательных характеристиках/количествах, достаточном складе, известных сроках/расходах/мощностях, бюджете и марже не ниже фильтра. Неизвестные существенные сведения — «Требует внимания». Остальные и бывшие excluded/not_analysed — «Вне анализа». Моковые оценки явно демонстрационные, фактическая прибыль не гарантируется.
7. Каждая содержательная строка входа учитывается. Повторы одной закупки объединяются только с сохранением исходных строк/происхождения; конфликтующие версии не подменяются молча. Пропуски/итоговые строки/дубли отражены счётчиками, без скрытых caps. Ошибки отдельных LLM-порций явны, не теряют весь уже выполненный проход и не выдаются за проверенное соответствие.
8. Нет количества/характеристик/срока поставки — требует внимания; догрузки тендерных карточек из интернета нет. Срок подачи заявки не является сроком поставки.
9. Основной реальный запуск на текущей дате плюс явно исторический контроль20.01.2026. Системную/рабочую дату не менять; исторический контроль не использует публикации после даты контроля и не является статистикой точности.
10. Универсальный ассистент выполняет все явно запрошенные действия приложения без второго подтверждения, наследуя actor/scope/permissions. Неоднозначность уточняет. Последние данные — последний готовый файл каждой назначенной роли, не просто последний файл любого вида.
11. Голос: MediaRecorder → серверный xAI REST grok-voice-transcribe-2.0 → редактируемый текст → отправка человеком. Ключ вводится через новое поле Настроек; секреты не возвращаются в браузер/модель/логи/историю.

## Архитектурные границы

- Существующее ядро оригиналов/индексации/прав сохраняется. Нужна предметная метка `usage_role`: general/procurement/stock/economics на оригинале. Она меняется отдельно от байтов; старые материалы general, подходящие существующие файлы будут назначены осознанно после проверки.
- В список файлов входят role и состояние подготовки точной редакции, готовые/общие числа фрагментов, безопасная ошибка. UI показывает «Обработка»/«Готов к ИИ анализу» у имени; failed/partial/unsupported имеют короткую явную диагностику, готовность не подделывается.
- `ArtifactService.prepared_metadata(actor,ref)` проверяет доступ, наличие, не удалённость и полную готовность выбранной редакции; возвращает метаданные с usage_role/processing_state. `set_usage_role(actor,id,role)` требует artifact:write. Чужие роли/секреты не раскрываются. Предыдущее полное удаление и старый logical archive сохраняются.
- Радар остаётся отдельным модулем. Новый `RadarService.analyse(actor,procurement_ref,stock_ref,economics_ref,filters,command_key)` импортирует выбранную закупку и ставит durable run. Новый HTTP POST `/api/v0.1/radar/analyse` с тремя refs и filters; прежние endpoints/отчёты сохраняют совместимость.
- Filters DTO: `min_price`, `max_price` nullable Decimal strings; `min_days_remaining` integer0..3650; `focus` string<=1000; `max_shortage_percent` Decimal0..100; `min_margin_percent` Decimal0..100. Снимок selection хранит все refs/filters, включает их в idempotency fingerprint.
- Экономический адаптер и правила живут в tender_radar. Десятичные величины не переводятся в float. Отчёт1.3 добавляет экономику/производительность и причины неизвестности; прежние1.0–1.2 читаются. Старый первичный кандидат не превращается в экономически подтверждённый тендер из-за смены подписи.
- Модель получает тексты/структуру/источники, а не числовые embedding-массивы. Индекс подготовлен для всех выбранных файлов. Для закупок используется полный структурированный оригинал, для склада/экономики — полный выбранный документ, без top-k, скрывающего обязательные позиции.
- Ассистент имеет прикладной диспетчер разрешённых операций к публичным сервисам через app_setup; SQL/SDK/рендеринг находятся во внешних адаптерах. Никаких импортов конкретных бизнес-модулей в core и обходов их правил.
- Модель выдаёт типизированное намерение/план, сервер валидирует и выполняет действия; сохраняются action receipt, результат и ошибка. Actor/scope/права не задаются моделью. Повтор/перезапуск не повторяет уже выполненную команду. Инструкции документов/веба не предоставляют права на действия.
- Долгий radar-run не удерживает один запрос модели. В сообщении сохраняется типизированная карточка radar_run, UI опрашивает сохранённый запуск и показывает PDF и deep link после завершения. Прямые API URL не подменяют защищённое fetch+blob скачивание.
- Генерация документов/схем сохраняет обычные оригиналы и возвращает карточки результата с разрешённым скачиванием/preview. PDF и редактируемый документ, SVG-схема; без исполнения произвольного кода модели. Веб-поиск — отдельная явно запрошенная возможность, с источниками и проверенной работой провайдера.
- Tickets — отдельный модуль, созданные пользователем/ассистентом карточки с заголовком, проблемой, ожидаемым/фактическим поведением, шагами, контекстом/диагностикой без секретов, ссылками. Список/деталь/редактирование, статус created; sent предусмотрен контрактом, действия отправки нет.
- Голосовые секреты хранятся сервером в существующем именованном credential volume с ограниченными правами, независимо от MOX auth. Нет смены чат-провайдера ради STT. API передаёт короткую запись через backend; запись/ключ не попадают в модельную историю.

## Интерфейс

Референс https://bervel-concept.vercel.app/bervel: графит, мята, крупная типографика, ясное разделение блоков. Общая оболочка с меню/высотой рабочего пространства; на desktop независимые прокручиваемые колонки. Радар: три равные по высоте карточки, фильтры и отдельная кнопка запуска, результаты и сохранённые запуски в соседних областях. На мобильном доступный последовательный layout без горизонтального overflow. «Тест чата» переименован в «Универсальный ассистент», добавлен раздел обращений. Копирайтинг через humanizer: короткие надписи, только необходимые подсказки, доступные labels/состояния/ошибки.
