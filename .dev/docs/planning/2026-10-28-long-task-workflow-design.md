# Длинные задания ассистента: согласованная схема

Пользователь поручил реализовать предложенную цепочку research → synthesizing → generating → verifying → completed, с partial/blocked при неполном результате или блокировке. Требование tests first сохраняется. Корень C:/OSPanel/home/bervel.local, Personal/core, Git только чтение. Внешние ключи, VPN и OSP не менять. Продолжение согласованной задачи ассистента; отдельные клоны/worktree не нужны.

## Данные и публичный контракт

У chat_turns добавить nullable JSONB `workflow`: старые строки остаются без изменения (NULL). Новые запросы получают `initial_workflow()`. JSON хранит фазу, времена, историю фаз, бюджеты, цель, накопленные доказательства и черновик. API публикует только public_workflow: phase, updated_at, reason, research_rounds, max_research_rounds, web_searches, max_web_searches, elapsed_seconds, max_research_seconds, history[{phase,at,reason}]. Внутренние goal/evidence/draft не выдавать дополнительными полями API.

Фазы: research, synthesizing, generating, verifying, completed, partial, blocked. Существующий state queued/running означает очередь/исполнение; терминальные state расширяются completed/partial/blocked/failed. completed — только подтверждённый результат, partial — сохранённый полезный результат с ограничением, blocked — продолжение требует отсутствующих данных/доступа либо исход эффекта неизвестен. failed — непредвиденная программная ошибка. Для обычного ответа без файла генерация файла не нужна.

Контракты чистого модуля modules/chat/workflow.py (root): initial_workflow(now=None)->dict; public_workflow(value)->dict|None; validate_transition(previous:dict|None,following:dict)->None. Внутренний `version` начинается с 0; каждая checkpoint увеличивает version на 1. Переходы монотонны по фазам; research→generating запрещён для документного пути, generating→research запрещён. Допустимы пропуски generating для ответа и synthesizing для простой операции. Любая нетерминальная фаза может перейти в blocked/partial; terminal phase не меняется.

PostgresChatRepository.checkpoint(turn_id,workflow)->None обновляет только running строку и ожидаемую предыдущую version, валидирует переход. finish(...,outcome=None,workflow=None) поддерживает terminal state; обычные вызовы без новых аргументов сохраняют прежний контракт. Цель/факты не входят в fingerprint команд. API DTO workflow nullable, state расширен; TypeScript принимает legacy ответы без workflow. Прогресс доступен через прежний polling, новый маршрут не требуется.

## Исполнение

План модели дополняется типизированной целью (ответ/файл/операция, форматы, необходимость исследования). Сервер контролирует допустимые операции каждой фазы. Исследование ограничено 4 раундами, 2 web.search и 240 секундами; лимит проверяется перед каждым внешним вызовом, оставшееся время передаётся CodexClient/runner. Отдельный резерв synthesizing — до 180 сек, generating — до 120 сек, локальная verifying — без нового вызова модели. После исследования новые платные поиски запрещены. Известные/неизвестные эффекты по-прежнему не переигрываются.

Доказательства сохраняются в компактной записной книжке с фиксированным бюджетом до 96КиБ (64КиБ файлы, 32КиБ web), точными ссылками/локаторами/покрытием/mock. Добавление действий не уменьшает уже сохранённые факты. Большие первичные ответы остаются в квитанциях, неполное покрытие явно указано. Записная книжка передаётся модели отдельно от сжимающейся истории ACTION_RESULTS. Инструкции из источников остаются недоверенными.

При достаточных данных или лимите research сервер переходит в synthesizing и требует текст документа из уже имеющихся источников. При исчерпанном исследовании результат отмечается partial, пробелы не выдумываются. Без содержательных данных для исследовательского отчёта — blocked; пользовательский текст для простого документа не требует внешних источников. Затем generating сохраняет файл через прежние авторизацию/renderer/квитанции. verifying читает оригинал и проверяет доступность, формат и содержимое без повторного планирования. Только проверенный файл даёт completed/partial. Ошибка модели не теряет ранее сохранённый файл. Защита FORBIDDEN/unknown сохраняется.

## Интерфейс и приёмка

Показывать русскую фазу, прошедшие этапы и причину partial/blocked. Не выдавать фиктивный процент. Текущий phase приходит с сервера; UI не переводит его самостоятельно. Списки web источников свернуть/объединить по URL с раскрытием полного сохранённого списка. Исследование и генерация различимы после reload без повторного POST.

Главная регрессия: длительный успешный поиск с множеством источников и повторными чтениями обязан перейти к созданию и проверке PDF либо честному blocked; исчерпание research не даёт ложного completed. Проверить миграцию на восстановленной БД, старые чаты/файлы/квитанции, fresh schema, атомарность checkpoint, scope, reload, таймаут и неизвестный эффект. Реальный исходный вопрос тестируется без автоматического повтора прежних команд.
