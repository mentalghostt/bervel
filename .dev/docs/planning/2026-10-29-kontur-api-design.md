## Сценарий и границы

В радаре переключатель «Файл выгрузки» / «Контур.Закупки API». Склад и экономика — прежние выбранные готовые CSV. В API-режиме вместо файла закупок: ключевые слова через запятую, даты публикации (МСК), лимит1–100 (по умолчанию20), стадия подачи/все. Автоподгрузка выполняется при запуске, отдельного расписания нет.

HTTP-команда быстро проверяет входы и ставит задание в прежнюю очередь; внешний поиск выполняет worker-radar. Для API-run до получения данных batch_id=NULL — одна additive migration0016, старые строки не переписываются. После успешной загрузки worker сохраняет неизменяемый JSON-снимок ответов в прежнее объектное хранилище и нормализованный batch, атомарно фиксирует ссылки запуска. Это свидетельство источника, без промежуточного XLSX/CSV и без ручной загрузки пользователем. Снимок привязан к actor/scope и содержит исходные ответы без ключа/заголовков авторизации.

Адаптер Kontur на внешней границе использует стандартный HTTPS-клиент, один запрос за раз, max response10МиБ, общий snapshot16МиБ, timeout25s, без redirect и отключения TLS. Ошибки401/403/404/429/сети/схемы различаются. Ретраев модели/скрытого переключения на выгрузку нет. Сетевой отказ не считается пустой успешной выдачей. Нет массовой загрузки по умолчанию.

Сначала поиск страниц до выбранного лимита; затем полная карточка каждого выбранногоID. Ошибка полной карточки прекращает получение, а не выдаёт частичный набор за полный. Полученный TotalCount, число загруженных, период, запрос, достигнутый лимит и момент наблюдения сохраняются/показываются. Лимит — явный выбранный объём источника, а не обещание проанализировать все найденные закупки.

Нормализация сохраняет ID/номер/название/НМЦ/валюту/сроки/отмену/планирование и реальный состав с характеристиками. Цифры читаются Decimal, отсутствующее/скрытое остаётся unknown. В description передаётся доказуемый текст позиций со структурными номерами; исключается двойной счёт сводных и заказчиковых позиций. Исходный JSON доступен для аудита. Спорная/неполная структура не считается подтверждённым полным составом. Тестовые/закрашенные данные помечаются, а не выдаются за фактическую готовность.

После получения данных используется прежний pipeline1.4: фильтры → извлечение → hybrid lookup → сопоставление → прежние stock/economics. filter_rows/preselect/stock_check/economics_check не править. Сохранённые file-runs, их PDF/ссылки и текущий выбор восстанавливаются. Новые поля API source в отчёте additive. Ассистентский запуск по файлам остаётся прежним.
