## Дизайн

Уточнение пользователя: целиться в прямо запрошенные файлы/участки. Нет обязательного system.list корня, перечитывания всего проекта или автоматической загрузки всей истории. Дополнительные зависимости исследуются по необходимости для вопроса; в контексте приоритет у текущего запроса и релевантных подтверждённых источников. Большие прежние результаты доступны по локаторам/страницам.

Существующие ChatService, PostgreSQL-очередь, история и разделение mode сохраняются. Инспектор получает доступ к прошлой истории своего session и данным прошлых подтверждённых операций, без жёсткого окна «последние восемь». Ограниченный модельный контекст явно сообщает покрытие и позволяет прочитать ранние страницы. История не авторизует новую запись.

Публичный workflow допускает nullable max_research_rounds/max_research_seconds для inspection. Другие режимы сохраняют свои бюджеты. Остановка — серверный запрос с принадлежностью session/turn; проверка между вызовами, отсутствие новых действий после остановки. Завершённые эффекты/неизвестные исходы не повторяются.

Новые инструменты: conversation.read; diagnostic.run; api.read; test.run; code.propose; document.create. Никакого произвольного shell, SQL, HTTP URL, Docker passthrough. Тесты запускаются только как именованные режимы в изолированном контейнере с project RO, отдельным scratch и тестовой БД; без production credentials/socket. Патчи применяет отдельный приватный executor с узким контрактом; обычный reader сохраняет ro mounts и SELECT-роль.

code.propose создаёт проверяемое предложение: title, explanation, changes[{path,content|null}]. Сервер фиксирует исходные хеши и fingerprint, возвращает diff. Кнопка подтверждения вызывает отдельный HTTP endpoint; текущие хеши обязаны совпасть. Запрещены .git, реальные .env/credentials, пути вне проекта, симлинки/спецфайлы, исходники с замаскированными секретами. Запись фиксируется квитанцией, при неопределённом исходе автоматического повтора нет. Диагностика Git выполняется только для чтения. Git staging/commit/branch/push недоступны инспектору.

Файлы ответов создаются через существующие ArtifactService и SafeDocumentRenderer; генератор не исполняет модельный HTML/код. SVG из фиксированного безопасного генератора показывает схему; frontend загружает разрешённые изображения через штатный marker header и blob. Форматы и ограничения явно представлены пользователю.
