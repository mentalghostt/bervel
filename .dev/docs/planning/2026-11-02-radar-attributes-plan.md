# Radar Attributes Implementation Plan

> **For agentic workers:** implement assigned task with TDD and report evidence; user authorized autonomous execution with subagents. No Git mutations in core.

**Goal:** Рабочий радар с едиными атрибутами готовности/выгоды, сортировкой и диапазонными фильтрами.

**Architecture:** Расширить существующий адаптер источника и склад, вычислять показатели в домене радара, отображать готовые результаты в UI/PDF. Сохранить исходные данные и исторические отчёты.

**Tech Stack:** Python/Decimal, существующие FastAPI/SQLAlchemy, React/TypeScript, ReportLab. Новых зависимостей не планируется.

**Spec:** .dev/docs/planning/2026-11-02-radar-attributes-design.md

## Global Constraints

- Корень C:/OSPanel/home/bervel.local, Personal, core. Git только чтение.
- Все материалы в этом корне; VPN/OSP не менять. Не запускать старые release helpers вслепую.
- Не терять существующие dirty изменения; каждый исполнитель редактирует только свою зону.
- Контракты полей и семантика процентов — как в Spec. Денежные/количественные расчёты Decimal.
- Новые зависимости и миграции не нужны без доказанной необходимости.

## Review Focus

- Частичные и повторяющиеся Objects не заменять заголовком и не удваивать.
- Требования из тендера не объявлять реальными свойствами склада; МОК сохраняет маркировку.
- Не тратить один остаток дважды, не складывать кг и штуки без преобразования.
- Неизвестная себестоимость одной позиции не превращается в выгодную полную закупку.
- Старый отчёт/ошибка анализа не получают фиктивных процентов, UI не скрывает всё при начальных диапазонах.
