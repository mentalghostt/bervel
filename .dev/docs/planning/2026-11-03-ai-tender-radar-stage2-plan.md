# План анализа для Тендерного радара ИИ

**Цель** — довести фоновое задание до проверяемого результата сопоставления и серверного расчёта.

**Спецификация** — [Тендерный радар ИИ](2026-11-03-ai-tender-radar-design.md), этап 2.

## Сопоставление

- [x] Проверить `match_positions(tender, stock, model, request_id, heartbeat)`. Тесты различают точный артикул, «Болт М12», несовместимую резьбу, недостаток доказательств и подмену SKU или ссылки в ответе.
- [x] В модуле `matching.py` получить кандидатов из всего CSV, передать источники порциями в штатный структурированный Codex CLI и проверить ссылки на каждое обязательное требование. Сохранить подтверждённые решения, ограничения отбора и статус незавершённых строк после сбоя.

## Расчёт и публикация

- [x] Проверить `calculate_analysis(tender, stock, matches)`. Тесты охватывают свободный остаток, конкуренцию за SKU, пересчёт известных единиц, пропущенные данные, маржу по суммам и ограничение отображаемой шкалы.
- [x] В `calculation.py` распределить остаток по допустимым соответствиям и вычислить показатели в десятичной арифметике. Экономика и остатки остаются в Python.
- [x] Подключить модель в отдельный worker, обновлять срок владения заданием между порциями и сохранять результат через миграцию собственной таблицы. Старые загруженные задания сохраняют совместимость. Результат доступен через существующий GET задания с проверкой прав.
- [x] Проверить работу через реальный Codex runner на контрольных данных и прогнать регрессию API и очередей в изолированной PostgreSQL. Прошли 114 тестов. На контрольном болте М12×95 с ГОСТ 7798-70 подтверждены нужный SKU, 100% покрытия и +60% выгоды. SKU с противоречивой длиной исключён. Проверены штатный сценарий запуска и обычная и dev-конфигурации Compose.

Изменения выполняются в текущем корне BERVEL. Страница и её установка относятся к третьему этапу. Действия Git ограничены чтением.

## Контракт анализа

Результат появляется в поле `analysis` ответа `GET /api/v0.1/ai-tender-radar/jobs/{job_id}`. Оно содержит строки с подтверждёнными SKU, ссылками на складские поля, количеством, причинами и экономикой. Загрузка из первого этапа без анализа остаётся читаемой с `analysis: null`.

Сервер передаёт в Codex только технические факты. Число кандидатов на позицию ограничено 12. Если по выбранным доказательствам нельзя установить точный итог, результат сообщает о недостатке данных. В первую версию входят точные требования с проверяемыми наименованиями, артикулами, размерами, стандартами и складскими полями. Неоднозначные характеристики и диапазоны требуют отдельного подтверждения.

НДС по решению владельца отдельно не учитывается. Цены сравниваются в одной валюте по сведениям из Контура и CSV. При недостающей себестоимости, дефиците или конфликте цен выгода остаётся неизвестной.
