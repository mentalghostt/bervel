# 1. Изолированные test и production

Результат: существующий симулятор используется в отдельном тестовом контуре. Одна настройка источника или метка `mock` не заменяет изоляцию.

**Inputs.** `EnvironmentConfig{environment, database_url, object_root, kontur_base_url, model_endpoint}`; согласованный синтетический набор и образ приложения.

**Outputs.** Два независимых набора API/worker/хранилища, явная метка среды в UI; тестовый прогон с `environment=test`.

**Preconditions.** Зафиксированы работающие сервисы и volumes. Все тестовые данные синтетические; права на рабочую БД и оригиналы не выдаются тестовым сервисам.

**Postconditions.** Тестовые задания, настройки, оригиналы и результаты живут в отдельных БД/volumes и очереди заданий. API и worker одного контура используют одну конфигурацию; перезапуск сохраняет его данные.

**Error cases & Invariants.** Проверка конфигурации запрещает одинаковые БД/хранилища test и production, производственный ключ Контура в test и незаметный переход с симулятора на реальный API. Недоступность источника — ошибка. Исторические смешанные данные автоматически не перемещаются и не удаляются. Тестовый модельный клиент не получает доступ к рабочим файлам через инструменты.

**Acceptance Criteria.** GIVEN тестовый прогон WHEN он завершён THEN рабочие записи и файлы не изменены; GIVEN симулятор недоступен WHEN запуск THEN явная ошибка без вызова Контура; GIVEN перепутанные настройки API/worker WHEN старт THEN отказ с причиной; GIVEN перезапуск test THEN его история сохранена.

**Реализация и проверка.** Проверить `compose.yaml`, `.dev/docker/compose.dev.yaml`, `core/config.py`, `ai_tender_radar_setup.py`, `infrastructure/kontur.py`. Добавить `.dev/docker/compose.ai-radar-test.yaml` с отдельными именами сервисов/volumes и `.dev/tests/test_ai_radar_environment.py`. Прогнать HTTP-сценарий существующего симулятора и сверку изоляции. Production-конфигурацию подготовить к отдельной установке; переключение текущей работающей среды — отдельный согласованный шаг этого этапа.
