# 4. Выполнимость заказа с допроизводством

Результат: для дефицита рассчитывается план выпуска ранее производившихся деталей с учётом общих ресурсов и срока поставки.

**Inputs.** `TenderData`, проверенный `MatchingResult`, фактические свободные остатки, каталог с `manufactured_before`, нормы шт./рабочий день, стоимость выпуска, группы ресурсов, календарь свободной загрузки, подготовка/сырьё, дата возможного начала, сроки поставки и доставка. LLM извлекает сроки/условия из документов со ссылками; дата подачи заявки не подменяет дату поставки.

**Outputs.** `FulfillmentPlan`: по каждой строке количество со склада и в производство, ресурс и время, ожидаемая готовность, стоимость, дефицит и ограничения.

**Preconditions.** Сопоставление включает подтверждённую номенклатуру с нулевым остатком. Числовые расчёты начинаются после проверки единиц, количеств и производственных фактов.

**Postconditions.** Код сохраняет проверенный план или `infeasible/needs_review`. Для выбранного SKU: `дефицит=max(0,потребность−выделенный остаток)`, `трудоёмкость=дефицит/units_per_workday+setup_workdays`. Работы одной ресурсной группы конкурируют за её свободные ресурсодни; разные группы работают параллельно. Время доставки исключается из производственного окна. Расчёт моделирует исполнение, реальных резервов не создаёт.

**Error cases & Invariants.** Производство разрешено только для `manufactured_before=true` с подтверждённой нормой. Для каждой строки должен быть покрыт весь объём к её сроку; средний процент не маскирует отсутствующий обязательный товар. Остаток/мощность не расходуется дважды внутри плана. Материалов, данных о загрузке или сроках нет — `needs_review`. Подтверждённый ноль мощности при дефиците/невозможный срок — `infeasible`. Неподдержанная сложная технологическая цепочка не упрощается до фиктивной независимой нормы.

**Acceptance Criteria.** GIVEN нужно 100, свободно 40, норма 20/день, доступно 3 полных рабочих дня и нет подготовки THEN выпуск 60 успевает; GIVEN две детали требуют по 3 дня общего станка при доступных 4 THEN вместе не успевают; GIVEN деталь никогда не производилась THEN её дефицит производством не закрывается; GIVEN производственный календарь неизвестен THEN нет уверенного «успеем»; GIVEN остатка хватает THEN отсутствие нормы выпуска не блокирует поставку со склада.

**Реализация и проверка.** Новый `ai_tender_radar/production.py`, расширение `models.py`, источников сроков и `matching.py`; UI показывает план в `AiTenderRadarPage.tsx`. Алгоритм первой версии: существующее проверенное распределение склада, затем последовательное размещение дефицита по раннему сроку в свободном календаре каждой группы. Для альтернативных SKU/маршрутов неудача этой эвристики означает `needs_review`, если нет доказанного ограничения; найденный план всегда проверяется независимо. Не заявлять глобальный оптимум. Проверки `.dev/tests/test_ai_radar_production.py`: общие ресурсы, выходные, подготовка, сырьё, округление изделий, разные сроки и альтернативы.
