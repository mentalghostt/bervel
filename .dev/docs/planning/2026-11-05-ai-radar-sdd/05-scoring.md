# 5. Проверяемая оценка 0–100

Результат: высокий приоритет возможен при нулевом складе, если весь заказ выгодно и надёжно выполним производством. Наличие склада не компенсирует убыток или невыполнимую строку.

**Inputs.** Проверенный `FulfillmentPlan`, полный состав тендера, выручка по строкам, стоимость выделенного склада, себестоимость допроизводства, подготовка, логистика и прочие обязательные затраты, единая валюта/налоговая база; версионная `ScoringPolicy`.

**Outputs.** `TenderAssessment`, расшифровка `E,S,P`, прибыль и маржа всего заказа, базовый и стрессовый баллы, причины и статус данных. Прежние `coverage_percent`/`benefit_percent` сохраняют свой смысл, новый балл их не подменяет.

**Preconditions.** Для уверенной оценки все существенные входы подтверждены и свежи. Текущий `benefit_scope=confirmed` недостаточен для вывода о целом тендере. НДС сейчас отдельно не считается: до подтверждения сопоставимости цен/затрат новая итоговая экономика имеет статус предварительной.

**Алгоритм score-v1.** Сначала ограничения: доказанная невыполнимость или прибыль ≤0 дают `score=0` с разными причинами; неизвестные критические данные дают `score=null`, без автоматического отказа. Затем:

```text
R = суммарная выручка всего обязательного объёма
C = стоимость склада + выпуска дефицита + подготовки + доставки + иных затрат
m = (R − C) / R
E = clamp(m / 0.30, 0, 1)
S = Σ(R_i × stock_allocated_i / required_i) / R
P = 1 − 0.40 × clamp((U − 0.70) / 0.30, 0, 1)
score = round_half_up(100 × E × (S + (1 − S) × P))
```

`S` — доля стоимости заказа, покрытая складом, поэтому болты и тонны не складываются. Для каждого ресурса и срока: `U_g=B_g/(B_g+L_g)`, где `B_g` — занятое данным планом время выпуска/подготовки к этому сроку, `L_g` — свободное время ресурса после завершения этих работ до срока отгрузки. `U=max(U_g)`. Так поздняя готовность сырья или занятость станка не создают ложного запаса времени. План уже должен укладываться в календарь, сырьё и доставку; `U` не заменяет эту проверку. Когда допроизводство не нужно, `P=1`; при `B_g>0,L_g=0` загрузка равна 1.

Вес склада равен `S`, вес производственного закрытия — `1−S`: мощность влияет только на дефицит. Экономика умножает общую готовность. Целевая маржа 30%, комфортная загрузка 70% и минимальный коэффициент 0.60 — предлагаемые параметры первой версии, не эмпирически доказанный оптимум.

**Postconditions.** Сохранены формула, версия политики и исходные числа. Стресс-сценарий отдельно пересчитывает план при цене −10%, затратах +10% и скорости выпуска −20%. Базовый `score≥80` означает кандидат высокого приоритета; «устойчивый высокий приоритет» требует также стрессового ≥80 и отсутствия критических неизвестных. 50–79 — рассмотрение; 1–49 — низкий приоритет. Причины всегда важнее одного числа; балл не является вероятностью выигрыша.

**Error cases & Invariants.** `R≤0`, неизвестная валюта/стоимость/обязательные позиции — нет положительного балла. Неизвестные расходы не равны нулю. Для конечного допустимого плана балл 0–100; при неизменных прочих данных снижение прибыли не повышает балл, рост загрузки не повышает балл. Прибыль в рублях и прибыль на ресурсодень показываются отдельно: нормированная маржа не оптимизирует общую прибыль завода.

Совпавший по продукции тендер остаётся в выдаче при дефиците, невыгодной цене, плохих сроках, `score=0` и `score=null`. Расчёт относится к конкретному плану исполнения; если альтернативные допустимые SKU/маршруты не исследованы, отрицательная экономика этого плана не выдаётся за доказанную убыточность всех вариантов.

**Acceptance Criteria.** Маржа 40%, склада 0%, `U=0.40` → 100, стресс → 89; маржа 2%, склад 100% → 7; маржа 40%, склада 0%, `U=0.95` → 67, стресс не проходит сроки → 0; никогда не производившаяся недостающая деталь → 0 с причиной; неизвестная себестоимость выпуска → `null`.

**Реализация и проверка.** `ai_tender_radar/scoring.py`, расширение `calculation.py` для полной экономики и модели результата, сортировка API и UI по баллу. Проверки `.dev/tests/test_ai_radar_scoring.py`: примеры, границы, монотонность, Decimal, пропуски и существующая частичная экономика. До заявления об оптимальности — калибровка на ручных оценках и отложенной проверочной выборке, анализ чувствительности параметров; при изменении параметров новая версия политики.
