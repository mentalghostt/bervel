# 7. Проверка прогона и калибровка

Результат: кнопка «Проверить прогон» выявляет ошибки отбора и расчётов, включая ошибочно отклонённые тендеры.

**Inputs.** `RunSnapshot`, первичные материалы, сохранённые этапы/версии, опциональный ручной эталон совпадений, выполнимости и приоритета; `command_key` проверки.

**Outputs.** `AuditReport{run_id,status,checked,total,findings[],rule_versions,model_versions,reference_comparison}`; расхождения по карточкам/позициям и этапам, включая отбор, склад, мощности, деньги и score.

**Preconditions.** Доступ к прогону и снимкам; задан явный бюджет проверки. Исторический прогон без необходимых материалов получает статус «неполная проверка», а не «успешно».

**Postconditions.** Код повторно проверяет арифметику и инварианты на сохранённых входах. LLM заново рассматривает исходные требования/товары и сроки без показа исходного ответа, затем результаты сравниваются. Эталон менеджера используется отдельно от мнения модели. Отчёт сохраняется как самостоятельная запись, исходный результат не переписывается. Есть прогресс и отметка непроверенного остатка.

**Error cases & Invariants.** Повторное согласие той же модели не доказывает истинность. Проверка тем же калькулятором подтверждает воспроизводимость; известные контрольные примеры и ручной эталон нужны для обнаружения ошибок правил. Вновь загруженные данные не заменяют снимок проверяемого прогона. Проверка не расширяет охват поиска за пределы сохранённых кандидатов без отдельного нового запуска. Низкий балл и техническая ошибка различаются.

**Acceptance Criteria.** GIVEN ошибочно отвергнутый подходящий товар THEN отчёт указывает пропуск с доказательством; GIVEN двойное использование остатка/станка THEN найдено нарушение; GIVEN все ответы LLM совпали, но нет ручного эталона THEN нет утверждения «точность 100%»; GIVEN бюджет закончился THEN видны проверенные/непроверенные карточки; GIVEN повтор command_key THEN возвращается прежний audit.

**Реализация и проверка.** Новый `ai_tender_radar/audit.py`, сохранение отчёта/команда в существующей очереди и API; кнопка/отчёт на `AiRadarHistoryPage.tsx`. Проверки `.dev/tests/test_ai_radar_audit.py`, контрольный набор `.dev/tests/fixtures/ai-radar-sdd/` с фиксированными исходами. Калибровка score на подтверждённых реальных случаях, отдельная отложенная выборка; синтетические сценарии доказывают правила, а не оптимальность весов на производстве. При изменении политики не перезаписывать старые оценки.
