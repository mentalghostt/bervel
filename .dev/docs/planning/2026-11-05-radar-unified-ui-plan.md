UI/root: POST /api/v0.1/ai-tender-radar/runs принимает command_key,settings_snapshot_id,name,source(test_api|kontur_api|file),source_artifact_id?; старые бюджеты принимаются необязательно для совместимости, новая форма их не посылает. В run.data сохраняются name/source. GET /runs/history возвращает entries[{id,kind:'legacy'|'run',title,created_at,state,card_count}],next_offset; первая запись legacy. GET /runs/legacy?limit&offset возвращает cards старого TenderCard-формата,next_offset,entry. Старый /jobs/{id} читает детали legacy. Обычные /runs/{uuid} и операции сохраняют нынешнийDTO, дополняются полями data.name/source; для основной подборки учитывать coverage_percent>=80,100сначала. Неполные/низкое покрытие видны в дополнительном фильтре.

selection/root: сохраняются совместимые collect_candidates/rank_candidates/rerank_candidates для v1. Для v3 новый CatalogPrefilter(stock,profile): rank(candidates)->упорядоченные кандидаты; check(tender)->{state:'reject'|'candidate'|'unknown',upper_coverage_percent:str|null,reason:str}. Это только предварительный допуск: unknown не отклоняется, низкое покрытие отсекается только при консервативно доказанной верхней границе. Никакой подмены окончательного matching/calculation. Нет передачи всего каталога вLLM и вызоваLLM на каждыйbrief.

simulator/root: новый coverage profile, поддержка пользовательского stock как входа генератора,150positives+многоhardnegatives,истина отдельным evaluator-объектом/файлом внеHTTP. Старыеprofiles/контракты/seed tests не ломаются; новые квоты позволяют>200карточек. root подключит профиль в локальный runtime и замеритpipeline.
