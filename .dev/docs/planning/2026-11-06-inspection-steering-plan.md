# Inspection steering — план реализации

**Goal:** Досылка уточнений в работающую «Проверку» и Enter только в этом разделе.
**Architecture:** Сохраняемый inbox в chat_turns, доставка native workflow, идемпотентные квитанции runner, Codex App Server. Общая UI/API инфраструктура расширяется только условно для inspection.
**Tech Stack:** Python/FastAPI/SQLAlchemy/PostgreSQL, Node stdlib, установленный Codex CLI 0.163.0, React/TypeScript.
**Spec:** [Спецификация](2026-11-06-inspection-steering-spec.md).

## Ограничения и выполнение

- Корень C:/OSPanel/home/bervel.local; основной core; без Git-записей, новых копий, VPN/OSP изменений.
- Три независимых набора файлов и фиксированный контракт позволяют параллельную реализацию по dispatching-parallel-agents. Root владеет runner и интеграцией; отдельные исполнители — Python inbox и UI. Пользователь разрешил все переходы режимом АВТОНОМНО.
- Текущие изменения других задач сохранять; исходные версии целевых файлов сохранены в .dev/local/inspection-steering-2026-11-06/baseline.
- Не вводить новые внешние зависимости. Обновление CLI — только при доказанной несовместимости установленного.

## Review focus

- POST потерян после принятия: квитанция восстанавливает исход без второго steer.
- Последнее уточнение одновременно с завершением: доставить или безопасно поставить следующим запросом, не потерять.
- Stop и перезапуск: не запустить недоставленные сообщения автоматически после остановки.
- Несколько сообщений, диалогов и областей доступа: сохранить порядок и изоляцию.
- IME, удержание Enter и поздний polling: не дублировать отправку и не стирать новый черновик.
