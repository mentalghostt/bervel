## Поведение

Enter отправляет, Shift+Enter переносит строку; ввод с IME не отправляет сообщение до завершения композиции. Во время работы CLI доступны текст, голос и отправка. На время самого HTTP POST и восстановления неизвестной попытки сохраняется защита от дублей. Каждое уточнение имеет собственный идентификатор, сохраняется в истории и передаётся активной проверке без перезапуска и отмены выполненных действий.

## Устройство

Текущий API messages сохраняется. Только inspection связывает новую строку chat_turns с текущим корневым queued/running запросом: nullable followup_of и delivery_state (pending/sending/accepted/unknown). Worker не запускает связанные строки как отдельные задачи. NativeInspectionWorkflow доставляет их через private POST /v1/inspection/jobs/{id}/messages. Тело: message_id, question, session_id, actor_id, data_scope. Ответ — полный документ родительского job с followups: [{message_id,state}], state queued/sending/accepted/rejected/unknown.

Runner использует двусторонний stdio Codex App Server: initialize, thread/start или thread/resume, turn/start, turn/steer с expectedTurnId, turn/interrupt. Существующие thread IDs, CLI home, провайдер, sandbox, export и маскирование только выхода сохраняются. Добавленные сообщения не превращаются в инструкции разработчика.

Повтор message_id с тем же содержимым возвращает сохранённую квитанцию; другой текст отвергается. Состояние sending записывается до RPC. Потеря подтверждения или перезапуск не разрешает повтор RPC с неизвестным исходом. Если CLI явно отказал, потому что закончился активный ход, сообщение становится обычным следующим queued запросом в том же диалоге. Stop блокирует ещё не доставленные уточнения; они не начинают новую задачу после отмены. Завершение родителя согласуется с enqueue одной блокировкой; сообщения на границе завершения не теряются.

UI показывает отдельные пользовательские сообщения с состоянием доставки, без фиктивного отдельного ответа. API assistant не получает новые поля и сохраняет прежнюю обработку Enter и блокировку занятого ввода.

## Проверка

Контролируемый CLI протокол: досылка во время работающего инструмента влияет на итог; несколько уточнений идут в порядке отправки; один turn/start; возобновление прежнего thread. Контракты, PostgreSQL и браузер: идемпотентность, конкурентное завершение, отмена, потеря POST-ответа, перезагрузка, IME, Enter/Shift+Enter, desktop/mobile и неизменность assistant. Живая проверка использует отдельный QA-диалог и безопасную задачу чтения. Все артефакты в .dev/local/inspection-steering-2026-11-06.
