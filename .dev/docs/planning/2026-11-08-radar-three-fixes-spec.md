# Радар: соответствие, сравнительная оценка и независимые вопросы

Пользователь включил АВТОНОМНО и поручил реализацию субагентам под управлением основного агента.
Рабочий корень: C:/OSPanel/home/bervel.local, Personal, основная ветка core, исходный HEAD 12ebcdb0 (radar-1).

## Требования

1. Проверка совместимости SKU соответствует radar-1: проверяются только реально заявленные требования, отсутствующие параметры не придумываются. Полностью доказанный SKU подтверждает позицию независимо от неполных альтернатив. Количество склада не определяет техническую пригодность. Показатель продукции не должен исчезать у всей закупки из-за одной неопределённой позиции или лота.
2. Все детализированные карточки одного прогона получают сравнительную оценку ИИ 0–100. Модель получает только идентификатор и четыре агрегата: стоимость с валютой, соответствие продукции, покрытие склада, маржинальность с областью расчёта. Неизвестность не равна нулю. Оценка не является разрешением участвовать и не обнуляется из-за невозможности исполнить весь заказ. Лучшие относительно набора получают высокие оценки даже при малом абсолютном покрытии.
3. Вопрос по сохранённому тендеру выполняется параллельно анализу прогона. Независимость проходит через форму, очередь, исполнителя и доступ к модели. Сохраняются область доступа, защита повторных команд, история ответов, остановка и удаление.
4. Последующее указание владельца: после выполнения трёх исправлений удалить локальный предел двух одновременно выполняемых модельных запросов и искусственный semaphore на модельные запросы прогона. Естественный порядок операций/ограниченное число обработчиков карточек не являются квотой модели; provider quotas и ограничения контекста не обходить.

## Решения и границы

- В radar-1 отдельного catalog_match_percent не было: исходная метрика измеряла обеспеченные штуки, а её запасной вариант — полностью обеспеченные строки. Техническую совместимость восстанавливаем по исходным требованиям/доказательствам. Для новой колонки продукции считаем подтверждённые подходящие строки среди раскрытых строк, отдельно показывая неполноту; склад остаётся самостоятельной метрикой. Строгие выводы о пригодности целых лотов сохраняются отдельными от этой витринной метрики.
- Устранить исходный дефект matching: ноль положительных доказательств у постороннего складского изделия не создаёт неопределённость всей позиции. Не ослаблять проверку явно указанных требований, не превращать ошибку модели в несовпадение.
- Исторические анализы и исходный CSV не переписывать. Проекция использует исторические склад/профиль и сохранённые доказательства. Сравнение с radar-1 на тест100 сначала выполняется с теми же сохранёнными ответами модели, без повторных сетевых запросов.
- Сравнительный рейтинг хранить отдельным отчётом с fingerprint нормализованных четырёх агрегатов. GET не вызывает модель. Перед вызовом сохранить running; неизвестный исход не повторяется автоматически. При продолжении сохранять пригодные завершённые результаты. Большие наборы не усекать; ограниченные пакеты должны иметь общий сравнительный контекст.
- Для вопросов и анализа использовать две линии исполнения в существующем worker/очереди. На этапе3 анализ занимает не более одного модельного места, вопрос — отдельную линию; после приёмки этого исправления этап4 удаляет локальный model cap/semaphore по отдельному указанию владельца. Не менять выбранную модель/провайдера и не добавлять новую инфраструктуру без необходимости.
- Не устанавливать отложенную inspection-функцию 0028. При необходимости новой схемы сохранить линейную историю: новую radar-ревизию поставить после применённой0027 и перед ещё нигде не применённой0028, изменить только её down_revision. Выпуск применяет явную radar-ревизию, а не head.
- Общий dirty tree не принадлежит этой задаче. Git только чтение; никаких commit/staging/push/fetch/переключений. Работа на месте разрешена личными правилами. VPN, Open Server Panel и папки проекта не менять.
- Все отчёты, baseline, тестовые данные и материалы выпуска внутри .dev/local/radar-three-fixes-2026-11-08. Дизайн существующего UI сохранить.
