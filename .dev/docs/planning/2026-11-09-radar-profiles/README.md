# Постоянные профили тендерного радара — план реализации

> Для исполнителей: применять subagent-driven-development и test-driven-development. Режим АВТОНОМНО. Переходы этапов разрешены пользователем; независимые вертикали выполнять параллельно после сверки спецификаций.

**Цель:** один обновляемый анализ и база тендеров на источник вместо истории раздельных анализов.

**Архитектура:** два фиксированных профиля владеют постоянными контейнерами анализа (существующий run_id используется как внутренний идентификатор, а не новая история). Очередь PostgreSQL, анализ подробностей, доказательства сопоставления, документы и адресный чат переиспользуются. Поиск/приоритет/детали/пересчёт реализует единый сценарий для двух адаптеров; расписание исполняет существующий worker. Новые библиотеки и процессы не нужны.

**Стек:** Python 3.12, FastAPI/Pydantic, SQLAlchemy 2/PostgreSQL, React 19/TypeScript, существующие CSS/dialog и модельный шлюз.

**Спецификации:** [01 — профили и хранение](01-profiles-storage.md), [02 — обновление и квоты](02-refresh.md), [03 — интерфейс](03-interface.md), [04 — интеграция и выпуск](04-integration.md).

## Глобальные ограничения

- Корень Personal: `C:\OSPanel\home\bervel.local`, основная ветка `core`, существующая папка; Git только для чтения. Dirty tree предыдущих задач сохранять. Все материалы внутри корня. Не создавать клон/worktree для копирования незакоммиченных изменений.
- Не менять VPN, его адаптер, Open Server Panel или модули. Приложение уже работает в Docker.
- Не менять склад, настройки предприятия, оригинальные файлы и другие разделы. Старые строки только таблиц радара удалить БЕЗ резервной копии по прямому ответу пользователя. Никакого восстановления старого dump поверх БД.
- Лимит кратких карточек исправлен пользователем на **10 000 = 200 × 50**. Оба источника исполняют одинаковую механику.
- Числовые фильтры кроме цены работают **от** значения. Ручная квота подробностей **0** допустима.
- После смены ключевых слов старые карточки не становятся неактуальными из-за отсутствия в новой выдаче; истечение срока продолжает действовать.
- Операции с неизвестным исходом не повторять автоматически; сохранять квитанции и попытки до внешнего запроса. GET не вызывает ИИ/источник и не пишет состояние.
- Отложенную inspection-миграцию 0028 и неустановленные соседние изменения не выпускать вместе с радаром. Новая миграция радара должна работать поверх установленной 0027a независимо от inspection-ветви.

## Review focus

1. Повтор POST после обрыва/двойной worker не удваивает расход и карточки; смена склада между отправками не ломает replay.
2. 10 000 результатов, 9 999 при незавершённом обходе, сбой страницы, дубль ID и истёкшая дата не дают массовой ложной неактуальности.
3. Смена слов и нулевая квота не теряют старые карточки/чат; новый склад действительно меняет покрытие.
4. Перезапуск worker, пропущенное время, n дней, два tick и ручное обновление в тот же день не дают повторного автостарта.
5. Длинные названия, 10 000 карточек, неизвестные метрики/валюта/тип торгов, mobile и клавиатура сохраняют рабочий интерфейс.

## Проверка границ параллельной работы

| Пара | Интерфейс/файл | Разрешение |
|---|---|---|
| storage / refresh | PostgresProfileRepository.upsert_card, operation | Зафиксированы выше; storage владеет реализацией, refresh только вызывает |
| storage / frontend | /profiles API | Формат spec 01; не менять без сообщения root/соседнему агенту |
| refresh / frontend | RunCard + metrics/information_state | Дополняющий контракт spec 02/03; legacy поля сохранены |
| root / storage | profiles wiring, schedule tick | Только root правит setup/worker/app_setup/runs.py |
| root / refresh | profile_policy | Только root пишет policy; exact signatures в spec 02 |
| root / frontend | assets / installation | Агент правит source; root собирает узкий release из проверенного source |
| storage (самосогласованность) | миграция/API/repository | Одна сущность профиля, unique(scope,source), stable run и тендер |
| refresh (самосогласованность) | briefs/details/stock | 10 000/200/50, 0 допускается, нет повторных деталей |
| frontend (самосогласованность) | активность/полнота | Независимые метки, числовые фильтры «от», один актуальный список |
| root (самосогласованность) | purge/release | Backup запрещён пользователем; остальные данные не меняются |
