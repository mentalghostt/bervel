# План реализации этапа 3.1

> Исполнитель: текущий агент, без делегирования реализации. При выполнении используется executing-plans; этот документ не разрешает Git-изменения или следующие этапы.

**Цель:** пользователь через браузер загружает учебный CSV, получает проверенный результат и читает обе редакции без дублей и утечки между областями.

**Архитектура:** небольшое Python-приложение с прикладными правилами, HTTP-входом и отдельными адаптерами PostgreSQL/файлов. Учебный модуль формирует записи; ядро проверяет схему и публикует набор одной транзакцией. Обработка синхронная, n8n не подключается.

**Стек:** Python/FastAPI, Uvicorn, SQLAlchemy/psycopg, Alembic, jsonschema; pytest/HTTPX для разработки. Точные совместимые версии фиксируются при установке.

**Спецификация:** [принятый профиль 3.1](../architecture/13-core-stage-3.1-storage-csv.md) и [контракт 0.1.0](../architecture/12-core-v0.1-spec.md).

## Общие ограничения

- Работа в `C:/OSPanel/home/bervel.local`, ветка `core`; Git только для чтения, без новой копии и worktree.
- Приложение в `src/bervel`, пакетная конфигурация и миграции вне `.dev`. Тесты, образцы, инструкции и отчёты — в `.dev`.
- PostgreSQL 17 уже включён пользователем. Создаются отдельные база и роль приложения и отдельная учебная БД проверок; базы n8n и другие существующие данные не меняются.
- Сервисы Open Server и VPN не переключаются. Приложение подключается по переменным окружения; сервер API слушает loopback.
- Оригиналы имеют логические ссылки; путь не определяется исходным именем. Максимум 5 MiB, 1000 строк, 2000 символов в ячейке.
- Источник роли `test_fixture`; `pcs`/`piece` → `piece`, пустое количество → `UNKNOWN`/`null`. Значимые десятичные числа передаются строками.
- Тот же ключ команды с иными данными — конфликт. Публикация результата атомарна; области и права определяются сервером.
- Секреты только через окружение; локальная настройка и отчёты не содержат открытых секретов. Автоматическое удаление объектов не вводится.

## Дополнительные случаи проверки

- CSV с BOM/CRLF, дублирующими заголовками, лишней ячейкой и повторным `line`.
- Отрицательные числа, NaN/Infinity, неизвестная единица и слишком длинное поле.
- Одновременный повтор одной команды и разные команды с одинаковой ожидаемой редакцией.
- Чужая область при чтении оригинала, страниц результата и истории; неизвестный ключ доступа.
- Ошибка файлового сохранения или SQL-транзакции, повреждение сохранённых байтов, запуск собранного пакета без исходников `.dev`.

## Приёмка этапа

Критерий: пользователь самостоятельно запускает API, загружает оба учебных файла, видит ожидаемые значения и неизменную первую редакцию, повторяет команду без дополнительного результата и получает отказ при чужом доступе. Отчёт перечисляет выполненные команды, результаты и оставшиеся ограничения. Полный CORE-V01, n8n, согласование и промышленная отказоустойчивость не отмечаются выполненными.

После этапа 3.1 работа останавливается для приёмки. Коммиты и операции с PR из текущей папки выполняет человек.
