# План реализации этапа 3.2

> Исполнитель: текущий агент, inline через executing-plans; один независимый read-only review после реализации. Режим АВТОНОМНО разрешает внутренние переходы. В основной ветке `core` Git остаётся только для чтения.

**Цель:** учебный CSV обрабатывается через n8n, процесс и попытки прослеживаются, ручное восстановление сохраняет исходные входы/версию и не дублирует результат.

**Архитектура:** существующие приложение, parser и хранилище расширяются портом движка процессов, отдельным PostgreSQL-репозиторием и API. Публикация результата использует существующую транзакционную логику с проверкой актуальной попытки. Собственный оркестратор не создаётся.

**Стек:** существующие Python/FastAPI, SQLAlchemy/PostgreSQL/Alembic, стандартный HTTP-клиент Python; n8n 2.43.5 и Redis в Docker. Новые зависимости не требуются.

**Спецификация:** [этап 3.2](../architecture/14-core-stage-3.2-orchestration.md), [контракт ядра](../architecture/12-core-v0.1-spec.md), [ADR-0002](../adr/0002-durable-orchestration.md).

## Общие ограничения

- Корень C:/OSPanel/home/bervel.local, Personal; новые материалы разработки только `.dev`.
- Продолжать в существующей папке; не создавать копию или worktree без необходимости. Не менять Git в `core`.
- Не менять VPN и модули Open Server. Использовать доступный Docker; сохранить старые данные/ключи n8n.
- Runtime не читает `.dev`; схемы workflow поставляются с модулем.
- Внешний контракт движка — public API `/api/v1` и production webhook. Документация Context7 недоступна; проверены официальные страницы и исходники установленного выпуска.
- Перед изменением поведения — тест RED, затем минимальная реализация и GREEN.

## Фокус проверки

1. Сетевой ответ потерян после успешной публикации или создания исполнения: не создавать новый эффект вслепую.
2. Callback восстановления приходит раньше HTTP-ответа retry: не перезаписать его состояние запоздалым ответом.
3. Старый worker заканчивает после новой попытки/редакции: атомарно отклонить публикацию.
4. Новая версия workflow опубликована между аварией и повтором: сохранять исходную версию, входы и модуль.
5. История n8n недоступна/обрезана или чужая область угадывает ID: явный безопасный отказ без утечки/повтора.
