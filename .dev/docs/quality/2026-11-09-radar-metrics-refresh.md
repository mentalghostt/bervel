## Что изменено

- Убран control «Валюта стоимости». Цена остаётся подписанной одной валютой; RUB и другие валюты не смешиваются и не пересчитываются по выдуманному курсу.
- Range исключены из общего стиля текстовых полей с сохранением специфичности для остальных input. На установленном UI у всех шести range прозрачный фон, высота области 26px, border/padding/radius0; тонкая линия и две видимые ценовые ручки работают с pointer/keyboard до концов.
- Удалены требуемые пояснения попапов профиля и обновления. Квота, её валидация и расписание сохранены.
- Добавлена «Обновить показатели» → `POST /profiles/{source}/metrics` со строго одним `command_key`. Берётся последний сохранённый профиль предприятия с выбранным им складом, входы закрепляются на всю команду/возобновление. Источник и ИИ не требуются.
- Пересчитываются покрытие и маржинальность с числовыми строками/агрегатами. В БД исходные анализ, соответствия, ревью, план, дата анализа и оценки не подменяются: новая числовая проекция хранится отдельно.
- При изменении основания старый балл остаётся виден как «Оценка до обновления показателей», ревью также помечается прежним. Неизменившиеся факты не устаревают из-за нового UUID снимка или текстовых labels. Stale score не становится актуальным в фильтре.
- Полный refresh нового режима: метрики → поиск → приоритет новых/неоценённых кратких карточек → отсутствующие подробности → необходимые подробные стадии и индивидуальная оценка. Старые валидные первичные оценки не отправляются модели заново из-за нового refresh ID.
- Готовые стадии повторно используются по существенным входам. Stock-only изменения не требуют снова читать неизменившиеся документы/подтверждать тот же технический SKU. Новый день производственного расчёта/дедлайн учитываются. До10 подробных жизненных циклов, сохранение расчёта до ревью/оценки, отдельный retry незавершённой стадии.
- Transient ошибки одной карточки не обрывают свежих соседей; ограниченный retry и provider cooldown сохраняются. Stop/lease/ownership/платный source unknown не обходятся. Остаточные ошибки отражаются честно после сохранения остальных результатов, без фиктивного полного успеха.

## Существенные исправления, найденные до установки

1. Кэш зависимостей не учитывал экспериментальные производственные изделия и production unit/attributes. Изменённая маржа могла не сохраниться; исправлено общими production products и regression persistence.
2. Быстрый cost-only путь пропускал неоднозначность маршрутов/распределения склада, ошибочно объявляя полную себестоимость. Guard сохраняет unknown без календаря; проверен на изменившихся затратах.
3. Неизвестное покрытие и область подтверждённых лотов должны совпадать с полным анализом. Null не превращается в0/подтверждение при новых остатках.
4. Review timeout/crash требует durable calculation до model I/O, а source unknown — сохранённой reservation без автоматического повтора.

## Источники и пределы подтверждения

`test_api` и `kontur_api` проходят общий прикладной сценарий; граничные страницы/10 000cap, квоты, нестабильная выдача, сроки, retry/resume проверены на двух реальных вариантах клиента с synthetic HTTP transport. Unlimited fallback разрешён только симуляции.

Боевые платные запросы и реальную доступность вложений при установке не проверяли. Общий document v4 разбирает уже имеющийся текст без сетевой загрузки/OCR; URL без текста остаётся честной неполнотой `DOCUMENTS_NOT_FULLY_READ`. Это не объявляется живой проверкой настоящего API или гарантией доступности провайдера. Неизвестный платный исход не повторяется автоматически.
