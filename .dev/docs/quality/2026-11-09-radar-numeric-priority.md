# Первичный приоритет: один числовой ответ на тендер

Задача и установка разрешены пользователем: один тендер на запрос, до10 запросов параллельно, модель возвращает только целое число0–100 для очереди загрузки подробностей; сохранить текущие оценки и продолжить незавершённый анализ. Все материалы внутри `.dev/local/radar-priority-2026-11-09/`. Git только чтение.

## Устройство

- `brief_ranking.py` отправляет одну краткую карточку с ограниченными образцами продукции. Ответ — только число. Категория, обоснование, цитата и ссылки на продукцию больше не запрашиваются и не создаются для новых первичных решений. JSON Schema для прежнего многословного ответа удалена; на границе принимаются только целые0–100, без JSON-объекта, текста, дробей или логических значений.
- Существующий ThreadPoolExecutor держит максимум10 незавершённых задач без очереди из тысяч заранее отправленных запросов. Завершения сохраняются по готовности. Ошибка одной задачи останавливает новую отправку, после чего остальные полученные корректные числа сохраняются; неподтверждённые оценки не заменяются нулём.
- Связь числа с тендером обеспечивает карта future→candidate_id. Стабильный SHA256 request_id укладывается в лимит runner128 символов даже при source ID длиной128; namespace включает логический refresh и тендер.
- `profile_refresh.py` сохраняет `priority_score` и `priority_evidence={score: N}` каждой новой карточки, без `priority_reason`. Совместные счётчики и model-attempt reservations защищены существующим RLock. При Stop новые вызовы прекращаются, уже выполняющиеся результаты сохраняются под действующей проверкой владельца. Результат карточки служит основанием для продолжения при разрыве перед записью общего checkpoint.
- Подтверждённые старые оценки, включая прежние объяснения, сохраняются без нового запроса к модели. Новый запрос выполняется только для незавершённой карточки. Полный анализ, сравнительный рейтинг, источники, квоты и выбранная модель не менялись.
