## Исправление

- Первичная оценка сохраняет проверенные evidence каждой завершённой карточки с `priority_refresh_id`, счётчики и текущий пакет. При recovery повторно валидируются сохранённые evidence; завершённые карточки исключаются из модельных запросов. Callback передаёт новый пакет, не копирует весь накопленный набор10 000 на каждом шаге.
- Полный анализ сохраняет `analysis_completed_refresh_id` атомарно с результатом. Разрыв между записью результата и общим checkpoint не вызывает повторного анализа. Последние параллельные результаты записываются по фактическому завершению, без ожидания первого медленного future.
- Продолжение получает новый queue job_id при прежних run_id, snapshot, keywords, budgets и logical refresh_id. На каждом execution write одна транзакция блокирует run и проверяет актуального владельца/scope/live lease. Защищены update/upsert, archive, скрытый prepare_card, rating reserve/report; поздний старый worker не перезаписывает новое исполнение.
- Worker автоматически подхватывает только потерявшие lease profile_refresh. Ручной Stop не возобновляется сам. Ожидаемый predecessor и причина проверяются атомарно под lock. POST `/profiles/{source}/resume` — явное продолжение с прежними входами, с квитанцией и проверкой прав.
- Уже сохранённая исходная поисковая страница обрабатывается из архива без повторного HTTP. Stable refresh_id/request_job_id позволяют найти её через несколько recovery hops. Неизвестный исход платного запроса без архива не повторяется; показывается точная ошибка. Оплаченные подробности сохраняются до ИИ.
- Итоговый сравнительный рейтинг хранит исходный нормализованный snapshot и завершённые пакеты. Recovery продолжает только незавершённый пакет; истечение сроков в период остановки не смешивает разные cohorts. Прежние отчёты не переписываются.
