## Изменение поведения

- Первичная оценка по-прежнему возвращает только целое число0–100: один тендер на запрос, до10 одновременно. Первый проход охватывает все ещё не оценённые карточки. Временный сбой отдельного запроса больше не прекращает этот проход.
- После свежих карточек выполняются до2 дополнительных проходов только для оставшихся неудачных оценок: максимум3попытки на тендер в одном цикле. Базовые паузы5/15сек, heartbeat не реже1сек во время ожидания. После исчерпания бюджета показывается ошибка с числом оставшихся карточек и последней ошибкой именно незавершённого тендера. Подтверждённые числа не заменяются нулём и не пересчитываются.
- Автоматически повторяются только временные модельные ошибки timeout/unavailable/failed/busy/rate-limit и неверный числовой ответ. Stop, потеря владельца, ошибки авторизации, настройки, квоты/баланса и TLS прекращают отправку; уже полученные корректные ответы сохраняются.
- `Retry-After` задаёт абсолютный deadline перед любым следующим запросом, включая свежие карточки текущего прохода. Во время cooldown готовые ответы остальных запросов продолжают сохраняться. Deadline хранится в checkpoint и переживает восстановление процесса и ручное продолжение.
- `checkpoint.ranking_retry` хранит цикл, зарезервированные попытки каждой карточки и `not_before`. Попытка сохраняется до model I/O вместе с pending ID. Автоматическое восстановление потерянного lease сохраняет бюджет; явное ручное resume начинает новый ограниченный цикл только для неоценённых карточек, сохраняя provider cooldown. Готовые приоритеты определяются по прежнему logical refresh и их устойчивым маркерам.
- Повторы относятся к первичной ИИ-оценке. Платные запросы источника с неизвестным исходом не повторяются, поиск/подробный анализ/сравнительный рейтинг сохраняют свои прежние правила и checkpoints.
- Кнопка «Возобновить» появляется при failed-профиле рядом с «Обновить». Она использует существующий POST `/profiles/{source}/resume`, прежние run/snapshot/keywords/квоты, без нового поиска. Для обоих источников действуют единый durable command, защита двойного нажатия, replay той же команды после неизвестной квитанции и обновление статуса через прежний polling. Старые сохранённые refresh-команды совместимы.
