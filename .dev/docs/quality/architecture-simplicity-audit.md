## Самое простое корректное устройство и небольшие этапы

Цель: одна ручная сборка; общие документы/доступ/модель; модули с собственными обычными операциями; HTTP и SQL по краям; простое последовательное выполнение фоновых обработчиков. Нынешняя основа уже близка к этому. Достаточно убрать лишние обязанности, не заменяя её новой архитектурой.

Предлагаемый порядок, **ничего из него не выполнено**:

1. **Убрать старую ветку CSV-поиска.** Критерий: один действующий путь получения контекста; текущий парсер, scope, точные редакции, длинные ячейки и история продолжают работать; схемы БД/оригиналы неизменны.
2. **Согласовать и выровнять чтение обычного CSV.** Критерий: таблица поддерживаемых разделителей/кодировок даёт предсказуемые preview и индекс; сохраняются лимиты и locator строк; учебные/тендерные правила не смешаны с декодером. При изменении индекса проверена его версия.
3. **Сократить контракт подключения модулей.** Критерий: реальная новая операция подключается Python-кодом без пустых деклараций; текущие схемы, данные, авторизация и выбранная совместимость `/modules` сохранены; API/worker устанавливаются без `.dev`. При таком изменении нужны соответствующие backend-проверки, без повторных платных генераций.
4. **Уточнить реальные границы модулей.** Критерий: допустимый публичный межмодульный вызов не запрещён проверкой, внутренний доступ/циклы запрещены; «последний CSV» остаётся поведением чата и не влияет на явные источники радара.
5. **Отдельно решить назначение учебного контура.** При сохранении — не перестраивать его в универсальный двигатель. При выводе — сначала определить сохраняемые API/историю и проверить чтение прежних результатов, отсутствие потери данных и работу чата/радара. Это продуктовая развилка, не техническая уборка по умолчанию.

Для самостоятельной поддержки полезнее начать с одной такой небольшой правки и проследить её целиком. Новое поле отчёта обычно требует правила в `analysis.py`, HTTP-типа, отображения и иногда PDF — несколько файлов здесь отражают несколько настоящих обязанностей. Учить реестр совместимости для изменения правила отбора не требуется. Плотная запись радара в одну строку и смесь исторических/актуальных пояснений дополнительно затрудняют чтение; исправление читаемости не требует новых классов и каталогов.
