## Причина и тесты до кода

Сохранённый пользовательский запрос упал на `knowledge.search` с `EMBEDDING_REGION_UNAVAILABLE`. Доступная PostgreSQL-база и оригиналы не использовались без внешнего embedding-запроса. Любая ошибка инструмента выходила из цикла планирования и обрывала сообщение. Дополнительно подтверждён ошибочный `failed` после фактического создания файла: потерянное чтение metadata могло разрешить дубликат.

Исходная фаза RED выполнена до изменений production: retrieval 11 failed/5 passed; workflow 13 failed/3 passed (два запуска); outcome safety 1 failed/1 passed. Настоящие PostgreSQL, репозитории, HTTP, квитанции, renderer, скачанные PDF и извлечение текста; подменены только внешние модель/embedding/web.

Независимое review добавило RED до каждой соответствующей правки: реальные URLError через CodexClient до/после эффекта, повтор failed web с изменённым запросом, выдуманный успех после failed create, потеря lexical/mock предупреждения, лимит шести шагов и потерянное подтверждение записи настроек. Затем все 11 review-сценариев прошли. Отдельно зафиксированы RED для чтения выбранного склада при пустом поиске, pending/failed индексе, и для HTTP статусов typed ошибок модели.

## Изменения

- Scoped лексический поиск по уже готовым текстам при шести известных embedding-ошибках; режим, причина и ограничение сохраняются даже при нулевой выдаче. Чужие/удалённые файлы и другая модель индекса не обходят прежние проверки.
- Чтение выбранного оригинала переходит к упорядоченной странице, когда поиск пуст или индекс недоступен. Сохраняются точные строки и признак неполноты; нет повторного embedding API.
- Известные отказы возвращаются планировщику типизированно. Completed карточки основаны на сохранённых эффектах, неизвестные исходы не повторяются. Ложное сообщение модели о созданном файле после failed create не показывается.
- Нет автоматического нового платного web-запроса после failed web, даже с изменёнными словами. Успешные различные исследования допускаются.
- Ошибка модели после создания документа сохраняет доступ к реальному файлу. Транспортные/структурные ошибки получили отдельные коды и безопасные HTTP 503/502. Ожидаемые ограничения дают обычный честный ответ, без выдуманных файлов/источников.
- Исследование конкурентов разрешает необходимые чтение ассортимента и штатный веб-поиск. Планировщик отличает склад от закупок/экономики и не требует от пользователя помнить имя файла.
