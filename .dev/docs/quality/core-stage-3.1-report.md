Дата: 14 октября 2026. Реализация подготовлена к приёмке владельцем разработки. Рабочий корень `C:/OSPanel/home/bervel.local`, существующая ветка `core`; Git использовался только для чтения. Предыдущие незакоммиченные материалы планирования сохранены. Следующие этапы не выполнялись.

## Полученный результат

Приложение сохраняет исходные байты, редакции и происхождение, разбирает искусственный CSV, проверяет payload по неизменяемой зарегистрированной схеме и публикует весь результат одной транзакцией PostgreSQL. Серверный ключ определяет субъекта, область и права. Повторы возвращают прежнюю ссылку; иное тело под прежним ключом и конкурирующая редакция получают явный конфликт. Первая редакция остаётся доступна после второй.

Код и ресурсы приложения находятся в `src/bervel`; сборка — `pyproject.toml`. Тесты, образцы, помощники и отчёт находятся в `.dev`. [Инструкция самостоятельной проверки](../operations/core-stage-3.1-local.md).

## Разбор отказов и ревью

Проверки заранее описывали неправильные заголовки, лишние ячейки, повтор `line`, отрицательные/нечисловые/бесконечные значения, неизвестные единицы, пределы файла/строк/ячеек и повреждённую кодировку. Некорректное содержимое сохраняется как оригинал после допустимой загрузки; набор не публикуется. Повреждение сохранённых байтов возвращает отказ целостности. Сбой после записи части строк откатывает также набор, снимок, обработку, аудит, квитанцию и указатель текущей редакции.

Самостоятельная проверка выявила неоднозначный JOIN SQLAlchemy; связь результата с областью его оригинала теперь указана явно. Независимый агент выполнял только read-only ревью. Найденные им пробелы воспроизведены отдельными отказавшими тестами, затем исправлены: история требует оба права чтения; URI схемы уникален независимо от пары ID/версия; превышение общей квоты тела возвращает `413` в едином конверте. Ранний отказ неизвестному ключу независимо проверен до чтения тела. Итог ревью: оставшихся actionable замечаний нет; эксплуатационные проверки вне объёма явно отделены.

API содержит отдельные модели ответов и ошибок; `/docs` описывает реальные структуры. Ошибки CLI подключения к БД возвращают безопасное сообщение без traceback и адресов. Тестовый клиент использует HTTPX ASGITransport напрямую, поэтому не вызывает предупреждение устаревшего Starlette TestClient.

Два последовательных файла миграций сохраняют историю структуры: `0001_core_storage`, `0002_core_extraction`. Дополнительная миграция введена после реализации хранения, вместо переписывания уже применённой структуры. Это уточнение упаковки принятого решения, а не новая архитектура.

## Ограничения и состояние после проверки

Хранилище локальных объектов, синхронная обработка и ключи доступа предназначены для искусственного учебного сценария. n8n, OCR, модели, согласования, второй модуль, реальный склад, корпоративный вход, нагрузка, резервное восстановление и отказоустойчивость ОС не реализованы и не приняты. Проверка wheel подтверждает независимость пакета от файлов разработки и путей панели; PostgreSQL предоставлялся этой локальной машиной. Полное развёртывание на отдельной площадке без Open Server ещё не проверялось.

Секреты не сохранялись в Git, отчёте или обычных журналах. Автоматической очистки исходных объектов нет. Проверочные API-процессы остановлены; базы и учебные материалы сохранены для повторной проверки. Коммиты, staging, push, merge и операции с PR не выполнялись. Работа останавливается после этапа 3.1 для приёмки; 3.2 и 3.3 требуют отдельного разрешения.
