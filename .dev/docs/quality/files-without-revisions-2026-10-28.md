# Файлы без редакций: состояние при завершении сессии

28 октября 2026. Пользователь запросил `end full` до установки новой схемы в основное приложение. Удаление 28 старых скрытых файлов завершено; переход на отдельные файлы реализован и проверен в исходниках, но **не установлен**. Основное приложение работает на миграции `0012_assistant_workflows` и прежних образах.

## Подтверждённый результат

- Уничтожены ровно 28 файлов и 32 сохранённых содержимых из закреплённого manifest. Удалены их поисковые и производные данные, а также 17 физических объектов без оставшихся ссылок. Сохранены шесть активных оригиналов. Чаты, отчёты и обращения не удалялись. Минимальные признаки удалённых ID остаются для ответа «Файл удалён». Независимые старые backup и Downloads в операцию не входили.
- Новый контракт использует один ID неизменяемого файла. Новая загрузка или правка создаёт отдельный файл; повтор одной команды возвращает прежний результат. Редакции удалены из ядра, индексов, API, чата, радара и интерфейса. Собственные версии наборов данных и обращений сохранены.
- Миграция0013 проверена на восстановленной фактической базе: сохранены 6 файлов, 7 678 прежних векторов, 13 запусков радара, 44 реплики, 14 чатов, 4 обращения и 29 действий. Из 13 запусков 12 имеют сохранённый отчёт. Байты оригиналов не переписывались, переиндексация не запускалась. Числовые результаты и свободный текст истории не менялись.
- Итоговый Python-набор: **462 passed**, 3 прежних предупреждения; frontend: **101 passed**, сборка без ошибок с 6 прежними предупреждениями. Упакованные 91 Python-файл совпадают с рабочими исходниками. Новые зависимости и службы продукта не добавлялись.
- Независимые UI и архитектурная проверки приняты после исправлений: старая неизвестная команда радара не теряет JSON/ключ и не отправляется автоматически; при удалении текущего источника набор данных атомарно переключает и свою версию, и ID файла. Отдельно исправлена гонка чтения с удалением.

## Живые проверки и ограничения

На изолированной базе и отдельном файловом хранилище подняты кандидат API, три обработчика и frontend без опубликованных портов. Через настоящий HTTP-контракт прочитаны все шесть оригиналов с проверкой SHA256, готовности и просмотра; все 28 удалённых файлов возвращают410. Прежние маршруты отсутствуют, старый параметр редакции отвергается. Прочитаны сохранённые чаты, обращения и отчёты, сформирован PDF без вызова модели.

Проверены две самостоятельные загрузки одинакового содержимого под одним именем, повтор command_key, подготовка, просмотр и удаление одного экземпляра с сохранением другого. Реальная модель прочитала контрольный CSV и исходный DOCX. Создание DOCX подтверждено сохранённой квитанцией; последующий запрос на правку завершился штатно через `file.read`→`file.create`, новый ID отличается, SHA256 исходника прежний.

Однако часть запросов вернула `MODEL_FAILED` из существующего Codex-сервиса. В первом случае документ уже был создан; результат сохранён, создание не повторялось. Один запрос на правку остановился после чтения, ещё один запрос чтения — до действий. Два отдельных контрольных запуска радара получили частичные отчёты с ошибкой модели: две исходные строки учтены, одна отсеяна по сроку, одна явно оставлена непроверенной. **Успешный живой проход нового радара с моделью не подтверждён.** Причина ошибки внутри модельного сервиса не установлена; относить её к провайдеру или миграции без дополнительных данных нельзя. VPN, авторизация, настройки и сертификаты не менялись.

При `end full` остановлены и удалены только пять собственных QA-контейнеров и точная временная база. Основные семь служб здоровы; все 24 таблицы и шесть объектов основного приложения побайтно/логически совпадают со снимком после разрешённого удаления. В основной схеме0013 не запускалась. Проверка установленного нового UI также не выполнена.

## Продолжение

Сначала изучить `MODEL_FAILED` безопасной диагностикой, не повторяя сохранённые эффекты и не меняя VPN/MOX. При необходимости заново восстановить post-purge backup в новую изолированную базу и поднять кандидаты. После успешного живого контроля проверить source/image hashes и отсутствие активных задач, сделать свежую копию после удаления, затем согласованно обновить API и все три Python workers вместе со схемой0013 и frontend. Проверить основной UI, фактические оригиналы, старые источники и сохранность данных. Подготовленный runtime-helper до установки необходимо перечитать; это не команда для слепого запуска.

Код и документация остаются незакоммиченными в существующей ветке `core`, рядом с прежними изменениями. Git-операций записи не было.
