## Результат

- В установленном API отсутствуют все семь прежних маршрутов `/api/v0.1/radar/*`. Проверенные чтения партий, запусков и статуса Контур возвращают 404, включая обращение через рабочий frontend.

- Старый пакет отсутствует в новых образах API и трёх общих workers. Операции `radar.*` удалены из ассистента, CLI не принимает worker `radar`.
- Применена миграция `0024_retire_legacy_radar`: `radar_runs` и `radar_batches` физически отсутствуют. Контейнер `bervel-worker-radar-1` удалён без удаления volumes или других контейнеров.
- Контейнер ИИ-радара, его образ и работающий процесс не заменялись. Код ИИ-радара и его данные сохранены.

Заменены только 11 файлов удаления и удалён старый пакет; в API также добавлена новая миграция. Полная сверка файлов подтвердила отсутствие остальных изменений. У API все 12 файлов ИИ-модуля и его сборки зависимостей сохранились по SHA256. Проверены также 15 защищённых исходных файлов ИИ-радара из первого этапа.

Идентификаторы остальных работающих контейнеров сохранились. Изображения не строились из общего dirty tree целиком, изменения других задач не выпускались.

Обычные локальные теги `bervel-api:local` и `bervel-frontend:local` также указывают на новый выпуск. Их прежние образы сохранены под тегами `bervel-retire-legacy-previous:*`. Основной Compose и список workers уже исключают обычный радар; стандартная пересборка из исходников его не возвращает.

## Данные и порядок установки

Перед установкой сохранены контрольные суммы всех таблиц и резервная копия БД в каталоге этапа: `database-before.dump`, 61 223 882 байта. Активных заданий ИИ-радара и сообщений очереди ассистента на момент проверки не было.

Сначала обновлены API и общие workers, затем frontend. После health/API-проверки, подтвердившей 404 для обычного радара и прежние ответы ИИ-радара, применена миграция. После неё:

- все **356 заданий ИИ-радара** совпали по полным контрольным суммам строк;
- все **126 общих файлов** сохранились;
- все **22 остальные таблицы** совпали до и после установки, исключая две удалённые таблицы и ожидаемое обновление `alembic_version`;
- ответы списка всех **179 карточек** в области рабочего пользователя и полного первого задания ИИ-радара совпали;
- после браузерных проверок полная сверка БД повторилась без изменений.

Полный restore БД не выполнялся. Возврат прежних образов сам по себе не восстанавливает удалённые таблицы; восстанавливать старую полную БД поверх новых пользовательских/ИИ-записей нельзя. Эта оговорка не мешает текущему успешному выпуску.

- Сборка frontend прошла; предупреждение о больших прежних пакетах Mermaid/PDF осталось без изменения.

Материалы: `.dev/local/retire-legacy-radar-2026-11-05/deployment/`.

- `runtime.private.compose.json` и `rollback.private.compose.json` содержат секреты окружения, не публиковать и не включать в Git.

Для точного повторного запуска пяти обновлённых сервисов при уже работающих зависимостях используется сохранённый runtime:

```powershell
docker compose -p bervel -f .dev/local/retire-legacy-radar-2026-11-05/deployment/runtime.private.compose.json up -d --no-deps --no-build --wait api worker-chat worker-knowledge worker-inspection frontend
```

Контейнер ИИ-радара в эту конфигурацию не включён. После фактического изменения пользовательских данных не запускать повторно скрипты первоначальной установки, миграции или захвата исходной резервной копии; для обычного перезапуска достаточно команды выше.

VPN, адаптер VPN, Open Server Panel, конфигурация Codex/модели и внешние учётные записи не менялись. Git использовался только для чтения, коммитов/push нет. Оставшийся на Windows Python-кэш первого этапа не удалялся повторно после отказа автоматической проверки; он исключён `.dockerignore` и отсутствует в новом пакете обычного радара внутри API/общих workers. Исторические резервные образы не являются запущенным старым радаром.
