Дата: 22 октября 2026. Основание — явное решение владельца сохранить фоновый запуск на Python/PostgreSQL, удалить n8n и неиспользуемый Redis, сохранить данные и проверить CSV-интерфейс и защиту от дублей.

Рабочий корень: `C:/OSPanel/home/bervel.local`, существующая основная ветка `core`, исходный HEAD `f79bc76`. Прежние незакоммиченные изменения списка файлов и серверного веб-ключа сохранены. Git использовался только для чтения; staging, коммитов и push не было. VPN и Open Server Panel не менялись.

## Что работает теперь

API сохраняет фоновое задание в PostgreSQL. Отдельный контейнер `worker` запускает `python -m bervel worker`, берёт задание и вызывает прежний обработчик учебного CSV. PostgreSQL хранит очередь, точный источник, попытки и результат. При публикации проверяется активная попытка; строки и завершение сохраняются одной транзакцией.

Прямая загрузка и просмотр с сайта остались на прежнем API. Новых библиотек и движка сценариев не добавлено. После аварии работа восстанавливается явно; автоматические повторы внешних действий не заявляются.

Удалены адаптер и настройка n8n, поставляемая схема узлов, callback-маршруты и их секреты, Compose-профили, старые инструменты и проверки движка. Контейнеры n8n main/worker и Redis остановлены и удалены. Других потребителей Redis в приложении не обнаружено. В окружении текущих `api`, `worker`, `frontend`, `postgres` нет переменных прежних сервисов.

Миграция 0004 убирает ставший ненужным хеш callback-токена и добавляет индекс очереди. Оригиналы, данные, ID, версии, результаты, команды и история попыток сохранены.

## Ограничения

Историческая база и volumes прежнего движка сохранены для данных, но новым приложением не используются. Старые завершённые процессы доступны для чтения; старые схемы, включая учебное ожидание n8n, автоматически в Python не переносятся и не исполняются. Для повторной обработки прежнего оригинала нужна новая команда. Промышленная нагрузка, длинные ожидания сотрудника и развёртывание на отдельном сервере этой работой не подтверждаются.
