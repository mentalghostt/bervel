# Прямая оценка всех тендеров: этап1

26октября2026. Рабочий корень `C:/OSPanel/home/bervel.local`, боевая ветка `core`. Код изменён в существующей папке; Git HEAD/индекс/ветка не менялись. Этап1 реализован, проверен и применён к основной локальной установке. Семантическое качество настоящей LLM ещё не проверялось.

## Согласованное поведение

- Каждая импортированная запись передаётся LLM без лексического отсева, ранжирования и общего ограничения12кандидатов. Закрытые и просроченные тоже получают оценку товарного соответствия.
- Пользователь выбрал один длинный запуск без сохранения промежуточных порций. Общий worker не обслуживает чат до завершения радара. Ошибка любой порции прерывает запуск; частичный отчёт не публикуется, автоматических повторов модели нет.
- Текущий `bervel-product-profile.csv` согласован как профиль интересующих групп. `capability_confirmed=false` не превращается в подтверждение производства, склада, мощности или экономики.

## Устройство

`RadarService → полный DocumentMemory.context(complete=True) → analysis.batches → ModelClient.generate для каждой порции → parse_assessments → make_report → прежний RadarRepository.finish`.

Новых сервисов, зависимостей, PostgreSQL-таблиц или миграций нет. Используются прежние ModelClient, очередь PostgreSQL, worker, импорт оригиналов и декодеры. Эмбеддинги не добавлялись. У чата сохранён прежний поиск фрагментов по умолчанию.

В порции не более20тендеров и240КиБ UTF-8 текста запроса. Граница ниже существующих256КиБ runner; компактный JSON ограничен также прежними32000символами ответа. Идентификатор запроса — `run_id:номер_порции`. Разбиение сохраняет все поля импортированной записи и порядок, без дополнительного обрезания.

Выбранный профиль читается целиком, до96КиБ извлечённого UTF-8 текста суммарно. Нечитаемый/частично извлечённый/слишком большой профиль даёт ошибку доLLM. Все выбранные изображения должны быть фактически приложены: прежние ограничения2изображения/5МиБ не расширялись; при неполноте запуск отказывает до модели. Повторная проверка оригиналов учитывает точную пару artifact_id/revision, в том числе несколько кэшированных редакций одного файла.

Ожидаемый JSON каждой порции: один элемент на каждый ID, с fit/reason/evidence_indexes/product_group/tender_quote/profile_quote/risks/next_steps. Для relevant нужны непустые дословные цитаты из названия или описания именно этого тендера и из указанного читаемого фрагмента профиля; название группы входит в цитату профиля. Для irrelevant/uncertain три поля положительного доказательства равныnull. Пропуски, дубли, чужие ID, ошибочная структура или выдуманные цитаты отклоняются.

`fit` хранится независимо от проверки срока/стадии/свежести. `irrelevant` исключается даже при неизвестном сроке. Профильный просроченный тендер также исключён по сроку, но его товарное совпадение остаётся видимым. `uncertain` сохраняет недостаточность данных. Производственная/техническая готовность и экономика неизвестны, participation_ready=false.

Новый отчёт имеет версию1.1.0. API продолжает читать1.0.0, возвращая для новых полей старого отчётаnull. Данные старых запусков не переписываются. UI и PDF показывают fit, группу и обе цитаты, если они есть. Обновлена подсказка о полном проходе и длительном ожидании.

## Реальная выгрузка: проверена подготовка, не качество модели

Без БД и обращения кLLM обработаны исходные `2.xlsx` и согласованный профиль3379байт. Получено2290тендеров,115порций,1явно пропущенная итоговая строка,0дублей. Совпадение упорядоченного спискаID до/после разбиения проверено. Профиль полностью прочитан:1фрагмент,3900байт UTF-8 после представления CSV. Максимальный запрос32947байт,0модельных вызовов. Доказательство: `dry-run.py`, `dry-run.json`.

Следующий этап — отдельно разрешённый живой прогон этой выгрузки через настроенную модель и разбор результатов. Нужно проверять положительные решения, явно непрофильные контрольные закупки и часть отклонённых, чтобы искать как ложные совпадения, так и потерянный крепёж/смешанные лоты. В наличии цитат проверяется подлинность текста; соответствие их смысла оценивается отдельно. Нулевое число ошибок LLM этими тестами не доказано. В этом этапе настоящих запросов модели не выполнялось.
