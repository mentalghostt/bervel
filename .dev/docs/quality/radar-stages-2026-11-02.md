# Выбор стадий закупок — 2 ноября 2026

По согласованному запросу владельца список «Подача заявок / Все стадии» заменён шестью независимыми галочками: подача заявок, работа комиссии, завершены, планируются, отменены, несостоявшиеся. Есть «Выбрать все». По умолчанию выбрана подача заявок; пустой выбор блокирует отправку. Размеры и управление проверены на 1440 и 390 px.

Новые команды содержат `kontur_query.stages` со строковыми кодами `open`, `commission`, `finished`, `planned`, `cancelled`, `unsuccessful`. Сервер проверяет список, удаляет дубли и сохраняет порядок справочника. В Контур передаётся `PurchaseStatuses` с кодами 1–6 из сохранённой официальной схемы `.dev/local/kontur-api-2026-10-29/openapi.json`. Некорректный список не превращается в поиск всех стадий.

Выбранные неактивные стадии проходят анализ состава и экономики при истёкшем сроке подачи; фактическая неподходящая стадия исключается. Запас дней проверяется для подтверждённой подачи заявок. Фильтры цены и товарного соответствия продолжают действовать. Готовность означает покрытие потребности складом, включая для завершённых/отменённых закупок, и не подтверждает доступность подачи заявки.

В карточке и PDF показана стадия закупки, в сведениях о прогоне — выбранные стадии. При многозначном фильтре API не всегда раскрывает точную стадию отдельного результата; такое значение остаётся «Точная стадия не раскрыта API». Причина отмены, признаки планирования/несостоявшейся закупки и однозначный фильтр используются как подтверждённые данные; комиссия/завершение по одному сроку не выдумываются.

Старые команды `stage=open|all` сохраняют прежнюю канонизацию и правила повтора. Новые и старые команды повторяются с исходным телом после неопределённой отправки. Запрос, скопированный из ответа API с неиспользуемым `null`-полем, также совместим. Сохранённые отчёты не пересчитываются.

Проверки: 311 серверных тестов, затем 30 проверок HTTP/очереди/повтора после уточнения обработки `null`; 32 уникальных браузерных сценария, включая новые галочки, обе ширины, произвольную комбинацию, пустой выбор, старые команды, сбой/перезагрузку, карточку отменённой закупки с 100%/80% и PDF. TypeScript/Vite проходят; lint — 0 ошибок и 2 предупреждения в существующих участках радара. Живой UI также проверен на обеих ширинах; сохранённый run `7a5b2747-7867-45cc-a20a-d0dd3547be15` сохранил 100%/80%. Новых платных запросов к Контуру/модели не отправлялось; анализ неактивных стадий проверен на контролируемых данных, включая настоящую очередь БД и оба модельных прохода с тестовой моделью.

Установка ограничена 9 файлами серверного модуля радара и его frontend. Незавершённые правки загрузки файлов и визуализаций из других задач исключены из сборки: восстановленный исходный frontend даёт те же хеши сборки, что установленная до задачи версия. Общий `compose.yaml` содержит чужую настройку `TMPDIR`; локальное дополнение `runtime-preserve.compose.json` оставляет её неустановленной, как в исходном API. Окружение процесса проверено непосредственно; Docker-маркер отсутствующего значения без `=` не считается установленной переменной.

Резервная копия проверена восстановлением: 24 таблицы, 9229 строк, 47 файлов. Перед установкой проверены исходный серверный код и отсутствие смены контейнеров другой задачей; после — контрольные суммы кода и сохранность данных/окружения/томов/сетей/остальных контейнеров. Git, VPN и модули Open Server Panel не изменялись.
