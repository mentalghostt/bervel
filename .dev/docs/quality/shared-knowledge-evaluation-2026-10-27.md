# Проверка общей базы знаний — 27.10.2026

Реализация установлена и проверена. Активно **24 файла**: 23 полностью подготовлены для ИИ, один неизвестный `.custom` сохранён с явным `unsupported`. **3668 из 3668** подготовленных фрагментов имеют настоящие 1536-мерные векторы OpenAI `text-embedding-3-small`. PostgreSQL/pgvector хранит исходные выдержки, локаторы и пространство модели.

## Поиск: измеренный результат

До изменений зафиксированы 12 вопросов, ожидаемый исходный файл и обязательный текст ответа (`questions.json`). Проверяется наличие нужного текста именно в правильном источнике в контексте до 12 фрагментов/16000 символов. Это метрика извлечения контекста, **не процент правильных ответов LLM и не точность классификации тендеров**.

| Проверка | Контроль по словам | Векторный поиск | Рабочий гибридный поиск |
|---|---:|---:|---:|
| Предварительно, 22 готовых файла | 8/12 | 12/12 | 12/12 |
| Полный текущий корпус | 5/12 | 11/12 | 11/12 |

В полном сравнении все методы использовали одинаковые новые фрагменты и одинаковый бюджет контекста. Для семантического и гибридного поиска 12 векторов вопросов получены **одним настоящим API-запросом** и использованы повторно в памяти эксперимента. Модель и размерность проверены адаптером; искусственных векторов в оценке качества нет.

Лексический контроль ранжирует по пересечению слов, сохраняя прежний вес имени файла; выбирает 48 кандидатов до общего ограничения контекста. Он не воспроизводит прежнее распределение квоты между файлами. Семантический контроль использует только косинусную близость pgvector; рабочий вариант объединяет её с PostgreSQL FTS и приоритетом явно названного файла. Исходный показатель старой системы — 7/12 на прежних 25 файлах — сохранён как исторический ориентир. Для вклада эмбеддингов основной контроль — одинаковые новые данные из таблицы выше.

Вопросы и критерии после результатов не менялись. Это небольшая диагностическая выборка, а не доказательство универсальной точности.

## Известный пропуск

Вопрос о городе склада и резерве из загруженной заметки не нашёл ожидаемый фрагмент с KAZAN. Все 12 возвращённых фрагментов пришли из большой тендерной Excel-выгрузки. Добавление этой выгрузки снизило результат с предварительных 12/12 до 11/12. Полное покрытие индекса не гарантирует правильный выбор контекста. Для узких вопросов полезно явно называть файл; источник этого пропуска не скрывался и вопрос не переписывался ради оценки.

Это три конкретных успешных примера, а не общая статистика качества генерации.

## Реальная независимость workers

Установлены `worker-knowledge`, `worker-chat`, `worker-radar` из одного образа приложения. Старый комбинированный контейнер удалён. Проверены фактические команды ролей, образы и готовность API/Codex; установленный Python-код совпал с исходниками по SHA256 всех 67 файлов.

В живой проверке простаивающий worker радара был остановлен. Чат и API продолжили работу. Во время исполнения чата другой worker загрузил подготовку нового тестового TXT и завершил оба его фрагмента; пересечение состояний наблюдалось напрямую. Скачанные байты оригинала совпали с загруженными. Тестовый оригинал сохранён в `.dev`, его запись удалена из активного каталога, radar-worker снова запущен. Итоговый рабочий каталог снова содержит 24 файла.

Runner допускает два параллельных запроса. Отдельный тест запустил настоящие SDK/CLI-процессы с общим CODEX_HOME: локальный Responses-сервер дождался обоих запросов и вернул каждому только его ответ. Третий запрос ограничен, слот освобождается после ошибки. Это проверка протокола; тестовый сервер не выдавался за настоящую LLM.

## Сохранность и воспроизводимость

- Перед изменением сохранены полный custom-format pg_dump, все объектные данные и 29 прежних редакций оригиналов; SHA256 каждого проверен. Папка: `.dev/local/knowledge-2026-10-27/backup/`.
- Все 25 текущих оригиналов повторно загружены через штатный API с совпадением имени, размера и байтов. Затем по указанию пользователя удалён дубликат `2.xlsx`; оставлена выгрузка с полным названием. История и резервная копия дубликата сохраняются, в активную очередь он больше не попадает.
- Исходные оригиналы и бизнес-история в 19 прежних таблицах сохранились. Производные старые document_indexes обновлялись при снятии лексической базы; их изменения не выдаются за потерю оригиналов.
- Радар прочитал профиль целиком: все 11 строк P01–P11, 6019 байт контекста, без усечения и embedding-запроса. Правила отбора и дат не менялись; большой платный проход классификации в этой задаче не запускался.
- Полный backend: **244 теста прошли**. Node/SDK/runner: **12 прошли**. Браузерные проверки установленного интерфейса: **29 прошли**. Сборка и lint фронтенда прошли в Docker. Живой интерфейс проверен на 1440 px и 390 px, без ошибок JavaScript/переполнения страницы.
- Независимое ревью общей базы выявило четыре ошибки, исправленные через RED/GREEN: полный архивный источник, контекст длинной строки XLSX, покрытие явно названных файлов, длинный вопрос. Ревью разделения workers и последующей классификации регионального 403 не выявило значимых замечаний.
- Локальная npm-сборка Windows ранее упиралась в отсутствующий optional native binding; её успех не заявляется. Проверенная сборка приложения — Docker.

## Доступ OpenAI и нагрузка

Начальная ошибка `insufficient_quota`/`credit_balance_exhausted` исчезла: API вернул HTTP 200, затем реально обработал большой корпус. Во время работы возник отдельный HTTP 403 `unsupported_country_region_territory`, подтверждённый с хоста и контейнера. Пользователь восстановил доступ; проверка из worker снова дала HTTP 200. Позже произошёл транспортный сбой с неизвестным исходом; продолжение оставшихся 170 фрагментов выполнено только после явного решения пользователя. Готовые векторы не отправлялись повторно. После установки новых workers успешно прошли и embedding нового файла, и ответ чата.

Автоматических повторов нет. Текущие бюджеты — 24000 токенов/минуту для индексации и 8000 для чата при наблюдавшейся общей квоте 40000; порция до 8000 токенов/64 фрагментов, интервал не менее 5 секунд. Из request-limit=2000 не делается неподтверждённый вывод о минутном окне: [описание заголовков OpenAI](https://developers.openai.com/api/docs/guides/rate-limits).

Итог: 3668 активных векторов, 3649 уникальных embedding-входов, 1978528 уникальных входных токенов. Одинаковые входы в одной области данных/пространстве модели используют кэш; отдельные ссылки на источники сохраняются.

## Практические пределы

Формат `.custom` без декодера не получает выдуманный текст или эмбеддинг. Чат использует ограниченный контекст, а не всё содержимое БД. Производительность 100000 тендеров за два часа этим изменением не доказана. Не заявляется повышение точности текущей полной классификации радара: проверены общая подготовка, поиск и полное чтение профиля. Независимые workers сохраняют общими PostgreSQL, хранилище и квоты внешних поставщиков.
