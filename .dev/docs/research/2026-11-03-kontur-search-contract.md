# Поиск закупок по складу в API Контур.Закупок

Проверка от 3 ноября 2026 года для модуля «ИИ Радар тендеров». Использованы официальная схема, сохранённая 29 октября, действующий прайс-лист и ранее сохранённые ответы API. Портал разработчиков открывает страницу на JavaScript, а запрос документации без сеанса возвращает `401`. Новых авторизованных запросов в этой проверке не было. [Портал разработчиков](https://developer.kontur.ru/doc/zakupki.external_api?about=0), [сохранённая OpenAPI-схема](../../local/kontur-api-2026-10-29/openapi.json), [прайс-лист с 3 августа 2026 года](https://services.kontur.ru/Files/Modules/LandingPage/7824/price-skb-kontur.pdf).

## Что получает радар

- `POST /external/v1/search` принимает массивы `Text` и `Exclude`, признаки `StrictSearch` и `Attachments`, обязательный диапазон дат публикации, фильтры этапа, сроков подачи, отрасли, региона и другие параметры. В схеме `ExternalApiSearchArgs` отсутствуют отдельное поле для поиска только по заголовку, поле сортировки и отдельный фильтр ОКПД2. `CategoryIds` относится к отрасли. [OpenAPI-схема](../../local/kontur-api-2026-10-29/openapi.json).
- Результат поиска содержит `TotalCount`, `PageNumber`, `Items`. У элементов есть `Id`, `OrderName`, дата публикации, срок подачи и другие сведения карточки. `Snippets` может присутствовать как массив строк, подробных позиций в этой выдаче нет. Для них нужен `GET /external/v1/purchases/{id}`. В ответе полной карточки позиции, характеристики и ОКПД2 находятся внутри лотов, состав может быть неполным. [OpenAPI-схема](../../local/kontur-api-2026-10-29/openapi.json), [разбор объектов закупки](2026-11-02-kontur-procurement-objects.md).
- `Attachments=False` сохраняет поиск за пределами заголовка. В сохранённом запросе «болт» с отключённым поиском по приложениям у всех 50 элементов первой страницы есть `Snippets`. В закупке «Услуги комплексному обслуживанию административного здания» это упоминания осмотра и подтяжки болтов. Сниппет даёт основание поднять или опустить кандидата в очереди, а привязку к позиции нужно проверять в полной карточке. [Код исторического запроса](../../local/kontur-api-2026-10-29/compact_probe.py), [ответ](../../local/kontur-api-2026-10-29/compact-search.json).
- Одна поисковая страница содержит до 50 закупок и расходует один поисковый запрос. Для одних условий поиска через страницы доступно до 10 000 результатов. Одна подробная карточка расходует отдельный запрос. Прайс-лист указывает до пяти запросов в секунду суммарно по всем методам и суточные квоты по группам. `GET /external/v1/limitGroups` показывает доступные запросы и модификаторы текущего ключа. Снимок 29 октября показывал 200 запросов в сутки отдельно по поиску и карточкам, с модификатором `Snippets` у поиска. [Прайс-лист, пп. 3.3–3.5, 3.8.4](https://services.kontur.ru/Files/Modules/LandingPage/7824/price-skb-kontur.pdf), [снимок лимитов](../../local/kontur-api-2026-10-29/probe-summary.json).

## Поисковые выражения

Веб-справка Контура описывает пробел как «И», запятую как «ИЛИ», морфологию и точное соответствие для ГОСТов и аббревиатур. Поиск в документах веб-сервиса применим на этапе подачи заявок и к доступному индексируемому тексту. OpenAPI описывает `Text` только как массив ключевых слов. Для API отдельно проверяются объединение элементов массива, влияние `StrictSearch`, варианты дефиса, пробелов и года у стандартов, влияние `Attachments` и наличие `Snippets` на текущем тарифе. Для контрольного сравнения подходят запросы `Text: ["болт ГОСТ 7798"]`, `Text: ["болт", "ГОСТ 7798"]` и `Text: ["болт, ГОСТ 7798"]` с одинаковыми фильтрами. Сравниваются ID и `TotalCount`, а при усечении страниц состав фактически просмотренной части. [Поиск по ключевым словам](https://support.kontur.ru/zakupki/49207-zapros), [поиск по документации](https://support.kontur.ru/zakupki/49208-dokumentaciya), [OpenAPI-схема](../../local/kontur-api-2026-10-29/openapi.json).

В рассмотренном CSV БЕРВЕЛ 3 076 строк, пять групп, 28 уникальных пар группы и непустого значения `standard`, девять строк без стандарта. В двух значениях перечислены по два стандарта. После разбиения в отдельные поисковые ветки получается 30 пар. Например, `ГОСТ 7802-81` и `СТО 37841295-002-2016` дают две ветки в группе болтов. Сокращение записи стандарта полезно для поиска кандидатов после проверки токенизации, а совпадение стандарта подтверждается отдельно по полному идентификатору. Складской CSV из исследования03.11 (исторический вход; текущий склад хранится в снимке предприятия).

## Предварительный отбор

Текущий адаптер ищет по одной строке, с включёнными документами, за последние 365 дней и на этапе подачи заявок. Он просматривает до трёх страниц по 50 закупок, возвращает полную карточку первого необработанного ID в порядке Контура и не различает исчерпание выдачи и остановку на третьей странице. В прежнем радаре уже есть пример локальной оценки названия и сниппетов с понижением закупок работ и услуг и учётом признаков товара на складе. [Адаптер ИИ Радара](../../../src/bervel/modules/ai_tender_radar/infrastructure/kontur.py#L218), [адаптер действующего AIрадара](../../../src/bervel/modules/ai_tender_radar/infrastructure/kontur.py).

Рабочая гипотеза для сравнения состоит из двух источников кандидатов. Ветки «семейство + стандарт» помогают найти конкретные товары, а ветки по семейству и его подтверждённым синонимам сохраняют кандидатов, в которых ГОСТ отсутствует в индексируемом тексте. Для проката это могут быть отдельные выражения «калиброванный пруток», «круг калиброванный», «шестигранник калиброванный». Если запускать все 30 точных и пять широких веток отдельно, одна страница каждой расходует 35 запросов, три страницы каждой — 105. Поэтому для сравнения важен общий бюджет, с отдельным резервом на широкие ветки. После объединения по `Id` стоит сохранить сведения о ветках, оценить заголовок и доступные фрагменты, а затем запросить полные карточки первых кандидатов в пределах отдельной квоты. При равных признаках можно использовать ближайший подходящий срок подачи и `Id` для стабильного порядка.

Отдельный поиск по стандарту может вернуть закупки с нетипичным названием товара, а также работы, где стандарт упоминается мимоходом. Для него сравнивается прирост подтверждённых карточек на один вызов. Код ОКПД2 поддерживается в строке поиска веб-версии. Для внешнего API это отдельная гипотеза о поведении `Text`, которую можно проверить на известном коде и контрольной закупке. [Веб-справка по поиску](https://support.kontur.ru/zakupki/49207-zapros), [OpenAPI-схема](../../local/kontur-api-2026-10-29/openapi.json).

Для опыта фиксируются даты, стадия, доступный остаток и единый бюджет полных карточек. По каждой стратегии учитываются число поисковых запросов, число уникальных кандидатов, пересечения веток, доля целевых карточек в первых `K`, число дополнительных целевых карточек и причина остановки. Целевой статус для такой оценки определяется по составу полной карточки. Абсолютную полноту по всей базе этот ограниченный опыт не измеряет.
