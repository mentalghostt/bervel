## До purchase: только признаки, не полный состав

| Данные | Поля search |
|---|---|
| Текст | `OrderName`; дополнительный вариант `SearchResultItemWithSnippets` содержит nullable `Snippets: string[]` |
| Даты | `CreateDate`, `ApplicationDeadline`, `CommissionDeadline`: публикация, завершение подачи заявок, подведение итогов; не сроки поставки |
| Деньги и место | `MaxPrice`, `Currency`, `DeliveryPlaces` |
| Идентификация и стороны | `Id`, `NotificationNumber`, `NotificationTypeDesc`, `TypeOfTrading`, `EpUri`, `Link`, `Inns`, `Customers`, `Participants` (последнее описано для «Поиск 2.0») |
| Состояние | `IsCancelled`, `IsAbandoned`, `IsPlanning` |
| Состав и требования лотов | `Lots`, `Objects`, `Quantity`, `Characteristics`, структурированный ОКПД2 отсутствуют |

Источник таблицы: [SearchResultItem:2418](../../local/kontur-api-2026-10-29/openapi.json), [paging:2538](../../local/kontur-api-2026-10-29/openapi.json), [snippets:2569](../../local/kontur-api-2026-10-29/openapi.json). Краткие `Customers` — сведения об организациях, не позиции заказчиков.

Сниппеты не гарантированы: допустим обычный элемент без них и nullable массив; [LimitModifiers:2028](../../local/kontur-api-2026-10-29/openapi.json) содержит `Snippets`. Контракт не обещает количество/полноту фрагментов или привязку к конкретному лоту. Отсутствие фрагмента не доказывает отсутствие товара.

В [ExternalApiSearchArgs:1798](../../local/kontur-api-2026-10-29/openapi.json) есть ключевые слова, исключения, даты, этапы, регионы, отрасли и другие фильтры. `CategoryIds` — отрасли, не ОКПД2. Отдельных фильтра ОКПД2, сортировки, размера страницы, поиска исключительно по заголовку и переключателя сниппетов нет. `Attachments` описан как поиск по документам; `false` не доказывает поиск только по заголовку.

После `GET /external/v1/purchases/{id}` объекты доступны в `Lots[].JointObjects[]` и `Lots[].Customers[].Objects[]`: `Name`, `Okpd2s`, `Quantity`, `Okei`, цены, `Characteristics`. Поля допускают null; полная карточка не гарантирует полноту требований. Источники: [лот:1460](../../local/kontur-api-2026-10-29/openapi.json), [заказчик:1514](../../local/kontur-api-2026-10-29/openapi.json), [объект:1729](../../local/kontur-api-2026-10-29/openapi.json).

## Единицы квот и ограничения

- Одно search-обращение — одна страница до 50 процедур. Каждая следующая страница требует нового обращения.
- Одна детализация — одна закупочная процедура по ID со всеми её лотами; не отдельный запрос на каждый лот. Пакетного метода нескольких ID в рассмотренной OpenAPI нет.
- Прайс ограничивает один поиск 10 000 процедурами; схема формулирует предел как 10 000 на диапазон дат. Полный охват большей выдачи не обещан.
- Прайс: не более 5 запросов/сек суммарно по пользователям и методам. Схема дополнительно говорит о 5 одновременных обращениях; это разные ограничения.
- Суточные объёмы в прайсе 200/300/500/700/1000 — варианты лицензии, не остаток пользователя.

Источники: [API-прайс, пп. 2.1, 3.3–3.5, 3.8.4](https://services.kontur.ru/Files/Modules/LandingPage/7824/price-skb-kontur.pdf); OpenAPI, описание API:5, [search:314](../../local/kontur-api-2026-10-29/openapi.json), перечень `paths`.

[GET limitGroups:68](../../local/kontur-api-2026-10-29/openapi.json) возвращает группы `search`, `purchase` и другие, `AvailableRequests`, `TotalLimit`, `IsPeriodic`, `Modifiers`, даты подписки. При `IsPeriodic=true` лимит дневной, иначе — на срок поставки API. [Модель:1399](../../local/kontur-api-2026-10-29/openapi.json). Метод в этой работе не вызывался.

**Не установлено:** отдельные правила списания повторов ID/страницы, ошибок 4xx/5xx и таймаутов с неизвестным результатом; бесплатность `limitGroups`; часовой пояс обновления дневного счётчика. Общее описание схемы указывает 00:00 без часового пояса. Бесплатные повторы и скидку за пакет предполагать нельзя. Резервирование бюджета на каждую попытку — осторожная политика приложения, а не доказанный биллинг.

## Следствие для алгоритма

Цель пользователя — соответствие всех позиций **отдельного лота** ассортименту; достаточность количества проверяется отдельно. До детализации полный состав неизвестен, поэтому гарантированное соответствие лота по brief определить нельзя. Предварительный алгоритм оценивает шанс соответствия и выбирает карточки для раскрытия; окончательное решение требует объектов. Неполные требования означают «неизвестно». Это логический вывод из границы данных выше.

Локальный адаптер сохраняет границу: [search_page](../../../src/bervel/modules/ai_tender_radar/infrastructure/kontur.py) получает краткие данные; [fetch_tender](../../../src/bervel/modules/ai_tender_radar/infrastructure/kontur.py) отдельно вызывает purchase; [normalize_tender](../../../src/bervel/modules/ai_tender_radar/infrastructure/kontur.py) читает объекты лотов. `SEARCH_PAGES=3` — ограничение приложения, не квота Контура.
