# Инженерный атлас BERVEL

Результат: `.dev/visualizations/bervel-code-map.html`. Открывается напрямую через `file://`, работает без сервера и сети. Mermaid.js и исходники встроены в один HTML. Атлас содержит исходный код проекта: распространять его следует как исходники, а не как публичную презентацию.

## Источники

- `build-code-map.cjs` и `code-map-python.py` — статический разбор реальных исходников. Код приложения не исполняется.
- `code-map-shell.html` — оболочка, поиск, навигация и карточки исходников.
- `code-map-atlas.js` / `.css` — представления Mermaid, C4, ADD и оформление.
- `code-map-architecture.cjs` — вручную проверенные инженерные представления и учебные пояснения. Ссылки на файлы/строки проверяются при сборке; при изменении общего хеша исходников C4 показывает необходимость пересверки пояснений. Этот хеш нельзя обновлять без содержательной проверки.
- `vendor/mermaid-12.2.0.min.js` — официальный browser bundle из npm `mermaid@12.2.0`, MIT; лицензия рядом в `mermaid-LICENSE`. SHA-256: `a8a6a6f805b074a8261a2825c86f99c8054acb3b35f50bb7e24a4f9f2c3c3b9f`. Вендоринг обеспечивает автономный HTML, библиотека не добавлена в runtime приложения.

## Сборка и проверки

Из корня проекта:

```powershell
node .dev/scripts/build-code-map.cjs
node .dev/scripts/code-map-atlas-test.cjs
node .dev/scripts/code-map-edge-audit.cjs
node .dev/scripts/code-map-browser.cjs
```

Для генератора нужны TypeScript из `frontend/node_modules` и Python 3.9+. Python по умолчанию взят из установленного runtime Codex; другой путь задаётся `CODE_MAP_PYTHON`. Для браузерной проверки используются установленный Chromium/Chrome/Edge и Playwright из runtime Codex; путь браузера можно задать `CODE_MAP_BROWSER`. Проверка идёт с отключённой сетью и сохраняет результаты в `.dev/local/code-map-mermaid/checks`.

`code-map-test.cjs` дополнительно проверяет неизменность исходников/HEAD/индекса относительно выбранного baseline (`CODE_MAP_BASELINE`). Для этой доработки baseline — `.dev/local/code-map-mermaid/baseline.json`. Это проверка сохранности конкретной работы, её не следует выдавать за проверку новых изменений приложения.

## Чтение

- В карте кода выбрать тип отношений: состав, импорты, вызовы, ссылки на методы, HTTP или значения. Проекция не смешивает их в одну стрелку. Число относится только к выбранному типу. Пагинация ограничивает показ текущей страницей; полный список обращений выбранной сущности доступен в карточке.
- Узел открывает карточку; двойной щелчок или «Внутрь» — детализацию. `Запуск и сборка` → `Как запускается serve`.
- C4: L1, L2, компоненты L3, подробности платформы/радара, развёртывание, три сценария и зависимости исходного кода. Учебный CSV-процесс удалён. Это разные виды диаграмм, а не дополнительные уровни C4. Карточки по arc42 §5 описывают границы, контракты, данные, отказы и доказательства; общие сведения вынесены отдельно.
- `Вместить` показывает весь граф. `Читать 100%` возвращает натуральный размер подписей; фон перетаскивается мышью/пальцем, масштаб меняется кнопками и колесом. Клавиатура: стрелки на поле графа, +/−, 0; Enter/пробел на узле. Кнопки участников под C4 доступны и для sequence/state-диаграмм.
- ADD — адаптация Attribute-Driven Design, 9 шагов, словарь и конструктор промпта. Введённое сохраняется только до закрытия/перезагрузки страницы; незаполненные поля явно отмечаются как неизвестные.

## Ограничения

Карта — снимок исходников и конфигурации, не инвентаризация запущенных контейнеров и не подтверждение SLA/backup/доступности модели. Статические ссылки на методы не доказывают фактический runtime-объект. C4-карточки требуют содержательной пересверки после изменения архитектуры. Полная диаграмма может требовать увеличения и перемещения; пересечение линий само по себе не означает узел соединения.

Первоисточники: [C4](https://c4model.com/diagrams), [arc42 §5](https://docs.arc42.org/section-5/), [ADD / SEI](https://sei.cmu.edu/library/attribute-driven-design-method-collection/), [Mermaid](https://mermaid.js.org/).
