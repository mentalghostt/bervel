# Основа Python-модуля

Скопировать только `package/` в `src/bervel/modules/<name>/`. Руководство остаётся в `.dev`; заготовка ничего не регистрирует/исполняет.

- Публичные типизированные операции — `service.py`/`models.py` по необходимости, экспорт через `__init__.py`. Ожидаемая ошибка — `CoreError` с явным кодом, HTTP переводит её в ответ.
- Порты определяет потребитель; SQL/HTTP/SDK/файлы находятся в реальных `infrastructure`-адаптерах. Пустые слои не нужны.
- HTTP/таблицы добавлять при реальной необходимости. Данные принадлежат модулю, изменение — следующая миграция общей истории `core/migrations/versions`; старые миграции не переносить/удалять.
- Подключение — явные зависимости/роутеры в `app_setup.py` или setup-сценарии. Нет манифестов, `default_schemas`, `/modules` или универсального `execute(payload)`.
- Общие права/область, оригиналы, знания/документы, модель и соединения использовать из ядра. Файл имеет один ID, предметная редакция — другое понятие.
- Соседа вызывать через публичные операции с явной зависимостью; не читать чужие private-методы/таблицы. `core` не знает модули.

Добавлять только необходимое. Проверки/примеры/документы остаются в `.dev`; приложение её не читает. [Python](../../docs/architecture/19-python-layout.md).
