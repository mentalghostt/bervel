# Основа Python-модуля

Скопируйте только `package/` в `src/bervel/modules/<name>/`. Руководство остаётся в `.dev`. Заготовка ничего не регистрирует и не исполняет.

- Публичные операции и их входы/результаты объявляйте с типами в `service.py` (при необходимости отдельные `models.py`), экспортируйте операции через `__init__.py`. Ожидаемые ошибки — `CoreError` с явным кодом; HTTP переводит их в ответ.
- Сценарий соединяет правила и переданные ему зависимости. Порты (`Protocol`) определяет потребитель; SQL, HTTP-клиенты, SDK и чтение файлов находятся в `infrastructure/` только при реальной необходимости.
- `api.py` принимает HTTP, проверяет входы и вызывает операции. Его добавляют, только если модулю нужен HTTP. `infrastructure/tables.py` описывает собственные таблицы на общей metadata; не читает таблицы соседей. Изменение БД — следующая миграция в единой `core/migrations/versions`.
- Для подключения не нужны manifest, декларации пустых возможностей и проверка совместимости версий модулей. Реальные схемы данных регистрируются явно в `app_setup.default_schemas`, только если результат нуждается в таком хранении. Версии данных/повторяемого сценария сохраняются независимо от устройства Python-пакетов.
- Внешняя сборка `app_setup.py` явно создаёт зависимости и подключает роутеры; `worker.py` вызывает нужные фоновые обработчики. Права проверяет операция. Настройки установки — `core/config.py`/окружение, настройки сценария передаются явно; пустой класс не нужен. `/modules` сохраняет прежний статический HTTP-каталог для совместимости, а не управляет подключением. Не создавайте универсальный `execute(payload)`.
- Общие права/scope, оригиналы/редакции, документы/поиск, модель и соединения БД используйте из `core`. Между модулями вызывайте только публичные операции с явными зависимостями; не импортируйте чужие private-методы/таблицы. `core` не знает конкретные модули.

Добавляйте только нужные части: одинаковые роли не требуют одинакового числа файлов, пустых слоёв или одинаковой бизнес-операции. Проверки/примеры/документы располагаются в `.dev`; приложение её не читает.
