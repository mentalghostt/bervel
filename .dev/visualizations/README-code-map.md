# Карта исходников BERVEL

Откройте `C:/OSPanel/home/bervel.local/.dev/visualizations/bervel-code-map.html` обычным браузером. Файл автономный: данные, стили и скрипты внутри; сервер и сеть не нужны.

Нажатие на имя узла показывает пояснение справа. «Внутрь» раскрывает содержимое. Хлебные крошки и ↑ возвращают наверх. Поиск принимает имя и часть пути вместе: `__main__.py settings`. `/` переводит фокус в поиск. Фон перетаскивается, колесо и +/− меняют масштаб. Стрелки двигают карту при фокусе на поле. На телефоне описание находится ниже графа; «Вместить» показывает весь уровень.

Начальный маршрут — кнопка «Как запускается serve». Связь Settings → __post_init__ с подписью «пояснение: dataclass» объясняет автоматическое действие. Она не является прямым вызовом, написанным в main. Коричневый пунктир «пояснение: HTTP» обозначает ручные связи процессов. Синие линии — вызовы через связанные имена/импорты; фиолетовый пунктир — ссылки на методы через self/cls, TypeScript Symbol или тип, выведенный из единственного присваивания. Runtime-адресат таких методов не доказан. В карточке каждой разрешённой ссылки указано основание. Направления обзорных стрелок подписаны явно; линии не проходят за посторонними узлами.

Снимок после пяти исправлений 23 октября 2026: **112 файлов, 4657 сущностей, 579 определений функций/методов, 2861 параметр, переменная, константа и поле**. Поля включают ключи JSON. Разбор: 70 Python AST, 22 TypeScript/JavaScript AST, 5 JSON, 3 JSONC, 12 текстовых конфигураций/стилей. Ещё 6 ресурсов перечислены без содержимого. У функций и имён сохранены физический файл, строки и область видимости. SHA-256 снимка: `3cb41e4bc987f8a446c45c08758dda5ba12ba069be89f222df361a85727bdf83`.

Обновление отражает настоящий код: удалены активные узлы ModuleRegistry/default_registry, три манифеста и прежние CsvMemory/retrieve/ChunkRepository/legacy-методы. В маршруте запуска появился `default_schemas` с двумя реальными схемами. Статический `core/api/module_catalog.json` сохраняет старые поля HTTP-ответа, но не управляет сборкой. `chat.service.select_sources` отвечает за последний CSV; общая память работает с переданным снимком. Preview и поисковые фрагменты связаны с общим `csv_memory.read_csv/decode_text`; `INDEX_VERSION = 4` и ленивое обновление индекса пояснены отдельно. Публичные вызовы между модулями разрешены; искусственных связей для иллюстрации не добавлено. Исторические таблицы/миграции и реальные поля каталога не скрыты.

Это статическая карта. Внешние и динамические вызовы перечисляются честно без выдуманного адресата. Ручные русские пояснения есть у частей приложения, основных файлов и маршрута запуска; остальные карточки сообщают наблюдения по коду. CSS и конфигурации показаны файлами, без полного синтаксического разбора. Подробности — «Охват и ограничения».

Пересоздание из актуальных исходников, из корня проекта:

```powershell
node .dev/scripts/build-code-map.cjs
node .dev/scripts/code-map-test.cjs
node .dev/scripts/code-map-edge-audit.cjs
node .dev/scripts/code-map-browser.cjs
```

Генератор использует существующий `frontend/node_modules/typescript` и Python из встроенного runtime Codex. Для другого Python задайте `CODE_MAP_PYTHON` (3.9+). Браузерная проверка использует встроенный Playwright и уже установленный Chrome/Edge; путь можно задать через `CODE_MAP_BROWSER`. Приложение не зависит от этих инструментов или `.dev`.

Проверка: целостность IDs, целей связей, строк и областей; покрытие исходников; точное совпадение встроенного текста с файлами; сохранность исходников, HEAD, ветки и индекса. **19 сценариев в настоящем Chrome через file://**: раскрытие до параметра/переменной, исходник и использования, вызовы, поиск, импорты, страницы большого уровня, клавиатура, масштаб/перемещение, возврат, повторное открытие, ширина 390 px, отсутствие линий за посторонними карточками. Ошибок JavaScript и сетевых запросов нет. Ещё **9 контрольных случаев** резолвера проверяют одинаковые имена методов в разных классах, неизвестного/переприсвоенного получателя, затенение параметром, self вложенной функции/staticmethod и импорт через псевдоним.

Доказательства и скриншоты — `code-map-checks/`: `coverage.json`, `integrity-report.json`, `edge-audit.json` (направления, примеры рёбер с доказательствами, неразрешённые вызовы), `browser-report.json`, PNG. У core нет импортов/вызовов бизнес-модулей; их операции обращаются к core. Линии сборки обходят карточку core. Чат → core: 12 связей по имени и 4 ссылки на методы; радар → core: 22 + 4; CSV → core: 27 + 0. Проверки обновлённых карточек и отсутствия старых имён включены в прежние 19 браузерных сценариев; целостность дополнительно проверяет реальные цепочки preview/индексатор → общий CSV-декодер, версию индекса и новый каталог.

`refresh-before.json` — точный снимок 112 исходных файлов перед этим обновлением атласа; он выбран для проверки сохранности. Исходный `source-before.json` оставлен как историческое доказательство первой сборки (с нормализацией переводов строк Python). Другую контрольную точку можно явно передать через `CODE_MAP_BASELINE`; проверка сохранности относится к конкретной задаче и не должна принимать намеренные будущие правки за свои. HTML содержит точный текст UTF-8 с исходными переводами строк. В этом обновлении изменены только материалы атласа в `.dev/scripts` и `.dev/visualizations`; исходники приложения, Git, сервисы и данные не изменялись. Проверки продуктовых исправлений и очистку данных этот отчёт не подтверждает.

Методы разбора сверены с официальным [TypeScript Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API), браузерная проверка — с [Playwright Page API](https://playwright.dev/docs/api/class-page). Новые зависимости не установлены.
