### Радар ИИ — отбор, симулятор без квот и аудит теста 100

### Радар: соответствие, сравнительная оценка, независимые вопросы и снятие model cap — установлено

Сессия: `01a1bbee-3e43-76b0-afb1-cc6c7ad04bea` · Ваня · Codex Desktop

Техническое соответствие строк, покрытие штуками, исполнимость целого заказа и сравнительная привлекательность имеют разные знаменатели и должны храниться раздельно. Для рейтинга достаточно четырёх агрегатов; отсутствие данных не равно нулю. Независимый вопрос требует согласованного разделения UI, уникального индекса БД, worker и модельного вызова; общий интервал источника должен разделяться всеми клиентами одного origin без удержания блокировки на HTTP. Durable complete деталей не завершает job во время последующей автооценки: история и Stop должны опираться на фактическую job. Каждый command_key требует durable receipt даже при reuse fingerprint, неизвестные исходы нельзя повторять автоматически. В общем dirty tree выпускать только проверенный allowlist от установленного baseline, сверять полную runtime Shape и закреплять rollback image IDs; после новых типов сохранённых отчётов простой откат несовместим. Живой parallel-proof фиксировать одним атомарным снимком; UI сверять с фактической сортировкой, не ожидать max рейтинга первым при сортировке по складу.

## 10 ноября 2026 — загрузка больших JSON через туннель

HTTP200 ещё не доказывает завершение загрузки: AbortSignal.timeout действует и во время response.json(). Сначала измерять размер и полное время тела. Для существующего контракта gzip сократил 75,4 МБ до 7,9 МБ без удаления полей; GET-only timeout отделён от команд. Проверять распакованный JSON по SHA и реальный публичный браузер. Переменные окружения сравнивать через хеш отсортированных значений: порядок Docker не является изменением; сырые значения никогда не включать в assertion diff.

### Пресейл установлен; попап настроек проверен, доставка поверх нового ngrok frontend ожидает

Сессия: `01a1c53f-484c-7ae0-a9a3-e13d52758b3b` · Ваня · Codex Desktop

- Не считать неполный знаменатель подтверждённым 100% покрытия; аналог экспортирует фактические характеристики SKU, а неизвестные факты остаются неизвестными.
- Канонический JSON обязателен для стабильных модельных ключей после JSONB; сырой ответ и прошедший валидацию ответ — разные состояния. При восстановлении экспорта сначала искать durable receipt. Job/request блокируются в одном порядке.
- Попап сохраняет родительский экран смонтированным: синхронизировать ожидающую команду после закрытия, проверить сохранение выбранной редакции, клавиатуру и точный retry. Использовать существующий WorkspaceDialog, а не второй механизм модальных окон.
- Перед установкой frontend повторно сверять фактический image и effective inputs: чужой поздний выпуск делает старый подготовленный image непригодным без обновления baseline. Автоматический CSS scan и deferred sources входят в доказательство точной сборки.
- Сравнивать конфигурацию по именам полей и хешам отсортированных значений; не печатать Env/секреты при assert diff. Успешный публичный скан пакета не отменяет фактическую ошибку tool stdout.
- Различать код, проверенный preview, собственную установку и последующую версию другого чата. /end сохраняет точку продолжения и не возобновляет продуктовые операции.

### Тендерный радар: профили, устойчивое обновление, индивидуальные оценки; ремонт23 документальных карточек не завершён

Сессия: `01a1bfa6-337d-7180-a073-439ef1e0dab4` · Ваня · Codex Desktop

MODEL_INVALID_OUTPUT может быть ошибкой postvalidator, поэтому виновность ИИ подтверждается входами/ответом и replay. Локальные ошибки после MAX3 не должны обрывать соседние lifecycle/rating retries; global DB/auth сохраняют отдельную семантику. Shared checkpoint maps защищаются общим RLock без ожидания future внутри. Генератор документов обязан строить сводку после окончательного выбора SKU; нельзя удалять неполные edgecase fixtures ради зелёного теста.

### Docker: остановленный контейнер не равен мусору — 11 ноября 2026

При очистке сопоставлять service/project/config_files, mounts, фактические
URL зависимостей и writable layers; удалять подтверждённые одноразовые цели
по ID без volumes/force. docker compose run --rm убирает только командный
контейнер: E2E-зависимости требуют отдельного адресного finally cleanup,
который не должен скрывать исходную ошибку теста. Не использовать глобальный
prune/--remove-orphans при рабочих overlay. См. отчёт
.dev/docs/quality/docker-cleanup-2026-11-11.md.

## 11 ноября 2026 — пресейл, размер durable cache и валидация ответов

Проверять масштаб не только модельного prompt, но и суммарного JSONB: fields в каждом difference и несколько полных диагностических копий способны превысить256МБ уже на9строках. Хранить канонический результат один раз, diagnostics как сводки; дедупликация после модельных проверок сохраняет оплаченные fingerprints. Отсутствие validated не доказывает ошибку: это может быть готовый корректный ответ перед сбоем сохранения. Индивидуальный validator отмечает только свой ответ; explicit validation_error позволяет адресный Resume. Семантические проверки должны соответствовать wire-контракту: отрицательные поясняющие facts не являются положительным предложением. Покрывать полный размер каталога и настоящую заявку до заявления готовности.
