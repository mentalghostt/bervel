# Модульный монолит и отдельно исполняемые тяжёлые задачи

Владелец разработки 14 октября 2026 согласовал одно ядро прикладных контрактов и модульную бизнес-логику, с отдельными процессами OCR/моделей/интеграций. Альтернатива - множество микросервисов с отдельным сервисом на каждый небольшой шаг. Для текущего объёма это добавляет распределённые отказы и сопровождение без доказанной пользы.

Границы модулей и владение данными сохраняются даже в одном процессе. Выделение сервиса возможно при подтверждённой нагрузке, изоляции или независимом цикле выпуска. Компромисс: общий backend остаётся совместно выпускаемым, а общая БД требует дисциплины доступа и резервирования.

Принята форма реализации для разработки. Конкретные контракты [спецификации v0.1](../architecture/12-core-v0.1-spec.md) требуют приёмки этапа 1. Это не подтверждение состава поставки и эксплуатационных требований заказчиком. См. [общую архитектуру](../architecture/00-overview.md).
