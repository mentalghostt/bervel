# План подготовки эксплуатации

Это перечень будущих процедур, не действующий runbook и не инструкция запускать несуществующую инфраструктуру.

| Ситуация | Что должно быть подготовлено | Владелец |
|---|---|---|
| Сбор перестал запускаться | Внешний контроль свежести, последняя успешная выборка, восстановление окна | Эксплуатация + владелец источника |
| Зависла задача | Поиск по correlation_id, причина ожидания, безопасный повтор/отмена | Эксплуатация |
| Недоступна модель | Квоты, разрешённый резерв или ручной путь, предел повторов | Эксплуатация + ответственный за модель |
| Недоступна 1С | Возраст данных, запреты, восстановление синхронизации | Сопровождающий 1С |
| Неизвестная отправка | Запись intent_id, проверка получателя, ручная сверка | Владелец процесса |
| Обновление правил | Утверждение, результаты проверки, версия и возврат | Технолог/экономист + команда |
| Обновление процесса | Совместимость незавершённых заданий и БД | Команда разработки |
| Восстановление площадки | Инвентаризация копий, зависимости, секреты вне git, сценарий проверки | ИТ/эксплуатация |
| Утечка/неправильный доступ | Контакт ответственного, ограничение доступа, сохранение необходимого аудита | Безопасность |
| Достигнут бюджет | Согласованная политика очереди и эскалации | Руководитель проекта |

## Наблюдаемость

Возраст последнего успешного сбора; число неполных документов; длина/возраст очередей; ошибки по типам; доля NEEDS_REVIEW; возраст справочников; квоты и стоимость; отставание копий; неизвестные внешние операции.

Health-check процесса не доказывает, что закупки продолжают поступать. Нужны отдельные проверки полезного результата и актуальности.

## Передача

Утвердить доступы, ответственных, часы реакции, документацию, контрольное восстановление и процедуру изменения. Заказчик подтверждает ограничения; конкретные команды появляются после выбора инфраструктуры и должны быть проверены на стенде.
