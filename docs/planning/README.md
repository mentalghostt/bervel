# Как читать декомпозицию

Это предварительное разбиение на ответственность и функции, а не окончательный перечень всех строк кода. Внутренние методы, экраны и поля уточняются по образцам заказчика. Один пункт каталога не означает отдельный микросервис, контейнер или задачу оркестратора.

[Каталог функций](function-catalog.csv) связывает вход, выход, обязательное ограничение и наблюдаемый критерий проверки. Идентификаторы C относятся к ядру, S — общим прикладным функциям, R…F — радару, P — пресейлу, U — интерфейсу, O — эксплуатации. R01–R22 без суффикса F — запросы заказчику.

Поле depends_on описывает необходимые контракты и функции. Это не последовательность сетевых вызовов и не обязательно самостоятельные workflow-шаги. Поле optional_depends_on используется только при включении соответствующей возможности: например, OCR для сканов или семантический поиск для расширенного подбора. Наличие зависимости на механизм одобрения не означает ручного одобрения каждого уведомления: точный состав действий задаёт политика R10.

[Backlog](backlog.csv) объединяет функции в проверяемые результаты и задаёт зависимости задач. Статус conditional означает отдельное подтверждение включения функции, а не низкую важность. Статус open означает работу, которая ещё не выполнена. Этапы определены в [дорожной карте](roadmap.md).

Для каждой выбранной задачи до реализации уточнить:

1. Схемы входа и выхода на реальном примере.
2. Владельца данных, права и ограничения доступа.
3. Поведение при неизвестных, устаревших и конфликтующих данных.
4. Транзакционные границы, ключ повтора и способ сверки внешнего результата.
5. Критерий приёмки и связанные [сценарии](../quality/test-scenarios.csv).

Все сценарии пока имеют статус not_run: работающего приложения нет. Каталог не обещает абсолютную отказоустойчивость. Требуемую доступность, допустимую потерю данных и стоимость эксплуатации необходимо согласовать.
